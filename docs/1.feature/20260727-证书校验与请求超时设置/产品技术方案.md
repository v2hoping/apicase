# 证书校验与请求超时设置

> 在「配置 → 通用」页增加三项工作空间级请求设置：SSL/TLS 证书验证开关、自定义 CA 证书、请求超时时间。

## 一、需求内容

当前 apicase 后端用 `reqwest` + `rustls-tls` 发请求，**始终严格校验证书**，且**没有超时上限**。两个现实问题：

1. **自签证书连不上**——内网 / 开发环境用自签证书或自建 CA 签发的证书，rustls 追溯不到受信任根，直接 `UnknownIssuer` 失败。企业 TLS 拦截代理（Zscaler / Charles）同理。
2. **慢接口卡死**——服务端不响应时请求会一直挂着，没有兜底超时。

据此增加三项设置：

| 设置项 | 类型 | 默认 | 说明 |
|---|---|---|---|
| SSL/TLS 证书验证 | 开关 | 开启 | 关闭后接受任何服务端证书（自签、过期、域名不符）。**降低安全性**，UI 需明确警示 |
| 使用自定义 CA 证书 | 开关 + 文件选择 | 关闭 | 从**当前工作空间目录下**选一个证书文件作为额外受信任根；追加到默认信任库而非替换 |
| 请求超时时间 | 数字（毫秒） | `0` | 整个请求的超时上限（含连接与传输）。`0` = 不限制 |

三项对**单请求执行与 flow 执行同时生效**——两者共用 `send_request` 后端通道。

### 两个开关的关系

彼此独立，可组合：

- **仅开自定义 CA**（推荐）：只信任你指定的那一个签发者，其余请求仍完整校验 → 内网能通，公网不失守。
- **仅关证书验证**：应急手段，全部请求都不再校验身份，存在中间人风险。
- **两个都开**：校验已关闭，CA 实际不再起作用（校验都跳过了，谈不上信任链）。UI 上在此组合下把 CA 项灰显并说明。

## 二、数据模型

用户选择**项目级**存储：写入工作空间根的 `application.yml`，随 git 分享给团队，与「环境」同一套机制。

```yaml
settings:                 # 新增顶层键
  verifySsl: false        # 默认 true，仅 false 落盘
  useCustomCa: true       # 默认 false，仅 true 落盘
  caCert: certs/ca.crt    # 相对工作空间根的路径，空则不落盘
  timeoutMs: 30000        # 默认 0（不限制），仅非 0 落盘
environment:              # 既有
  dev: { baseUrl: "..." }
```

设计取舍：

- **裁剪默认值**——与 case 序列化同风格（`serializeKV` 等），全为默认时整个 `settings` 键不落盘，不给既有 `application.yml` 添噪。
- **CA 存相对路径**——绝对路径换台机器 / 换 clone 目录就失效；相对路径随仓库走，团队成员 clone 下来即可用。运行时再 `joinPath(workspace, caCert)` 还原。
- **`useCustomCa` 与 `caCert` 分两个字段**——关掉开关时保留已选路径，重新打开不必再选一次。

## 三、技术方案

### 3.1 前端 `case.ts`

```ts
export interface WorkspaceSettings {
  verifySsl: boolean;    // 默认 true
  useCustomCa: boolean;  // 默认 false
  caCert: string;        // 相对工作空间根
  timeoutMs: number;     // 默认 0
}
export const DEFAULT_WS_SETTINGS: WorkspaceSettings;
export function parseSettings(text: string): WorkspaceSettings;      // 容错：缺键/类型不符一律回默认
export function dumpApplicationConfig(baseText, environment, settings?): string;  // 第三参可选，保持既有调用兼容
```

`parseSettings` 的健壮性要求与 `parseEnvironments` 一致：解析失败、键缺失、类型不符都回落默认值，不抛错。`timeoutMs` 需处理负数与非整数（钳到 `>= 0` 整数）。

### 3.2 后端 `lib.rs`

新增载荷结构与命令：

```rust
pub struct RequestOptions {
    pub verify_ssl: Option<bool>,     // None / true = 校验；false = 关闭
    pub ca_cert_path: Option<String>, // 绝对路径，前端已 join 工作空间
    pub timeout_ms: Option<u64>,      // None / 0 = 不限制
}

async fn perform_request(req, proxy, options: Option<RequestOptions>) -> ...
```

`ClientBuilder` 装配：

- `verify_ssl == Some(false)` → `.danger_accept_invalid_certs(true)`
- `ca_cert_path` 有值 → 读文件，先按 PEM bundle 解析（支持多证书的 CA 链文件），失败再试 DER，仍失败则**明确报错**（而非静默忽略——静默会让用户以为配了却仍失败，难排查）；成功则 `.add_root_certificate(cert)`（追加，不替换默认信任库）
- `timeout_ms > 0` → `.timeout(Duration::from_millis(ms))`

新增命令 `list_cert_files(root) -> Vec<String>`：递归扫描工作空间，返回**相对路径**列表，供前端下拉选择。复用 `search_workspace` 的遍历骨架（跳过隐藏项与 `node_modules`/`target`/`dist`，结果上限）；扩展名匹配 `.pem` `.crt` `.cer` `.der` `.ca-bundle`。

### 3.3 前端 `App.tsx`

与 `environments` 完全对称地接入：

| 环节 | environments 现状 | settings 照做 |
|---|---|---|
| 读取 | `loadEnvironments()` 里 `parseEnvironments` | 同处 `parseSettings` |
| 打开配置文件 | `setEnvironments(parseEnvironments(text))` | 同处 `setWsSettings(...)` |
| 文本 ↔ 可视切换 | `enterConfigVisual` / `exitConfigVisual` | 同处同步 |
| 保存 | `dumpApplicationConfig(rawText, environments)` | 传入第三参 settings |
| 编辑标脏 | `onEnvChange` → `mark()` | `onSettingsChange` → `mark()` |
| 发请求 | `proxyPayload(proxyConfig)` | 新增 `options` 参数 |

发请求处（`runRequestWithCtx`）把相对路径还原为绝对路径后传后端。

### 3.4 UI（设置页「通用」分区）

在既有两行只读信息（工作空间 / 配置文件）下增加一个「请求」分组：

- **SSL/TLS 证书验证**——复用快捷键页的 `.sc-switch` 开关。关闭时下方出现警示条（`.text-warn` 既有样式），说明"流量仍加密，但无法确认对端身份"。
- **使用自定义 CA 证书**——开关 + `<select>` 下拉（选项来自 `list_cert_files`，附"未选择"空项）。工作空间内没有证书文件时下拉禁用并提示。证书验证关闭时整项灰显。
- **请求超时时间**——数字输入 + 后缀「毫秒」，`0` 时旁注"不限制"。

## 四、执行计划

1. `case.ts`：`WorkspaceSettings` 类型 + `parseSettings` + `dumpApplicationConfig` 扩展第三参
2. `lib.rs`：`RequestOptions` 结构、`perform_request` 装配三项、`list_cert_files` 命令 + 注册
3. `App.tsx`：state 接入（读取 / 切换 / 保存 / 标脏）+ 发请求传参 + 「通用」页 UI
4. `App.css`：开关行、下拉、警示条样式
5. 测试：`test/settings.test.mjs`（解析容错 + 序列化裁剪 + 往返）接入 `npm test`；Rust 侧补 `list_cert_files` 与证书加载的离线用例
6. 构建验证（`tsc` + `vite build` + `cargo test`）
7. 变更要点同步进 `docs/0.latest/`（`0.概览.md`、`2.技术架构.md`、`3.YAML格式规范.md`）

## 五、风险与边界

- **安全**：关闭校验是降安全操作且**无可观察症状**（攻击者转发真实响应，请求照常 200）。故 UI 必须显眼警示；且因存于 `application.yml`，关闭状态会随 git 传播给团队——文档中需写明这一点。
- **rustls 严格性**：即便导入了正确的 CA，证书仍需满足 SAN 匹配（无 SAN 只有 CN 会被拒）、未过期、CA 证书带 `basicConstraints=CA:TRUE`。这些不是本功能能绕过的，需在文档中提示。
- **超时语义**：`reqwest` 的 `.timeout()` 覆盖从连接到读完响应体的全过程，不是单纯的连接超时。
- **兼容**：`settings` 键缺失的旧 `application.yml` 一律按默认值处理，不需要迁移。

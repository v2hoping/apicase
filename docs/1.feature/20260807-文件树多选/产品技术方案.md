# 文件树多选

## 一、需求

文件树当前只能选中一项。本需求引入 **Shift 连选 + Cmd/Ctrl 点选**，并让下列操作接受多个选中项：

| # | 功能 | 说明 |
|---|---|---|
| 1 | 生成测试报告（选中项） | 选中的用例 / 目录合成**一次**运行、**一份**报告 |
| 2 | 删除 | 一次确认，说清「几项、含几个文件夹」 |
| 3 | 拖拽移动 | 同名（批次内互撞或目标目录已有）**报错且整批不动**，文案与现有一致 |
| 4 | 选中态与取消选择 | 选了什么要看得见（行高亮），能选就得能退出（`Esc` / 点侧栏空白） |
| 5 | 复制 / 粘贴 | 剪贴板存多项，粘贴逐个排号 |
| 6 | 克隆 | 逐个在各自目录内排号 |

不在本次范围：批量重命名、多选下的「显示文件所在位置」「新建」（语义不成立，多选时隐藏）。
搜索结果列表保持单选——它是另一套平铺视图，Shift 区间要按它自己的顺序算，等有需要再说。

## 二、为什么值得做

**后端不用改。** `run_batch` 的入参本就是 `targets: Vec<BatchTarget>`
（`src-tauri/src/commands/exec.rs:167`），报告头的 `options.targets` 也已是数组；
`pathutil.ts` 里 `reportFileNameMulti` 与 core 的 `report_file_name_multi` 是为多目标写的一对函数，
CLI（`apicase run a.yml b.yml`）早就在用，只有桌面端把它收窄成了单个 `target`。
也就是说「选中散落各处的 5 个用例跑一次冒烟」这件事，缺的只是前端的选择模型。

## 三、选择模型（最容易做砸的部分）

### 状态

```ts
const [sel, setSel] = useState<Sel[]>([]);   // 选区，按「可见顺序」排；末项之外无特殊含义
const [treeSel, ...]                         // 保留：最近点击的那一行（lead）
const anchorRef = useRef<string>("");        // Shift 的锚点 = 最后一次「非 Shift 点击」的行
```

**不变式**：`sel` 恒包含 `treeSel`；`sel` 为空 ⟺ `treeSel` 为 `null`。
为此把所有 `setTreeSel(x)` 收敛成 `selectOne(x)` / `clearSel()` 两个函数——
散落在七八处的 `setTreeSel` 各自再补一句 `setSel`，漏一处就是「选区与高亮对不上」。

### 交互

| 操作 | 行为 |
|---|---|
| 普通点击 | 选区重置为该行；锚点 = 该行；**照旧**打开文件 / 展开目录 |
| Cmd/Ctrl + 点击 | 切换该行的选中态；锚点 = 该行；**不打开、不展开** |
| Shift + 点击 | 以锚点到该行的**可见区间**覆盖选区；锚点不变；**不打开、不展开** |

三条要点：

- **Shift 是覆盖不是累加**。连点两次 Shift 要基于同一锚点重算，否则「Shift 点回去反而选得更多」。
- **区间按可见顺序算**，不是按目录结构：展开的子项算在内、折叠的不算。故需要一份
  `flattenVisible(root, childrenMap, expanded)` 的扁平数组——树是递归渲染的，没有它就无从取区间。
- 锚点若已不可见（父目录被折叠、文件被删），回退成「点击行自身」，不报错也不留空选。

### 右键落点（同 Finder / VSCode）

- 右键点在**已选中**的行上 → 菜单作用于整个选区；
- 右键点在**未选中**的行上 → 先把选区重置成这一行，再弹菜单。

少了后半条，用户会在毫无察觉的情况下批量删掉一批东西。

### 工作空间根不参与多选

根行只能单选（它不能被删 / 移 / 复制）。Shift / Cmd 不作用于根行，因此选区里永远不会混进它。

## 四、各功能的实现要点

### 通用：祖先吸收

选区里同时有 `订单/` 和 `订单/下单.yml` 时，删除 / 移动 / 复制 / 克隆一律**只处理最上层**的那些
（`pruneDescendants`）。不做的话：删除会「删完父再删子」报错，移动会在移完父之后找不到子的源路径。

### 1. 生成测试报告

- `RunDialogState.target: string` → `targets: Sel[]`，`isDir` 由「选区里是否含目录」派生（`hasDir`）。
- `discoverCases` 对每个目标展开后**合并、去重、排序**——两个选中目录互为父子时会扫出重复用例，
  重复跑一遍既费时又让报告里出现两条同名结果。
- 报告文件名走已有的 `reportFileNameMulti`（`<时间戳>-<首个目标>等N项.html`），
  与 CLI 生成的名字逐字一致。
- `options.targets` 填全部目标的相对路径——报告头是半年后回看时唯一的「当时跑了什么」。

### 2. 删除

确认框说清规模：`删除选中的 5 项？` + `其中 2 个文件夹将连同内容一并删除 · 不可撤销`。
逐个删，删完统一做一次标签 / 选区 / 剪贴板的级联清理。

### 3. 拖拽移动

拖起来的是**整个选区**（拖的那一行在选区内时），否则按单行处理并重置选区。

**全或无**：先把整批检查完，任一冲突就整批不动。移了一半再报错，用户得自己逐个核对哪些已经过去了。

| 情形 | 文案 |
|---|---|
| 目标目录已有同名（1 个） | `<目标目录名> 下已有 <名字>`（**与现有单选完全一致**） |
| 目标目录已有同名（多个） | `<目标目录名> 下已有 <名字> 等 N 项` |
| 批次内两项同名 | `选中项里有两个 <名字>，不能一起移动到 <目标目录名>` |
| 文件夹拖进自己的子目录 | `不能把文件夹移动到它自己或它的子目录中`（现有文案） |
| 拖回原处 / 拖到自己身上 | 静默无操作（现有行为） |

### 4. 选中态与取消选择

**不加提示条**。最初做过一条「已选 N 项 + 取消选择」的细栏，实测后拿掉了：
它常驻占一行、把整棵树往下推，而「选了哪些」行高亮本来就看得见——
为一个次要信息牺牲侧栏的简洁不划算。

取消选择给两条路：

| 方式 | 说明 |
|---|---|
| `Esc` | 最顺手，手不用离开键盘。侧栏有焦点时生效（点过树就有）；焦点在搜索框里则放行给输入框，不抢它的 Esc |
| 点侧栏空白处 | 同 Finder。判「点到的不是任何可交互元素」，而不是给 `.tree` 撑满高度——后者要改侧栏布局与滚动，代价大得多 |

「随便点一行」不算取消：那会打开文件 / 展开目录，而且仍剩一项选中。

### 5. 复制 / 粘贴

`clip` 从 `Sel` 变 `Sel[]`。粘贴时逐个排号，且**同批次内累积 taken**：
一次粘两个同名文件，第二个要看到第一个刚落地的名字，否则两个都算出同一个「副本」名。
菜单文案：单个沿用 `粘贴「x」`，多个为 `粘贴 5 项`。

### 6. 克隆

按源目录分组，组内累积 taken（同上）。

## 五、执行计划

1. **新增 `src/treesel.ts`**：`flattenVisible` / `rangeBetween` / `toggleSel` / `pruneDescendants` /
   `dupName` / `countKinds`。纯函数、无 React——多选的坑全在这几个算法里，必须能单测。
2. **`App.tsx`**：选择模型（`sel` / `anchorRef` / `selectOne` / `clearSel` / `onRowClick`）、
   `TreeNode` 改收 `selectedPaths: Set<string>` + `leadPath`（滚动只跟 lead，否则多选时抖）、
   右键落点规则、六个功能的批量化、取消选择（`Esc` / 点侧栏空白）。
3. **`App.css`**：无新增常驻元素（选中态复用既有的 `.tree-row.selected`）。
4. **测试**：`test/treesel.test.mjs`（新增，进 `npm test`）、`pathutil.test.mjs` 沿用。
5. **文档**：同步 `docs/0.latest/`（`0.概览.md` 变更记录、`2.技术架构.md` 文件树一节）。

## 六、自测结果

单测（`test/treesel.test.mjs`，39 项）之外，用 CDP 驱动真实前端（Vite dev server + Tauri IPC 打桩）
点了一遍**47 项交互**：修饰键点击、取消选择、菜单、确认框、拖拽、以及「界面最终让后端做了什么」
（断言 `invoke` 的实际调用与参数——算法对不代表接线对）。

- [x] Shift 连选：连点两次基于同一锚点重算，不累加
- [x] Cmd 点已选项 = 取消选中；取消到空时高亮全部消失
- [x] 取消选择两条路各自生效（`Esc` / 点侧栏空白）
- [x] 焦点在搜索框里时 `Esc` 不动选区（放行给输入框）
- [x] Cmd 点击不打开文件（标签数不变）
- [x] 折叠目录后 Shift 区间不含被折叠的子项
- [x] 右键未选中行 → 选区重置为该行（菜单也随之变回单选那份）
- [x] 多选运行：目录 + 用例混选，扫出的用例合并去重，一次 `run_batch` 带全部用例
- [x] 报告头 `options.targets` 记下全部目标；报告名 = `<时间戳>-<首个目标>等N项.html`
- [x] 多选删除：父子同选只发一次 `delete_path`（删的是父目录）
- [x] 删除确认文案：多项说「删除选中的 N 项 + 其中 M 个文件夹」，吸收后剩一项则回到单项文案
- [x] 拖拽批次内同名 / 目标目录已有同名：整批不动（0 次 rename）+ 文案与单选一致
- [x] 多选粘贴两个同名文件：得到 `共同.yml` 与 `共同 副本.yml`
- [x] 多选克隆：落在各自所在目录，各自排号
- [x] `cargo test --workspace`（281）/ `npm test`（14 套件）/ `tsc --noEmit` / `vite build` 全绿

**驱动测试抓到的真问题**：两次点击落进 React 同一批处理时，Cmd 加选读到的是上一帧的 `sel`，
前一次加选被丢掉。改用函数式 `setSel((prev) => …)` 修掉——单测覆盖不到这一段，
因为它不是算法错，是 React 的状态时序。

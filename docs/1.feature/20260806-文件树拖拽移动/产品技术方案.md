# 文件树拖拽移动

## 一、需求

文件树里**拖住一个文件或文件夹，放到另一个文件夹上，就把它移过去**。

现在要挪一个用例，只能「复制 → 粘贴 → 回头删掉原来那个」——三步，且中途一旦忘了删就多出一份，
而用例的路径本身是有含义的（目录即分组、`apicase run 目录/` 按目录批量跑）。

## 二、交互

| 动作 | 结果 |
|---|---|
| 拖到**文件夹行**上 | 移进该文件夹 |
| 拖到**文件行**上 | 移进该文件所在的文件夹（同 VSCode，落点比"精确瞄准文件夹"宽容） |
| 拖到**工作空间根行**上 | 移到工作空间根 |
| 拖到自己身上 / 已在目标目录里 | 什么都不做（不报错——用户只是拖回了原处） |
| 文件夹拖进自己或自己的子目录 | 拒绝，并说明原因（那会把目录搬进它自己） |
| 目标目录里已有同名 | **拒绝并提示**，不自动排号 |

最后一条与「复制 / 粘贴」刻意不同：粘贴自动排号（`用例.yml → 用例 副本.yml`）是因为那本就是"再来一份"；
而移动时悄悄改名会让人**在新位置找不到自己刚拖过去的东西**，宁可拒绝，让用户自己决定先改名还是先删。

视觉反馈：拖动中的行降透明度，可放置的目标行整行高亮（同选中态的底色但用虚线边框区分），
不可放置时不给高亮、光标显示禁止。

## 三、实现

前端一层，后端不用改：`rename_path` 已经是「移动」（`std::fs::rename`），且已拒绝「目标已存在」。

- **`TreeNode`** 加 `draggable` 与 `onDragStart / onDragOver / onDrop / onDragLeave`；
  拖拽中的源用一个 ref 存（`dataTransfer` 在 `dragover` 阶段读不到数据，这是浏览器的安全限制），
  `dataTransfer` 里仍写一份路径，方便将来支持从外部拖入。
- **`moveInto(from, isDir, targetDir)`**：校验 → `rename_path` → 刷新两侧目录 → `retargetPaths(from, to)`。
  最后一步是关键：目录被移走后，其下**已打开标签页的路径**、当前文件、树选中项、展开态、子项缓存
  都要跟着改，否则保存会写到一个不存在的位置（`renameEntry` 已有同样的处理，这里复用）。
- **`noteSelfWrite(from, to)`**：告诉 fs 监听「这是我自己干的」，避免弹出「文件已被外部修改」。

## 四、执行计划

1. `App.tsx`：`moveInto` + `TreeNode` 的拖拽事件 + 根行与树容器的放置区。
2. `App.css`：拖动源、可放置目标的样式。
3. `test/`：`pathutil` 已有 `isUnder` / `retargetPath` 的覆盖；新增「移动的落点与合法性判定」纯函数测试
   （`dropTargetDir` / `moveRejection`），把边界（拖到自己、拖进子目录、同名、已在目标里）钉住。
4. 文档：`docs/0.latest/2.技术架构.md` 的文件树一节补交互说明。

# Cookie 改 YAML 与设置页调整

## 一、需求

### 1. Cookie 落盘改 YAML（主线）

现状：jar 存 `.apicase/cookies.json`，是 `cookie_store` 的内部序列化格式——
一行一条、字段名是库的私有约定（`raw_cookie` 里塞着完整的 `Set-Cookie` 串），
人读着费劲、AI 更不敢改，于是只能通过界面或 `apicase cookie` 命令间接操作。

目标：**人和 AI 共同编辑同一份文件**。故

- 格式换成 `.apicase/cookies.yml`，字段就是 cookie 的语义字段（域 / 名 / 值 / 路径 / 过期…）；
- 格式说明进 `docs/0.latest/3.YAML格式规范.md`，并作为 `apicase docs cookies` 的一个主题，
  AGENTS.md 指路过去；
- **删掉 `apicase cookie` 子命令**：文件本身已是可读可写的接口，再留一套命令就是第二条路径，
  而两条路径必然漂移（命令改了文件、AI 手上的内容成了旧的）。

### 2～7. 设置页细节

| # | 位置 | 改动 |
|---|---|---|
| 2 | 设置 → 环境 | 值列占位符 `值（如 https://api.demo.com）` → `值` |
| 3 | 设置 → AI | 首句改为「支持 Claude Code、Codex、OpenCode、Trae、Qoder 等完全接管操作该工作空间用例，包括编写、调试、运行等」 |
| 4 | 设置 → AI | 结构重排（见下） |
| 5 | 设置 → 代理 | 「使用系统 / 环境变量配置的代理（默认）」→「使用系统环境变量配置代理」；「直连，忽略系统代理（调试本地服务推荐）」→「忽略系统代理」 |
| 6 | 设置 → 快捷键 | 去掉每行下方的横线，行距重新配平 |
| 7 | 设置 → 通用 | 「请求」区各行的间距与「位置」区看齐（现在明显更挤） |

AI 分区的新结构：

```
支持 Claude Code、Codex、OpenCode、Trae、Qoder 等完全接管操作该工作空间用例，包括编写、调试、运行等

┌────────────────────────────────────────────────────────┐
│ 初始化环境变量和 AGENTS                      [初始化] │
│ 打开工作空间时自动完成，缺什么补什么                     │
├────────────────────────────────────────────────────────┤
│ CLI 环境变量     /usr/local/bin/apicase（无则「未配置」）│
│ AGENTS.md 配置   已配置 / 不一致 / 未配置                │
└────────────────────────────────────────────────────────┘

MCP
apicase mcp -w <工作空间>                          [复制]
```

要点：

- 一个「初始化」按钮做完两件事（命令行工具进 PATH + 写 AGENTS.md），不再分成两行两个按钮——
  用户要的是「能用」，拆成两步只是把内部实现摊给他看。
- **打开工作空间即自动初始化，没有开关**（原 `aiAutoSetup` 那个默认关的复选框连同 `settings.json`
  里的字段一并删除）：一个「要不要让 AI 能用」的选项只会制造「AI 说找不到 apicase 命令」这类求助。
  按钮仍留着，供自动那次失败（目录只读）或状态被外部改坏时重来。
- AGENTS.md 多一个 **`不一致`** 态：段落在、但内容与当前版本不同（升级后的常态）。
  原来只有 有 / 无 两态，升级后界面显示「已配置」而内容其实是旧的。
- MCP 区块只留标题与命令，代码块配色跟随主题（现在写死深色背景，浅色主题下是黑底黑字）。

## 二、Cookie YAML 格式

```yaml
# apicase cookie 会话。可手工编辑，保存后下次运行即生效。
# 本文件由 apicase 自动维护（响应里的 Set-Cookie 会写回这里），注释与顺序不会保留。
api.demo.com:                 # 域名；前缀 . 表示子域一并生效（.demo.com）
  - name: sid
    value: s3cret
    path: /                   # 省略 = /
    secure: true              # 省略 = false
    httpOnly: true            # 省略 = false
    expires: 2026-08-12T03:04:05Z   # 省略 = 会话 cookie（关掉应用也留着）
```

- **顶层按域分组**：与设置页「Cookies」的分组一致，也是人找 cookie 的自然入口。
- **默认值不落盘**（`path: /`、两个 false、无过期）——同 case 序列化的裁剪风格，文件尽量短。
- `expires` 用 RFC3339 UTC：跨时区归档不歧义，AI 也认得。读的时候宽容一些
  （允许 `2026-08-12 03:04:05`、允许省略秒、允许带偏移）。
- 读写仍**全部收敛在 `cookie_store`**：解析后拼成一行 `Set-Cookie` 交给它，
  域匹配 / 公共后缀防护 / 过期判定不另写一套（与 `CookieJar::put` 同一条路径）。

迁移：加载时若 `cookies.yml` 不存在而旧的 `cookies.json` 在，就按旧格式读进来，
落盘时写成 yml 并删掉 json（留着就是两个真相）。

## 三、执行计划

1. **core**：`cookie.rs` 加 YAML 编解码 + 迁移；`workspace.rs` 的 `COOKIE_JAR` 改名。
2. **cli**：删 `cookie` 子命令；`docs.rs` 加 `cookies` 主题；`.gitignore` 相关不变。
3. **agents.rs**：段落里补一行「cookie 会话在 `.apicase/cookies.yml`，格式见 `apicase docs cookies`」。
4. **前端**：`cookies.ts` 的路径常量；设置页文案 2 / 5、间距 6 / 7；AI 分区重排（含 `ai_status` 新增 `agentsState`）。
5. **文档**：`docs/0.latest/3.YAML格式规范.md` 新增 cookies.yml 一节，`0.概览.md` / `2.技术架构.md` 同步。
6. **测试**：core 补 YAML 往返 / 手写文件读入 / 旧格式迁移；前端 `cookies.test.mjs` 跟随路径改动。

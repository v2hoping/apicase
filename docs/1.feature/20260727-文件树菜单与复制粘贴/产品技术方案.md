# 文件树：行内「⋯」菜单 + 克隆 / 复制 / 粘贴

_创建：2026-07-27_

## 需求

文件树当前只有右键菜单，且只有「新建用例 / 新建文件夹 / 重命名 / 删除」四项。本次：

1. **悬浮时行最右显示「⋯」按钮**（含**工作空间根那一行**），点击弹出菜单，内容与右键菜单完全一致。
2. **菜单补全**
   - 工作空间根：新建用例、新建文件夹、粘贴、显示文件所在位置
   - 目录：新建用例、新建文件夹、克隆、复制、粘贴、重命名、显示文件所在位置、删除
   - 文件：克隆、复制、重命名、显示文件所在位置、删除
3. **Ctrl+C / Ctrl+V**：选中目录时粘进该目录，选中文件时粘到该文件所在目录。

> 评审调整（同日）：目录菜单里的「剪切」改为「粘贴」、去掉「打开目录」；根行也要有「⋯」
> 且悬浮反馈与其它行统一；工具栏「+」的菜单只保留新建两项。
> 因此**不做移动语义**——剪贴板只有「复制」一种模式，`openPath` 与随之申请的
> `opener:allow-open-path` 权限一并撤回（最小权限）。

## 方案

### 一、树选中态：从「当前打开文件」独立出来

现状 `.tree-row.selected` 直接以 `currentCasePath`（当前打开的文件）判定，**目录根本没有选中概念**——
而「选中某个目录后粘贴」要求目录可被选中。故新增 `treeSel: { path, isDir } | null`：

- 点目录 = 展开/折叠 **且** 选中它；点文件 = 打开 **且** 选中它。
- 右键 / 点「⋯」也顺带选中该行（同 VSCode），使菜单与选中态始终一致。
- 切换标签页（`currentCasePath` 变化）时同步到 `treeSel`，视觉上与现状一致。
- 删除 / 移动后若选中项已失效则清空。

搜索结果行仍以 `currentCasePath` 判定高亮（那里没有目录选中语义）。

### 二、「⋯」按钮

`.tree-row` 最右加 `.tree-more`（水平三点 SVG），默认 `opacity: 0`，行 `:hover`、行选中、
或**该行菜单正打开时**（`ctxMenu.entry.path === entry.path`）显形——菜单打开后鼠标移开按钮不能消失，
否则会闪。`onClick` 里 `stopPropagation`，避免连带触发行的展开/打开；菜单锚定按钮左下角
（`getBoundingClientRect`），与顶部「+」按钮的弹法一致。

**工作空间根那一行**（`.tree-root-name`）同样挂一个，走 `entry = null` 那套菜单
（新建 / 粘贴 / 显示位置），点击时顺带 `setTreeSel(null)` 让粘贴落到根。根行不给
克隆 / 重命名 / 删除——对工作空间根做这些既危险又无意义。根行原先是另一套盒模型
（`padding: 4px 6px 8px`、无圆角、无 hover），为此与 `.tree-row` 对齐：26px 行高、6px 圆角、
hover 与 menu-open 底色、0.1s 过渡；**下间距从 `padding-bottom` 换成 `margin-bottom`**，
否则悬浮底色会连那 8px 一起涂上、比其它行高一截。

**工具栏「+」不复用这份菜单**：它是「在这里新建」的入口，弹 `newItems`（只有新建用例 /
新建文件夹），由 `ctxMenu.newOnly` 区分——粘贴 / 显示位置是针对具体项的操作，掺进来只会干扰。

`ContextMenu` 增 `separator` 与 `disabled` 支持——八项菜单不分组读起来费劲，按
「新建 | 克隆·复制·粘贴 | 重命名·显示位置 | 删除」分组。

### 三、剪贴板与三个新动作

**内部剪贴板**（`clip`：`{ path, isDir }`），不走系统剪贴板——跨应用的文件剪贴板在 Tauri
没有现成 API，而这里只需应用内语义。**只有「复制」一种模式**（无移动语义），
故粘贴后剪贴板保留，可连续多次粘贴。

- **克隆**：同目录复制一份，命名 `用例 副本.yml`、再克隆 `用例 副本 2.yml`（`uniqueName()` 探测重名，
  扩展名前插入后缀，目录无扩展名直接追加）。
- **复制**：只记剪贴板，不动磁盘。
- **粘贴**：目标目录 = 选中项是目录则其自身、是文件则其父目录、无选中则工作空间根。走新增的
  `copy_path`。同名时**自动改名**（复用 `uniqueName`），不弹「替换 / 保留两者」——自动改名不会误覆盖，
  是更安全的默认。菜单里**常驻**（能收东西的位置：目录与根），剪贴板为空时 `disabled` 灰显而非隐藏——
  固定位置比忽隐忽现好找。
- **显示文件所在位置**：`revealItemInDir()` 打开父目录并选中该项（根行则定位工作空间目录本身），
  来自已装的 `@tauri-apps/plugin-opener`，`opener:default` 权限集已含，无需额外声明。

**粘贴的两条校验**（失败给可读错误，不动磁盘）：

1. 目录不能粘进**自身或自己的子目录**（会无限递归）。
2. 源路径**已不存在**（外部删了）：提示并清空剪贴板。

### 四、重命名后的路径迁移

新增 `retargetPaths(from, to)`：把 `tabOrder` / `tabCacheRef` / `currentCasePath` / `treeSel` /
`expanded` / `childrenMap` 中**等于 `from` 或位于 `from` 之下**的路径整体改写前缀。
顺带修掉原 `renameEntry` 只匹配精确路径的问题（**重命名目录时，其下已打开文件的标签会指向失效路径**）。

### 五、Ctrl+C / Ctrl+V 的作用域

**只在左侧栏内有焦点时生效**，不进全局快捷键表（`shortcuts.ts` 那套是 document 级分发，
劫持 Ctrl+C/V 会破坏编辑器、响应体、终端里的正常复制粘贴）。做法：`.sidebar` 挂 `tabIndex={-1}`
（可点击聚焦、不打乱 Tab 顺序）+ `onKeyDown`；事件源是 `input` / `textarea` / `contentEditable`
（如树顶部的搜索框）时一律放行。mac 用 ⌘、其余用 Ctrl（`e.metaKey || e.ctrlKey`，与 `eventToAccel` 同口径）。

文件行的菜单里**没有**「粘贴」（需求清单如此），但选中文件时 `Ctrl/⌘+V` 仍粘到它所在目录——
快捷键面向"当前位置"，菜单面向"这一项能做什么"，两者语义不同。

### 六、后端：`copy_path`

```rust
fn copy_path(from: String, to: String) -> Result<(), String>
```

文件走 `std::fs::copy`，目录递归建目录 + 逐项复制（隐藏项一并复制——只有 `list_dir`
出于展示需要跳过 `.` 开头）。前端已保证目标唯一，后端仍再校验一次：目标已存在 → 拒绝；
`to` 位于 `from` 之下 → 拒绝（防自我递归）。

## 落地文件

- `app/src-tauri/src/lib.rs`：新增 `copy_path` 命令 + `copy_dir_all` 递归工具，注册进 `invoke_handler`；
  新增测试（文件复制、目录递归复制、目标已存在、自我递归）。
- `app/src/pathutil.ts`（新）：`baseName` / `dirName` / `joinPath` / `relPath` / `isUnder` /
  `uniqueName` / `retargetPath` —— 从 App.tsx 提出来以便单测（`draft.ts` 的 multipart filename 也复用同一份 `baseName`）。
- `app/src/App.tsx`：`treeSel` 选中态；`TreeNode` 与根行的「⋯」按钮；`ContextMenu` 支持分隔线 +
  禁用项 + 贴边翻转；`ctxItems` 按根/目录/文件三分支给菜单；`cloneEntry` / `pasteInto` /
  `takenNamesIn` / `revealEntry`；`retargetPaths`；侧栏 `onKeyDown` 接 Ctrl+C/V。
- `app/src/App.css`：`.tree-more` 悬浮显形（含根行）、`.ctx-sep` 分隔线、`.ctx-item:disabled` 灰显。
- `app/test/pathutil.test.mjs`（新）：路径工具与 `uniqueName` / `isUnder` / `retargetPath` 的单测。

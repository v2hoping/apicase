# 运行报告：文件名带上目标，去掉那层目录

_创建：2026-08-01_

## 需求

报告原本落在 `<workspace>/.apicase/reports/<YYYYMMDD-HHmmss>/report.html`，两个问题：

1. **看名字认不出跑了什么**。一串 `20260728-215758` / `20260730-050633` 排在一起，
   想找"上次跑 `01-方法` 那次"只能一个个点开。目标信息在报告页里有，但得先打开才知道。
2. **那层目录是空壳**。每个目录里只有一个 `report.html`（40–68KB，样式脚本数据全内联）——
   报告本就刻意做成**自包含单文件**，为的是能整份转发给同事。既然产物是一份可独立传播的
   HTML，用目录包着它只是让每次查看都多进一层，Finder 里也没法直接空格预览。

改成：

```
.apicase/reports/20260728215758-01-方法.html
```

## 方案

### 一、命名规则（`pathutil.ts` 的 `reportFileName`）

`<YYYYMMDDHHmmss>-<目标名>.html`，纯函数、可单测。

**时间戳必须在前**——这是唯一容易做错的地方。目录列表按名字排序，时间戳打头才能让
字典序等于时间序；目标名放前面就成了按目标分组，"最近跑的那次"得满目录翻。

**时间戳内部不加分隔符**（14 位连续数字，同 Rails migration 的时间戳）：目标名自带连字符
是常态（`01-方法`），时间戳里再插一个就成了 `20260728-215758-01-方法`，边界得数着看；
连成一串之后"数字止于何处"即时间戳止于何处。

目标名取自运行目标的 basename：右键目录跑 → 目录名；右键单个 `.yml` 跑 → 文件名去扩展名；
目标是工作空间根 → basename 恰好就是工作空间目录名，不必特判。

三处净化，都是为了"拼出来的名字一定建得出来"：

| 处理 | 为什么 |
|---|---|
| 去掉 `.yml` / `.yaml`（大小写不敏感） | 否则成了 `…-登录取token链.yml.html` |
| `\ / : * ? " < > \|` 与控制字符 → `-`，压缩连续 `-`、去首尾 `-` 与 `.` | Windows 不收这些字符（macOS 只禁 `/`，按严的来）；首尾的点会做出隐藏文件 |
| 按 **UTF-8 字节**截到 60，切点落在字符边界 | 目录名上限 255 字节，一个汉字 3 字节；切碎汉字会得到乱码文件名 |

净化后为空（目标名全是点或全是非法字符）就只留时间戳——宁可少个后缀，
也不能拼出一个建不出来的文件名。

### 二、去掉目录

- `App.tsx`：`reportDirFor` → `reportFileFor`，直接返回文件路径；
  `RunSession.dir` 字段一并删除（它被赋值但从未被读取）。
- `src-tauri/commands/exec.rs`：仍 `create_dir_all(parent)`，只是 parent 从三级变成
  `.apicase/reports` 两级——首次运行时它还不存在。
- `core/examples/run_workspace.rs`：`reports/cli/report.html` → `reports/cli.html`，
  与桌面端保持同一种形态（CLI 用固定名，重跑覆盖）。

改动很安全：报告目录名**全项目没有任何代码去解析**，只有生成与拼路径两处；
历史报告以文件路径为会话 id，读回靠解析 HTML 里的内联数据（`parseReportHtml`），
与文件名无关。

## 落地文件

- `app/src/pathutil.ts`：`reportFileName` + `clipBytes`。
- `app/src/App.tsx`：`reportFileFor` 取代 `reportDirFor`；`RunSession.dir` 删除。
- `app/src-tauri/src/commands/exec.rs`：建目录的注释。
- `app/core/examples/run_workspace.rs`：CLI 报告输出路径。
- `app/test/pathutil.test.mjs`：命名规则的用例（补零、排序、净化、截断、兜底）。
- `docs/0.latest/0.概览.md`、`2.技术架构.md`：路径描述同步。

## 影响

- **已有的历史报告不受影响**：旧的 `<时间戳>/report.html` 照常能打开（按文件路径），
  只是与新报告两种形态并存。要不要把旧的搬平成 `<时间戳>.html`，等用户决定——
  旧报告的文件名里补不出目标名（那信息在 HTML 内联数据里，要读出来才知道）。
- **同一秒对同一目标跑两次仍会覆盖**。加了目标名之后，同一秒跑不同目标已不会撞名；
  剩下这一种手点触发不了，等真做了自动连跑再补去重后缀。

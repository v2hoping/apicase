# 画布坐标从顶层 `ui.nodes` 挪进 step

_创建：2026-08-01_

## 需求

画布坐标原本存在 case 顶层：

```yaml
steps:
  - id: login
    request: { … }
  - id: order
    request: { … }
ui:
  nodes:
    login: { x: 40, y: 40 }
    order: { x: 40, y: 200 }
```

这是一张与 `steps:` **并行**的 id 映射表，三个问题都由此而来：

- **改 id 要动两处**——漏改一处，坐标就成了对不上号的孤儿；
- **删 step 会留下孤儿坐标**，文件里越攒越多，没人会去清；
- **diff 里看不出坐标属于谁**——`login: { x: 40, y: 40 }` 这行改动，要往上翻几十行才知道说的是哪个 step。

改成跟着 step 走，用一个 `ui:` 子键兜住前端属性：

```yaml
steps:
  - id: login
    protocol: http
    ui:
      x: 40
      y: 40
    request: { … }
```

## 方案

### 一、格式与解析

- **模型**：`Case.ui: Option<CaseUi>` 删除，`Step.ui: Option<StepUi>` 新增（`StepUi { x, y }`）。
  类型独立而不是直接摊平成 `x` / `y` 两个字段，是为了将来的前端属性（折叠、配色…）
  有地方加——"前端的东西都在 `ui` 下面"这一条要立得住。
- **书写顺序**：`id → protocol → ui → dependsOn → request → …`。
- **硬切换**：顶层 `ui:` 块不再识别，坐标丢失、回退自动布局。坐标没有执行语义，
  丢了只是重排一次画布；为它长期背两套读法不值当。
- **写坏了只丢坐标**：缺 `x`、值不是数字、`ui: hello` 都回退成"无坐标"，
  而不是让整条用例解析失败——视图态不该有能力废掉一条用例。

### 二、写法与别处一致（块式）

一行一个字段，和文件里其它嵌套对象同一套写法：

```yaml
ui:
  x: 502
  y: -70
```

曾经试过给 `ui` 开流式（`{ x: 502, y: -70 }`）以免坐标在 step 中间占三行，但那要在输出器里
加一条按 key 的例外规则，还得处理"值里有字符串就得回退块式"（流式上下文要挡 `,` `}` `]`）。
省下两行的收益，换不来"全文件两种写法"这个代价——已回退。

顺带保留的一处重构：把"写一对 `key: value`"抽成 `emit_pair`。序列项要把第一个 key
紧跟在 `- ` 后面，本来有自己的一套 key 循环，规则各写一遍迟早只改一处而分叉。

### 三、前端仍用 id → 坐标表

画布按 id 查坐标最顺手（`FlowCanvas` 的 `layout(nodes, ui)` 不动），所以前端内部形态
保持 `UiNodes = Record<id, {x,y}>`，只在两处边界转换：

- `caseToRequests`（读）：各 step 的 `ui` 收成一张表；一个都没有时给 `undefined` 而非 `{}`；
- `stateToCase`（写）：按 `rd.id` 从表里取，分发回各 step。

### 四、迁移

`migrate.rs` 加第 4 条规则。与前三条不同，这条**得先从原文里捞坐标**——`parse_case`
已经不认顶层 `ui:`，等模型出来就没了。故用 `serde_yaml` 读一遍原文取 `ui.nodes`，
按 id 灌回对应 step；捞不到 id 的坐标随之丢弃，那正是这次要根除的孤儿。

语义校验里把 `ui` 清空后再比对：坐标是视图态，且迁移前后本来就分别是"顶层有 / step 上有"。

## 落地文件

- `app/core/src/model.rs`：`CaseUi` / `NodePos` → `StepUi`；`Step.ui` 新增，`Case.ui` 删除。
- `app/core/src/yaml/mod.rs`：`norm_ui` → `norm_step_ui`；`ser_step` 输出 `ui`；顶层不再读写。
- `app/core/src/yaml/emit.rs`：`emit_pair` 抽取（映射与序列项共用同一份 key 规则）。
- `app/core/examples/migrate.rs`：`adopt_legacy_ui`（文本层捞坐标）+ 语义校验忽略 `ui`。
- `app/src/case.ts`：`Request.ui` 新增，`Case.ui` 删除，`UiNodes` 注释改为"前端内部形态"。
- `app/src/draft.ts` / `app/src/App.tsx`：两处边界的收集与分发。
- `app/core/src/yaml/tests.rs`：黄金测试更新；新增 step 坐标解析 / 写坏回退 / 顶层不再识别。
- `app/core/src/yaml/emit.rs`（测试）：step 坐标的块式输出（含 `y` 不带引号）。
- `app/test/draft.test.mjs`：坐标收集为 id 表、部分缺失、全无时给 `undefined`。
- `docs/0.latest/3.YAML格式规范.md`、`0.概览.md`、`2.技术架构.md`：格式与描述同步。

## 影响

- **已有 case 的画布布局会丢**（顶层 `ui:` 不再识别），跑一次 `migrate` 即可恢复：

  ```sh
  cargo run -p apicase-core --example migrate -- <工作空间> --write
  ```

- 用户工作空间 `~/development/local/apitest` 已迁移（2 个文件有坐标：`01-方法/get.yml`、
  `07-多步flow/登录取token链.yml`），重跑 migrate 显示 0 个待更新（幂等）。

# 认证方式补全与表格样式统一

_创建：2026-07-23_

## 需求

1. **断言配置表格化**：请求编辑器「断言」Tab 的配置表，改用与「参数 / 请求头」
   完全一致的 Excel 网格样式。
2. **断言结果表同款**：响应区「断言」栏的结果表，同样对齐这套网格——配置与结果
   两处看起来是同一张表，只是一处可编辑、一处只读。
3. **认证补全与美化**：认证方式此前只有 `none / bearer / basic / apikey` 四种，
   且下拉里直接显示小写英文标识（`basic`、`apikey`）。调研 Postman / Insomnia /
   Bruno / Hoppscotch 后，改用它们通行的显示名（**Basic Auth / Bearer Token /
   API Key / No Auth**），补上主流工具都有、当前缺失的 **Digest Auth** 与
   **OAuth 2.0**，并重做认证面板的视觉与交互。

## 方案

### 一、断言两张表统一为 `.kv-table.grid`

- **配置表**（`AssertTable`）：加 `grid` 类，直接复用参数表的连续单线网格、表头灰底、
  单元格内嵌输入、聚焦高亮。操作符下拉去掉自身边框/圆角/背景，以 `padding:6px 8px`
  + 14px 字号内嵌进单元格（行高与相邻的 `<input>` 严丝合缝），hover 淡底、展开时
  与输入框同款 accent 描边。
- **结果表**（响应区）：同样加 `grid`。它原本继承 `.kv-table.readonly` 的等宽 13px +
  `4px 8px` 内边距，与配置表对不上——以 `.kv-table.readonly.assert-result-table td`
  （特异性压过 `readonly`）统一为 `6px 8px` + 14px 系统字体；「断言」列 112px 对齐
  配置表的操作符下拉宽度，结果徽标列 34px 对齐网格删除列。取消目标列的 accent 蓝与
  操作符列的 muted 灰，只留 ✓/✗ 徽标着色。
- `exists / notExists` 无期望值的单元格：两张表共用 `.kv-table .na-cell` 灰底示意
  （结果表内仍显示 `—`）。

### 二、认证：命名与面板

调研结论（Postman / Insomnia / Bruno / Hoppscotch 命名一致）：`No Auth`、`Basic Auth`、
`Bearer Token`、`API Key`、`Digest Auth`、`OAuth 2.0`、`AWS Signature v4`、`NTLM`…
本期取前六种（AWS SigV4 / NTLM 留待后续）。

面板（`AuthPanel`，布局为「顶部选方式 → 字段 → 底部预览」）：

- **顶部**：`认证方式` 下拉显示英文通名，右侧灰字给一句中文说明（`AUTH_TYPE_METAS.zh`）。
- **字段**：普通字段用 `VarInput`（`{{变量}}` 高亮，边框画在外层容器、内部两层共用
  `.auth-input` 保证排版一致）；密码类字段（密码 / API Key 值 / Client Secret）用
  `AuthSecret`——默认 `type=password` 掩码，点眼睛图标切明文（切明文后才做变量高亮）。
- **底部预览**（`.auth-preview`）：**一行**说清该方式最终往报文上附加什么——
  `附加请求头 Authorization: Basic <真实 base64>`；API Key 放 query 时标签改为
  「附加查询参数」；Digest 与 OAuth 2.0 在同一行末尾括注其额外交互
  （「收到 401 challenge 后计算并重发」/「发送前向 <token 端点> 换取」）。

### 三、Digest Auth（RFC 2617 / 7616）

需要服务端 401 的 `WWW-Authenticate` challenge 才能算摘要，因此**发送流程要能重发一次**：

- `parseDigestChallenge` 解析 `realm / nonce / qop / opaque / algorithm`（兼容带引号与
  裸 token 两种写法）。
- `buildDigestHeader` 计算：`HA1=MD5(user:realm:pass)`（`MD5-sess` 时再摘一次）、
  `HA2=MD5(method:uri)`（uri 取 path+query）、`response=MD5(HA1:nonce:nc:cnonce:auth:HA2)`；
  服务端不给 qop 时退化为两段式 `MD5(HA1:nonce:HA2)`。`qop/nc/algorithm` 不加引号，
  其余参数加引号。`auth-int` 不支持（罕见）。
- **MD5 自带实现**（`md5.ts`）：WebCrypto 的 `crypto.subtle` 不提供 MD5，而 Digest 默认
  就是 MD5——只能自己实现（已用 node crypto 逐向量比对，含 55/56/63/64 字节填充边界）。

### 四、OAuth 2.0（客户端凭据）

- 字段：`Token URL / Client ID / Client Secret / Scope / 凭据位置`（Basic 请求头 或 表单体）。
- 发送前 POST token 端点（`grant_type=client_credentials`），解析 `access_token` /
  `token_type` / `expires_in`，以 `token_type` 归一后的形式注入 `Authorization`。
- **token 缓存**：按 `tokenUrl|clientId|scope|凭据位置` 为键缓存，提前 30s 过期；
  认证面板任一字段变更即 `clearTokenCache()`，避免继续用旧令牌。
- 失败信息可读：非 2xx / 非 JSON / 无 `access_token` 分别给出带响应片段的错误。

### 五、发送流程收敛到 `sendWithAuth`

静态头（Basic / Bearer / API Key）仍由 `buildApiRequest` 组装；Digest 的 401 重发与
OAuth 2.0 的 token 交换都要发**额外请求**，统一收敛进 `sendWithAuth(draft, send)`：
`send` 由调用方注入（App 里就是后端 `send_request`），因此 token 请求与重发同样
**走后端 reqwest**（绕开 CORS）并**复用代理设置**。Digest 只重试一次，避免死循环。

## 落地文件

- `app/src/md5.ts`（新）：RFC 1321 MD5，仅供 Digest 摘要使用。
- `app/src/auth.ts`（新）：`AUTH_TYPE_METAS` / `authPreview` 显示元信息；
  `parseDigestChallenge` / `buildDigestHeader`；OAuth 2.0 取 token + 缓存
  （`clearTokenCache`）；统一发送入口 `sendWithAuth`。
- `app/src/case.ts`：`AuthType` 增 `digest` / `oauth2`，`AuthSpec` 增对应子对象；
  `normalizeAuth` / `serializeAuth` 补齐（`clientAuth: header` 为默认值不落盘）。
- `app/src/draft.ts`：`ReqDraft` 增 7 个认证字段；`emptyDraft` / `requestToDraft` /
  `draftAuth` 同步；新增 UTF-8 安全的 `utf8Base64`（`btoa` 只吃 Latin-1，中文密码会抛错），
  Basic 改用它。
- `app/src/flow.ts`：`resolveDraft` 对新增认证字段做 `{{变量}}` 替换。
- `app/src/App.tsx`：`runRequestWithCtx` 改为经 `sendWithAuth` 发送；断言结果表加 `grid`
  与 `na-cell`。
- `app/src/RequestEditor.tsx`：新增 `AuthPanel` / `AuthText` / `AuthSecret` / `EyeIcon`，
  替换原先内联的认证表单；`AssertTable` 加 `grid` 与 `na-cell`。
- `app/src/App.css`：认证面板样式（`.auth-type-row`/`.auth-type-zh`/`.auth-input`/
  `.secret-field`/`.secret-toggle`/`.auth-preview*`）；断言两表的网格对齐样式。
- `app/test/auth.test.mjs`（新，50 项）：MD5 向量、challenge 解析、**RFC 2617 §3.5 官方
  示例的 response 比对**、401 重发/不重发/只重试一次、OAuth 2.0 两种凭据位置 + 缓存命中
  + 配置变更失效 + 错误路径、YAML 往返。已接入 `npm test`。

## 验证

- `npm test`：37 + 66 + 50 全通过；`npx tsc --noEmit` 与 `npx vite build` 均无错。
- 未做真机联调（需要真实的 Digest / OAuth 2.0 服务端），Digest 正确性以 RFC 官方向量

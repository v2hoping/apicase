# 断言目标统一 `res.` 前缀与自动补全

_创建：2026-07-31_

## 需求

### 一、断言目标统一以 `res` 开头

现在断言的 `target` 是三种互不相干的写法拼在一个字段里：`status`（裸词）、
`header.Content-Type`（自造前缀）、`$.data.token`（JSONPath）。同类工具都有一个
统一的响应命名空间——Bruno 的 `res.status` / `res.body.x` / `res.headers['x']`，
Postman 的 `pm.response.*`——用户从别处迁过来时，"响应的东西都挂在 `res` 下"
是能直接迁移的直觉，而"status 裸写、header 要加前缀、body 用 `$`"三套规则不是。

统一后：

| 新写法 | 含义 | 旧写法 |
|---|---|---|
| `res.status` | 状态码 | `status` |
| `res.headers.Content-Type` | 响应头（大小写不敏感） | `header.Content-Type` |
| `res.headers['Content-Type']` | 同上，key 含点/空格时用 | — |
| `res.body` | 整个响应体 | `$` |
| `res.body.data.token` | 响应体字段 | `$.data.token` |
| `res.body.list[0].id` | 数组下标 | `$.list[0].id` |

**硬切换**：只认 `res.*`，旧写法一律判为无效目标（实际值列显示 `∅`，断言不通过）。
项目仍在 0.1，与其长期背两套语法、让 YAML 里混着两种风格，不如一次切干净——
这与 `steps:` 取代 `requests:` 时的取舍一致（见 `docs/0.latest/3.YAML格式规范.md`
的"序列化约定"）。

### 二、断言目标输入框支持自动补全

断言目标现在是个裸 `<input>`，路径全靠手打，打错只会在跑完之后看到一个 `∅`，
分不清是"服务端没返这个字段"还是"我路径写错了"。补全要做到：

1. 输入框聚焦、内容为空时提示 `res`；
2. 打出 `.` 后提示 `status` / `headers` / `body`；
3. 进入 `res.headers.` 后提示**这次响应真实返回的响应头名**；
4. 进入 `res.body.` 后**按最近一次响应的实际 JSON 结构**逐层提示字段名与数组下标，
   并在候选右侧显示该路径的当前值摘要（`"abc"` / `0` / `{4}` / `[3]`）。

值摘要是这件事的关键：它把"这个字段真实长什么样"直接摆在选路径的地方，
断言写完之前就能确认路径取得到值——`∅` 的排查成本正是这样被消掉的。

没跑过请求时（无响应可读）只提示 `res` 与三个固定字段，不臆造响应结构。

### 三、期望值也按目标的当前值给建议

目标补全回答"路径写对没有"，期望值这一格还差一问："该填什么"。填的十有八九就是
这次返回的值，所以把它摆在 placeholder 上（`当前：200`），聚焦后一条候选可点可回车。

但**只建议、不自动填**，而且要克制到什么时候不出声——把返回值一键固化成期望值，
正是脆弱断言的经典来路（uuid / 时间戳 / 随机 id 钉死之后下次必红）。

## 方案

### 一、目标解析（执行内核）

`assert.rs::actual_for` 从"三种前缀分派"改为"`res` 命名空间下三个域"：

```
res            → 无效（None）
res.status     → 状态码（数字）
res.headers    → 无效：必须带头名
res.headers.X  → 响应头 X（名字大小写不敏感，取第一条匹配）
res.headers['X'] / ["X"]  → 同上，支持含点/空格/中文的 key
res.body       → 整个响应体
res.body<路径> → 响应体内路径，`.key` / `[n]` / `['key']` 复用 jsonpath
其余           → 无效（None）
```

要点：

- **域名后必须是边界**：`res.bodyfoo`、`res.statusx` 判无效，不做前缀匹配。
- **`res.body` 在非 JSON 响应上返回原始文本**（而非无效）。HTML / 纯文本响应体做
  `contains` 断言是真实需求，旧写法的 `$` 做不到（JSON 解析失败就全军覆没）。
  `res.body.x` 在非 JSON 上仍是无效——那确实取不到。
- **`jsonpath.rs` 的标识符规则放宽到允许连字符**：`res.headers.Content-Type` 与
  `res.body.user-name` 都走点号形式。JSON 的 key 带连字符很常见，而我们的路径不是
  JS 表达式、没有减法语义，放宽不引入歧义（Bruno 因为把左侧当 JS 表达式跑，
  只能强制写 `res.headers['content-type']`——这是它的语法约束，不是更优）。

### 二、路径补全（前端）

新增 `app/src/assertPath.ts`，一个不依赖 React 的纯模块，负责：

- `evalPath(path, resp)`：按与内核相同的语义在最近一次响应上取值（用于候选的值摘要）；
- `suggestTargets(input, resp)`：由当前输入文本算出候选列表。

候选生成规则——把输入切成**已闭合前缀** + **正在输入的片段**，前缀求值得到当前节点，
列出该节点的成员并用片段做前缀过滤：

| 当前输入 | 候选 |
|---|---|
| `""` / `r` / `re` | `res` |
| `res.` / `res.st` | `status` / `headers` / `body`（按片段过滤） |
| `res.headers.` | 响应头名（来自最近响应） |
| `res.body.` | 响应体顶层 key；顶层是数组时给 `[0]`…`[n]` |
| `res.body.data.` | `data` 的子 key |
| `res.body.list[` | `[0]`…（下标） |

每条候选带：插入后的完整文本、显示名、值摘要、**是否还有下一层**。
采纳后若还有下一层则自动补 `.` 并继续弹出，一路点到底不用手打分隔符。

数组下标候选上限 50 条、字符串摘要截断 24 字符——响应体动辄上千行，
候选面板不该变成第二个响应体查看器。

### 三、交互（AssertTable）

目标列由 `<input>` 换成新的 `TargetInput` 组件：

- 聚焦 / 输入 / 点击时弹出候选；`Esc` 关闭；失焦关闭。
- `↑` `↓` 移动高亮，`Enter` / `Tab` 采纳，鼠标点击采纳。
- 浮层用 `position: fixed` + `getBoundingClientRect` 锚定输入框下沿——断言表在
  `.req-scroll` 里，绝对定位会被滚动容器裁掉（与 `.ctx-menu` 同一套做法）。
- 无候选时不弹空面板。

响应数据经 `App.tsx` → `RequestEditor` → `AssertTable` 透传：只传补全需要的
`{ headers, body }`（`RespLite`），不把整个运行态递下去。

### 四、期望值建议（`suggestValue`）

由 `evalTarget(target, resp)` 取当前值，转成裸文本（期望值格里填 `200` 而不是 `"200"`——
内核的 `value` 恒是 `String`，引号对比较毫无影响）。**不建议的清单比建议本身重要**：

| 情况 | 为什么不出声 |
|---|---|
| `exists` / `notExists` | 本来就不填值 |
| `matches` | 原文当正则会静默错判：`application/json` 里的 `.` 是通配符 |
| 目标取不到值 | 此时该修的是 target，不是 value |
| 值是 `null` | 比较里等同「不存在」，建议它毫无意义 |
| 值是对象 / 数组 | `eq` 退化成整段文本比对，又长又脆，这种目标本就该配 `exists` |
| 空串 / 超过 64 字符 | 前者 placeholder 显示「当前：」很怪，后者是钉死一大段文本 |

交互：值为空且有建议时 placeholder 显示 `当前：<值>`；聚焦弹一条候选（复用目标列的
`.path-menu` 样式），点击 / `Enter` / `Tab` 填入，一开始打字就收起——用户已经在写自己的值了。

## 影响与迁移

- **已存盘 case 的断言会失效**：旧 `target` 取不到值，断言实际值显示 `∅`。
  应用**不会**静默改写用户的源文件——那比显式失败更糟；迁移由已有的显式工具承担：

  ```sh
  cargo run -p apicase-core --example migrate -- <工作空间>          # 预演，不写盘
  cargo run -p apicase-core --example migrate -- <工作空间> --write   # 写入
  ```

  `migrate.rs` 新增第 3 条规则（`status` → `res.status`、`header.X` → `res.headers.X`、
  `$.a` → `res.body.a`），在**模型层**改而非文本替换——文本替换分不清 `target` 与
  `outputs` 的 JSONPath，会把不该动的输出提取一并改掉。认不出的写法原样留着让它显式失效，
  不猜一个可能更错的目标。规则幂等，重复跑不会二次加前缀。

  一个容易搞错的映射：`$.headers['Content-Type']` → `res.body.headers['Content-Type']`
  而**不是** `res.headers[...]`——`$` 一向指响应体根，httpbin 这类回显接口的 body 里
  正好也有个 `headers` 字段，映射成响应头就把语义改了。
- **`outputs` 的 JSONPath 不变**：它只从响应体提取，`$` 即 body 根，没有跨域歧义，
  加 `res.body.` 前缀纯属噪音。两处语法不同是有意的——断言要跨 status/headers/body
  三个域，输出只有一个域。
- 暂不提供 `res.statusText` / `res.responseTime`：内核的 `RespView` 目前只带
  status / headers / body，加字段要动 runner 的调用链，等有实际需求再说。

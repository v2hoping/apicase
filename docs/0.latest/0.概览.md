# apicase 概览

> 本目录（`docs/0.latest/`）是项目**当前全局最新的全部文档**，事实来源。
> 需求落地后将要点合并至此，保持其始终反映最新状态。

## 是什么

apicase 是一款 **API 接口调试、管理与用例编排** 的桌面软件。核心抽象：把「用例（case）」建模为 **DAG**——单个 API 调试 = 只有一个节点的 DAG，单 API 与编排用例在模型上统一。

设计上走 **文件即数据（local-first）** 路线：打开一个目录即一个**工作空间（workspace）**，folder 即分组，case 即用例。参考标杆 **Bruno**（理念）与 **Postman**（UI / 功能）。

## 当前能力（v0.1）

**脚手架 + 单 API 调试 MVP** —— 已落地：
- Tauri 2 桌面应用骨架可编译运行。
- 界面发起一个 HTTP 请求 → 由 Rust 后端（`reqwest`）发出 → 展示响应（状态码 / 耗时 / 大小 / 响应头 / 响应体）。即「单节点 DAG」的端到端执行。
- Postman 风格 UI：方法下拉与 URL **连体** + Send 请求行；Headers / Body 配置 Tabs；响应区标题栏单行——响应体 / 响应头 / 断言 Tabs 靠左、状态/耗时/大小靠右，且与请求编辑区上下可拖动分栏、可折叠为一行（响应体恒美化，非 JSON 回退原文）。
- 错误处理：空 URL、非法方法、网络失败均有可读提示。

**工作空间与界面外壳** —— 已落地（2026-06-30）：
- 左上角「选择工作空间」自定义下拉：打开/创建工作空间（选目录 → 幂等写 `application.yml`）、最近列表（内存态）。
- 左侧**文件树**：选中工作空间后懒加载、可展开/折叠目录；**缩进参考线**标示层级（对齐父行折叠箭头，压过选中底色保持连续）；空目录展开显示「空文件夹」占位；左侧栏可拖动调宽（默认 260px）；空状态可点击「创建或打开」。
- macOS **自定义标题栏**：隐藏标题、红绿灯下移与下拉垂直对齐、顶栏可拖动窗口；全屏时下拉贴左、退出全屏平滑让位不覆盖。

**case 读写与格式** —— 已落地（2026-06-30）：
- 点击 `.yml` case → 解析渲染到请求构建器；编辑后 `Cmd/Ctrl+S` 写回；文件树右键新建/重命名/删除 case 与 folder。
- 文件树顶部**搜索栏**（递归搜全工作空间）+ **`+` 新建按钮**；新建 case 走**可视化对话框**（名称 + method + URL），创建即打开。
- 请求构建器对齐 Postman：**Params / Headers / Auth / Body** 四 Tab（Params 与 URL 双向同步，Body 多类型，Auth 含 bearer/basic/apikey）。
- **case YAML 格式定稿**（参考业界）：request 借 Postman/HAR/Insomnia/Bruno，flow 借 Arazzo（OpenAPI 官方 workflow）+ GitHub Actions；单/多节点统一，详见概念模型。

**flow DAG 画布与三视图** —— 已落地（2026-06-30）：
- case 顶栏**两级视图切换（文本 | 可视）**：文本 = 原始 YAML（互斥）；点「可视」展开二级 **流程 / 请求**（流程 = DAG 画布、请求 = 复用编辑器，二者可并存、至少保留其一）。
- **内容驱动默认视图**（仅打开时决定）：校验不通过 → 文本兜底；有效单请求 → 请求；有效多请求 → 流程 + 请求。
- **DAG 画布**：`dependsOn` 自动分层布局（支持 fan-in）、SVG 贝塞尔连线、节点卡片（method 徽章 + 运行状态点）、选中高亮、添加/删除步骤；点状网格背景。
- **步骤编排**：请求 ID / 输出 / 断言 / 文档均为请求编辑器内的 Tab（请求 ID 位于末尾，改名同步引用），输出提取用「变量名 / JSONPath」；「文档」标签支持 markdown 编辑与预览；`发送` 与 `▶ 运行`（拓扑序逐节点执行）。依赖不再手动配置——新增请求默认串接当前选中请求，DAG 连线据 `dependsOn` 自动呈现。单节点与多节点发送按钮统一为 `发送`。
- 内部统一 step 列表模型（单节点 = 1 个 step），单 → 多平滑提升；读写**仅认** `steps:` 列表（每步含 `protocol:` 与 `request:`）——旧格式（`requests:` 列表 / `http:` 报文键）不再兼容，会被判为无效 case 回退纯文本编辑。

**flow 执行引擎** —— 已落地（2026-07-01）：
- **变量透传**：运行时把 case 级 `vars` 与上游 `outputs` 注入请求各字段；语法 `${{baseUrl}}` / `${{steps.login.outputs.token}}`，未解析保留字面量。
- **输出提取**：按 `outputs` 从响应提取变量供下游引用；路径与断言目标同一套语法（`res.status` / `res.headers.<名>` / `res.body<路径>`），故响应头、状态码同样可提取。
- **断言**：每步（及单节点顶层）配置断言（`eq/ne/contains/exists/notExists/gt/lt/matches`，目标统一以 `res` 开头 —— `res.status` / `res.headers.名` / `res.body<路径>`），目标格按最近一次响应逐层提示路径与当前值、期望值格提示该目标的当前值，运行后逐条 ✓/✗，失败标红节点。
- **运行全部**：拓扑序串行执行，`await` 间同步透传 outputs，数据真正在步骤间流动。

**environment 多环境 + 界面优化** —— 已落地（2026-07-01）：

- **application.yml 可视设置页（仿 GitHub 设置）**：顶栏「文本 | 可视」切换；可视 = 左导航（通用 / 主题 / 环境）+ 右配置面板。**环境**页可视化增删环境、编辑变量（`KVTable`），保存写回 `application.yml`（`dumpApplicationConfig` 保留其它顶层键）；与 topbar 环境下拉、变量注入实时联动。（环境页版式后改为左列表 + 右详情，见 2026-07-16 条目。）

**请求页 · 请求体类型平铺 + XML/Binary + multipart 真发送** —— 已落地（2026-07-23）：
- **类型平铺（取 Apifox 形式，非 Postman 的 raw + 二级语言下拉）**：`BodyType` 扩为 `none / form-data / x-www-form-urlencoded / JSON / XML / Text / Binary`，UI 由下拉改为一排 chip（`.body-type-chips`，窄面板自动换行，选中 accent 实底）。取平铺是因为——JSON 占绝大多数、一级直达少一次点击；一眼可见当前发什么体；且 `BodySpec.type` 本就是平铺的，走 Postman 形式反而要多维护一层 `raw + language ↔ type` 映射、凭空造概念。
- **Content-Type 行**：类型 chip 下固定一行，把最终会发的头摆明——`text`/`binary` 可编辑（`text` 默认 `text/plain`；`binary` placeholder 显示按当前文件推断出的值），其余只读展示（`form-data` 显示「multipart/form-data」，实际 boundary 由后端 reqwest 生成）。新增 `DEFAULT_CONTENT_TYPE` 表（json→`application/json; charset=utf-8`、xml→`application/xml; charset=utf-8`、text→`text/plain; charset=utf-8`、form-urlencoded→`application/x-www-form-urlencoded`），文本类显式带 `charset=utf-8`（对齐新版 Postman，规避 xml/text「无 charset 默认非 UTF-8」历史坑；form-urlencoded 值经百分号编码无需 charset）；**手填的 Content-Type 头优先级最高**。
- **Binary**：`plugin-dialog` 选单文件，YAML 存 `filePath`；发送时**由后端读盘发原始字节**（前端只传路径，大文件不经 IPC 搬运；读不到给可读错误）。路径过长时 `direction: rtl` 截前保后。**Content-Type 对齐 Postman**：`guessContentType` 按文件扩展名推断（`.png`→`image/png` 等约 30 种常见类型），推不出兜底 `application/octet-stream`，手填可覆盖。
- **form-data 由「假功能」变真**：此前 UI 可选可存但 `buildApiRequest` 根本不组装 body（发出去是空体）。现由前端传字段列表、后端交 `reqwest::multipart` 组装，`.multipart()` 在 `.header()` 之后调用以覆盖手填的同名 Content-Type（boundary 必须由 reqwest 生成）。文件字段见下一节。
- **后端**：`ApiRequest` 增 `body_file` / `form_data` 并派生 `Default`（Rust 测试改 `..Default::default()`，以后加字段不破坏测试），请求体三选一（`form_data` > `body_file` > `body`）；`reqwest` 启用 `multipart` feature。新增离线测试（binary 文件缺失报错）与 httpbin 端到端 `#[ignore]` 测试（multipart 字段回显 + binary 字节回显）。
- **测试**：新增 `test/body.test.mjs`（35 项：Content-Type 优先级、空体不发、form-urlencoded 编码与禁用行过滤、binary 传路径不传 body、draft ↔ HttpSpec 互转、xml/binary 的 YAML 往返与空值裁剪），已接入 `npm test`。

**请求页 · form-data 文件字段（multipart 上传）** —— 已落地（2026-07-27）：
- **逐行类型，不分表**：form-data 与 form-urlencoded 仍共用同一张 `KVTable` 与同一份 `bodyForm`，只给前者传 `withType` 多一列窄「类型」下拉（文本 / 文件，单元格内嵌样式同断言表操作符列）。一张表里文本行与文件行可混排（同 Postman）。选「文件」后该行**值单元格**换成「选择文件…」按钮 + 路径 + 垃圾桶清除（路径 `direction: rtl` 截前保后，同 binary）；切换类型会清空该行值——文本与路径语义完全不同，留着容易把一段文本当路径发出去。**一行一文件**（不做 Postman 的一行多文件：要引入「值是数组」的模型分叉，而同名多 part 再加一行同名字段即可表达）。
- **模型：复用 KV 行 + `type: file`**：`case.ts` 新增 `FormItem extends KV`（多一个可选 `type: "text" | "file"`），`BodySpec.formData` 由 `KV[]` 改 `FormItem[]`。**文件路径存进 `value`，不另立 `filePath` 子键**——行结构统一，`enabled` 禁用、`description` 备注、flow 的 `${{变量}}` 替换（`resolveKV` 泛型化后保留 `type`）全部天然复用；形态对齐 Postman collection 的 `{key, type:"file", src}`，只是把 `src` 并回 `value`。`type: text` 是默认值，不落盘。
- **filename 与 part 的 Content-Type 在前端算**：载荷 `formData` 元素扩为 `{name, value?, filePath?, fileName?, contentType?}`，`fileName` 取路径 basename（新增 `baseName()`，兼容 `/` 与 `\`）、`contentType` 复用 binary 那份 `guessContentType`。后端因此不必再维护第二份 MIME 表，推断逻辑只有一处。名称为空、禁用、**文件行未选文件**的行一律跳过。
- **后端**：`FormField` 增 `file_path` / `file_name` / `content_type`，有 `file_path` 即走 `Part::bytes(读盘字节).file_name(..).mime_str(..)`，否则仍 `form.text(..)`；读盘仍在后端（不把字节塞进 IPC，同 binary）。错误信息带**字段名 + 路径**（多文件表单里只报路径不好定位是哪行）。新增离线测试 `missing_form_file_is_rejected`，httpbin 端到端用例补文本行 + 文件行混排（校验 `files` 回显与文件内容）。

**应用级偏好统一迁入 settings.json** —— 已落地（2026-07-28）：
- **背景**：主题 / 代理 / 快捷键绑定 / 快捷键开关四项原本各占一个 localStorage 键，而 localStorage **按 origin 分桶**——dev 是 `http://localhost:1420`、打包是 `tauri://localhost`，两边各存一份，「dev 里设好的，打包后读不到」。「最近工作空间」当初正是因此迁到了 `settings.json`，这次把剩下四项一并收口，存储层不再分裂。
- **`settings.ts` 成为唯一持久化出口**：`AppSettings { recentWorkspaces, theme, proxy, shortcuts, shortcutsEnabled }`。`theme.ts`/`proxy.ts`/`shortcuts.ts` 各自的 `loadX`/`saveX` 删除，只保留类型、默认值与 `normalizeX(unknown)` 解析函数——存储的事只有一处知道。
- **首帧缓存解决异步问题**：`settings.json` 走 IPC 是异步的，而主题必须在首帧前定下来（否则深色下先闪一帧亮色）。故写盘时在 localStorage 留一份**整份镜像**（`apicase.settings.cache.v1`），`main.tsx` 同步读它应用主题；挂载后再以磁盘值校正。**权威源始终是文件，缓存删掉不丢设置。**
- **旧键无感迁移**：`settings.json` 缺字段时逐项回落到旧 localStorage 键（含 `"1"`/`"0"` 这种老格式），写盘成功即清除旧键。老用户升级后设置不丢。
- **写回收敛 + 无变化不写**：`settings.json` 是整份覆盖，分散写会互相抹字段，故收敛到单个 effect 整份写回；且**与磁盘内容逐字相同则跳过**——否则 dev 空跑一次就会把默认值固化进文件，反手覆盖掉打包版已有的设置（dev 侧的 localStorage 桶里看不到打包侧的旧键）。
- **`apicase.layout.v1` 未迁**：它在 `sessionStorage` 而非 localStorage，是**刻意的会话级**设计——关闭应用即清空、下次启动回默认（左开、底/右关），不属于跨启动的长期偏好。迁过去等于改变产品行为，故保持原样。
- **测试**：新增 `test/appsettings.test.mjs`（23 项：旧键迁移含老格式、缓存优先级、缓存缺字段时回落旧键、逐字段独立兜底、坏 JSON 不抛错）接入 `npm test`。

**设置 · 证书校验 / 自定义 CA / 请求超时** —— 已落地（2026-07-27）：
- **三项工作空间级请求设置**，加在配置页「通用」分区的「请求」组，随工作空间走（写入 `application.yml` 的 `settings:`，随 git 分享给团队），对**单请求与流程执行同时生效**：①**SSL/TLS 证书验证**（默认开）②**使用自定义 CA 证书**（默认关，从工作空间内的证书文件里选）③**请求超时时间**（毫秒，默认 0 = 不限制）。数据结构与解析/序列化见 [3.YAML格式规范](3.YAML格式规范.md#settings请求设置)，后端装配见 [2.技术架构](2.技术架构.md)。
- **为什么默认严格**：后端 `reqwest` 走 `rustls-tls`，原本始终严格校验，内网自签证书 / 企业 TLS 拦截代理下会直接 `UnknownIssuer` 失败；同时没有超时上限，服务端不响应时请求会一直挂着。三项设置正是为这两类现实问题兜底。
- **两个开关的关系**：彼此独立可组合。**只开自定义 CA 是推荐路径**——只放行你指定的那一个签发者，其余请求仍完整校验；**关校验**是应急手段，全部请求都不再验证身份。两者同开时校验已跳过、CA 不再起作用，故 UI 把 CA 项灰显禁用并说明原因。
- **关校验时给一条常驻警示条**（`.text-warn`）：压到一句，只讲当下决策要用到的两件事——风险是什么（无法确认对端身份）、能用在哪（本机 / 内网调试）。**其余一律不在这里展开**：中间人如何无症状地解密篡改、为何请求照常返回 200、该设置会随 `application.yml` 提交给团队，都属于知识而非状态，待内嵌文档落地后由此挂「了解风险」链接过去（见 2026-07-28「设置页文案从简」）。
- **CA 路径存相对工作空间根**：绝对路径换机器 / 换 clone 目录就失效，相对路径随仓库走，团队成员 clone 下来即可用；运行时在 `App.tsx` 里 join 工作空间还原成绝对路径再传后端。新增后端命令 `list_cert_files` 递归扫工作空间供下拉选择（进「通用」页时重扫，用户常是刚把证书拷进来就回来选）。已配置但当前扫不到的路径仍列在下拉里并提示，不静默丢弃设置。
- **证书文件下拉复用全局 `Select`**（`RequestEditor.tsx`，同请求编辑器的方法 / 认证下拉），不用原生 `<select>`——后者的系统弹层会盖住控件，且与全站观感不一致。为此给 `Select` 补了两项通用能力：`disabled`（工作空间内无证书文件时禁用，底色转 `--panel-2`，与只读输入同一套观感）与 `placeholder`（值为空时显示「未选择」，比正常值淡）。
- **超时输入的 0 显示为空**：`value={timeoutMs || ""}` + placeholder「0（不限制）」——「不填即不限制」比显示一个 0 更自然，且清空输入框正好回到 0，无需额外的草稿状态。

**界面细节 · 滚动条悬停显隐 + 文件树行通栏** —— 已落地（2026-07-27）：
- **滚动条悬停显隐（全局统一）**：滑块默认不可见，鼠标进入所在可滚动区域才出现、移出即消失；文件树、响应区、AI 栏、终端等所有滚动区一致。10px 槽位（`::-webkit-scrollbar` + `-track: transparent`）始终占位，显隐不引起内容宽度跳动。
  - **必须用自定义属性驱动**：WKWebView **不会**为滚动条伪元素重新匹配选择器，`X:hover::-webkit-scrollbar-thumb { background }` 一类写法**完全无效**（已在 Safari 同引擎下实测，JS 切 class 改 background 同样无效）；但它会重新求值伪元素从宿主继承来的自定义属性。故滑块统一取 `background: var(--sb-thumb, transparent)`，由宿主元素的 `:hover` 改该属性驱动重绘。
  - **须阻断继承**：自定义属性会向下继承，只写 `*:hover { --sb-thumb }` 会顺着公共祖先把非 hover 兄弟子树（右侧编辑区、底部终端等）的滚动条一并点亮。解法是先 `*:hover > * { --sb-thumb: transparent }` 复位子代，再由后写的 `*:hover { --sb-thumb: var(--border-strong) }` 覆盖回可见——两条特异性相同、后者胜，只匹配前一条的兄弟子树则保持透明。
  - 滑块自身悬停加深（`::-webkit-scrollbar-thumb:hover` → `--muted`）由 WebKit 原生状态维护，可直接改 `background`，有效。例外：`.tab-bar` 仍以 `::-webkit-scrollbar { display:none }` 完全隐藏横向滚动条。

**Cookie 自动收发与管理** —— 已落地（2026-08-03）：
- **每个请求不再是孤岛**：响应里的 `Set-Cookie` 自动记进 jar，后续请求按 RFC 6265 的域 / 路径匹配自动回带。
  在此之前，基于 session 的服务只能把 cookie 当普通头折腾——从 `res.headers.set-cookie` 提整串再手写回 `Cookie`，
  这既要用户自己做 cookie 解析（`Path` / `HttpOnly` 这些属性一并塞回去已不是 HTTP 语义）、
  多个 `Set-Cookie` 时只取得到一行，**而且跨不了 case**（每个 case 一份独立 `RunContext`，outputs 不共享），
  于是「登录一次、后面十个用例复用会话」这个最常见的回归形态无法表达。
- **jar 跟着工作空间走**（`<workspace>/.apicase/cookies.json`）：一个工作空间＝一个项目，
  两个项目都打 `localhost:8080` 时不会互相覆盖会话。不选应用全局一份，也不选纯内存
  （登录态每次重启都要重跑一遍，正是 jar 要消灭的麻烦）。会话 cookie 也持久化——
  apicase 的使用形态是「昨天登录过、今天接着调」，这里对齐 Postman 而不是对齐浏览器。
- **开关是工作空间设置 `settings.cookies`（默认开）**：与 `verifySsl` 同层，随 git 传给团队，回归行为一致。
  关闭时不带也不收，但**已存的 jar 原样保留**——关开关是"这轮不要自动带"，不是"删掉我的会话"。
- **收 `Set-Cookie` 交给 reqwest 的 provider，`Cookie` 头自己写进请求**：前者是因为
  `POST /login → 302 + Set-Cookie → GET /home` 中间那一跳我们根本看不到（reqwest 内部就跟完了）；
  后者是因为报告记的是这一份请求，补在这里才看得见本次带了什么会话。
  **用户手写的 `Cookie` 头优先**，jar 不插手。
- **管理界面**（设置页新增「Cookies」分区，属项目组，版式对齐 Bruno 的实现）：顶部工具条（搜索 / 添加 / 清空全部）
  → **按域折叠**的分组（域名 + 条数 + 该域的 ＋ / 清空，默认只展开第一组）→ 展开是**明细表**
  （名称 / 值 / 路径 / 过期 / Secure / HttpOnly / 子域 / 操作，勾选类用 ✓ 居中）。
  **增删改一律图标按钮**（铅笔 / 垃圾桶 / ＋，常态低调、hover 才浮出）——密集列表里文字按钮每行都要占掉一截宽度。
  搜索同时匹配域 / 名 / 值（Bruno 只搜域名）。空态与「搜不到」各有一套图标 + 文案 + 下一步动作。
  值不掩码（同报告的既有决策）。
  **增改的校验只在 Rust**：拼一行 `Set-Cookie` 交给解析器，与服务端下发的走同一套判定，
  前端只把错误原样显示在对话框里、不关窗。为写 `Expires=` 给 `util` 补了 `http_date`（自算历法，不引时区库）。
  **顶栏加了饼干图标直达该分区**（清一次登录态是调试里的高频动作，埋在配置 → 左导航第三项之后太深）；
  为此把设置页的当前分区提升到 `App` 持有——组件内部 state 随标签切走即卸载，既跳不进去、回来也回不到原处。
- **顺带修掉一个既有缺陷**：`dump_application_config` 清理旧键时漏了 `continueOnAssertionFailure`，
  把它从 `true` 改回 `false` 时旧值会残留在文件里（默认值不落盘 ⇒ 没有键去覆盖它），
  表现为「界面上关掉了、重开又变回来」。受管键收成一份常量数组，新加的 `cookies` 会踩同一个坑。
- **测试**：core 新增 10 项（域隔离 / 多 cookie 合成一头 / 持久化往返 / 坏文件回落 / 列删清 /
  手写头优先 / 开关关闭 / jar 共享，含两项**真发请求**的端到端——服务端下发的 cookie 要在下一个请求上原样带回去）；
  YAML 补解析容错、默认值不落盘与"改回默认要清旧键"三项；前端补 `test/cookies.test.mjs`。
  另用临时工作空间跑通无界面链路（登录 → 带会话访问 → 换进程仍带 → 关开关即不带）。

**报告的多格式视图与复制** —— 已落地（2026-08-03）：
- **整份报告三个视图：可视化 / JSON / YAML**（顶部最左），后两者配「复制全部」——
  一次性看到、也一次性拿走整份结果（贴 issue、存档、喂给别的工具）。切到源码视图时筛选与搜索一并隐藏。
  文本**只在切过去时才生成**：几百个用例的报告序列化出来是几 MB，每次进度更新都算一遍会把页面拖死。
- 每段请求 / 响应报文体上方另有一条工具条：**JSON ／ YAML ／ 原文** 切换 + **复制**（只要这一段响应时用）。
  报文体是报告里最常被拿去别处用的东西——贴进 issue、喂给下一个请求、和同事对字段，
  而此前只能手选一段深色代码块里的文本。
- **只有能解析成 JSON 的才给格式切换**，纯文本 / HTML 只留复制：点了「YAML」却什么都不变最让人困惑。
- 复制的是**当前显示的那一份**；`file://` 下 `navigator.clipboard` 常被拒，故留了
  `textarea + execCommand` 的老路；按钮自己变「已复制」而不弹 toast（报告可能嵌在 iframe 里，浮层会被裁掉）。
- YAML 只用于展示与复制、不参与解析回读，规则比 core 的 emitter 简单，但该加的引号必须加
  （`'200'`、`'true'`、含 `: ` 的值），否则复制出去粘到别处就变了意思；**键位置更宽松**（同 emitter）。
- 这段格式化代码抽成带 `#region` 标记的独立 IIFE，前端测试按标记截取求值（31 项）——
  报告页跑在浏览器里、没有模块系统，不这样就只能靠肉眼看。顺带修掉一个隐患：
  筛选段控件原按 `.seg button` 选，与新加的格式按钮串了台。

**命令行与 MCP** —— 已落地（2026-08-03）：
- **`apicase` CLI**（workspace 第三个成员 `cli/`，与桌面壳平行依赖同一个 `apicase-core`）：
  `run` / `ls` / `check` / `show` / `env` / `cookie` / `report` / `new` / `init` / `docs` / `mcp` / `completion`。
  用例是 YAML 文本、直接用编辑器改即可，故 CLI 不做编辑命令。
- **两个各自独立的二进制**：`apicase`（命令行与 MCP）与 `apicase-desktop`（图形界面），
  **互不引用**，唯一交集是共同依赖 `apicase-core`，各自 `cargo build` 出各自的可执行文件。
  不合成一个按 argv 分流，是因为桌面端在 Linux 上动态链接 webkit2gtk，
  编在一起的话没装桌面环境的机器上**动态链接器在 `main` 之前就会失败**——
  `apicase run` 连一行代码都执行不到。
- **让 AI 用起来**（2026-08-04）：`apicase init` 现在做三件事——写 `application.yml`
  声明边界、把命令行工具接进 PATH、生成 `AGENTS.md`（全部幂等）。
  界面对应「设置 → AI」分区，含一个**默认关**的「打开工作空间时自动补齐」开关。
  `AGENTS.md` 是 Linux Foundation 的开放标准，三十多个 Agent 原生读，**零配置**且随 git 走——
  比 MCP（每个客户端配一次）低摩擦得多，故为主路径，MCP 降为受管控环境的备选。
  内容刻意做得短：**指路不复制**，只告诉 AI 敲 `apicase docs` / `check` / `run --json`，
  不把 YAML 规范抄进去（省 token，也不制造第二个真相）。
  软链优先 `~/.local/bin` 而非 `/usr/local/bin`——不需要提权，且全局软链指向用户级
  安装时会指错人。
- **无 `application.yml` 也能跑**（2026-08-04）：`apicase run /tmp/试一下.yml` 直接可用。
  未锚定时不落报告、不建 jar、不碰 `.gitignore`（不在别人的目录里留痕），
  且不许省略目标（否则在 `~` 下敲会递归扫全盘、把真实写请求打出去）。
- **CLI 不提供唤起界面的命令**（曾有过 `apicase gui`，2026-08-04 移除）：
  跨进程唤起要维护「找可执行文件、判断显示服务、分类各种失败」一整套猜测逻辑，
  换来的只是省掉用户点一下图标。桌面端自己认启动参数（`apicase-desktop <工作空间>`），
  「把目录拖到应用图标上」也走这条。
- **`apicase mcp`** 以 MCP 服务器（stdio）运行，七个工具：`apicase_run` / `check` / `list` / `show` /
  `env` / `report` / `docs`。AI 的闭环是 **查格式 → 用自己的文件工具写 YAML → check 自检 → run 验证 → 读失败现场改**；
  写文件不做成工具（AI 自带的够用，再包一层只会多一道权限与语义的错位）。
- **两端共用同一份配置**：工作空间级的 `application.yml`（随 git）之外，
  应用级的**代理设置**（`settings.json`）此前只有界面读得到，CLI 只认环境变量——
  于是「界面里设了直连、CLI 照样走系统代理」。现已统一：CLI 环境变量优先、回落界面设置；
  配置目录的推导下沉进 core 且只有一份（有测试比对 Tauri 的结果），读不到一律回落默认，
  只用一边的人不会被另一边绊倒。
- **CLI 与 MCP 共用一层 `ops`**（与呈现、协议都无关，且**不 print**——
  MCP 的 stdout 只能有协议消息）：两处外壳，一套操作语义，参数名一一对应。
- **退出码分四档**：`0` 通过 / `1` 断言失败（被测服务的问题）/ `2` 用法错误 / `3` 执行错误。
  `1` 与 `3` 分开，是因为 `failed ≠ error` 本就是执行内核的核心理念，
  退出码不体现它等于在 CI 那一层把最有用的信息丢掉。
- **输出格式跟着 TTY 走**：终端里给文本，管道里给 JSON（就是 `RunReport`，与报告页内联的那份同一套 schema），
  且默认是**摘要**——一份 500 用例的完整报告有几 MB，灌进 AI 上下文或管道给 `jq` 都不该是默认值。
- 顺带把「工作空间定位 / 用例发现 / 报告命名与周期写盘」**下沉进 core**（此前散在示例代码、前端与命令层里），
  并退休了 `core/examples/run_workspace.rs`——它的使命「验证 CLI 可行」已经完成。

## 技术栈一览

| 层 | 选型 |
|---|---|
| 桌面框架 | Tauri 2（Cargo workspace：`core/` + `src-tauri/` + `cli/`） |
| **执行内核** | **`apicase-core`**（零 GUI 依赖）：`reqwest`+rustls、`cookie_store`、`tokio`、`serde_yaml`、`base64`、`md5`、`regex` |
| 桌面壳 | Rust：`notify`（fs 监听）、`portable-pty`（终端）、`tauri-plugin-dialog/opener` |
| **命令行 / MCP** | **`apicase-cli`**（零 GUI 依赖）：`clap`、`clap_complete`、`chrono`、`rmcp`（官方 MCP SDK） |
| 前端 | React 19 + TypeScript + Vite 7（**只做配置与展示**，无 YAML / HTTP 依赖） |
| 存储格式 | YAML（case / 配置文件；格式参考 Postman/HAR/Arazzo 等） |

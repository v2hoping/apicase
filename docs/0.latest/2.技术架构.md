# 技术架构

> 描述 apicase 的实现架构现状（v0.1）。

## 技术栈

- **桌面框架**：Tauri 2.x（Rust + 系统 WebView）。
- **执行内核**：`apicase-core`（独立 crate，**零 Tauri / 零 GUI 依赖**）；`reqwest`（rustls TLS，避免本地 OpenSSL）；`cookie_store`（RFC 6265 的 cookie jar，与 reqwest 内部同版本）；`tokio`（异步与并发调度）；`serde` / `serde_json`（`preserve_order`）/ `serde_yaml`；`base64`；`md5`；`regex`。
- **命令行 / MCP**：`apicase-cli`（同样**零 GUI 依赖**）；`clap` 4 derive + `clap_complete`；`chrono`（只用于取本地时区偏移）；`rmcp`（MCP 官方 Rust SDK）。
- **桌面壳**：`tauri-plugin-dialog`（目录选择）；`notify`（fs 监听）；`portable-pty`（伪终端）。
- **前端**：React 19 + TypeScript + Vite 7；`@tauri-apps/plugin-dialog`；`@xterm/xterm` + `@xterm/addon-fit`（底部终端）。**不再有 YAML / HTTP / 执行相关依赖**。
- **前后端通信**：Tauri command + `invoke`；批量运行的进度走 Tauri event。
- **权限**（`capabilities/default.json`）：`core:default`、`opener:default`、`dialog:default`、`core:window:allow-start-dragging`（自定义标题栏拖动窗口需显式授权）。

## 目录结构（`app/`）

Cargo workspace 三个成员：执行内核、桌面壳、命令行。**后两者平行、互不依赖**——
CLI 因此不会把整个 WebView 框架拖进编译，也才能在没装桌面环境的机器上跑起来。

## 执行内核 `apicase-core`

**一句话职责：从 case 文件到运行报告的全部语义都在这里。** 桌面壳与将来的 `apicase run` CLI
只做三件事——给输入、注入 IO、把产物交给用户。二者不共享任何执行语义，因此不会出现
「界面里跑过了、CLI 跑却挂了」这类两套实现必然产生的漂移。

```
case.yml → yaml → vars → request → auth → http → jsonpath → assert → RunReport → report.html
```

**边界是硬的**：`core/Cargo.toml` 里没有 `tauri`。这条线一旦破掉（比如为了发个进度事件
而 `use tauri::Emitter`），CLI 就得把整个 GUI 框架拖进来编译。故进度上报走**回调注入**
（`ProgressFn`），桌面壳在回调里转成 Tauri 事件，CLI 在回调里打印一行。

### YAML：解析容错、输出规范

- **解析一律容错**：除「YAML 本身语法错」外，认不出的 `op` 回落 `eq`、认不出的 `auth.type` 回落 `none`、
  `settings` 解析失败回落全默认。配置文件是手写的，一处写错不该让整个功能瘫掉。
- **序列化自己写**（`yaml/emit.rs`），不用通用库。落盘的 case 是用户要读、要 diff、要 review 的源文件，
  格式不是实现细节。

  **引号按字段的语义类型加**，一条规则：值位置的字符串，裸写后若不被读成字符串就加引号。

  | 字段 | 写法 | 例 |
  |---|---|---|
  | 会发到网络上的字符串（`query`/`headers`/表单的 `value`、`url`、`id`…） | 数字 / 布尔形态**加引号** | `value: '2'`、`name: '1'` |
  | 数字 / 布尔（`timeout` / `x` / `y` / `enabled`） | 裸写 | `timeout: 500000`、`x: 502` |
  | 断言的期望值（`assertions[].value`） | **裸写** | `value: 200`、`value: ok` |
  | 自由类型（`vars` / `body.json`） | 引号在这里**有语义** | `retries: 3` vs `label: '3'` |

  HTTP 报文里没有数字类型——query / header 的值语义上恒是字符串，`value: 2` 裸写虽也读得回 `"2"`，
  但读的人无从判断类型（Postman 的 JSON collection 里同样是 `"2"`）。而 `timeout` 在模型里
  真的是 `u64`，写成 `'500000'` 反而误导。

  **`assertions[].value` 走宽松规则**（`LOOSE_SUBTREE_KEYS`）：它是期望值、不进报文，
  类型跟着 `target` 走；且它在模型里恒是 `String`、比较本就宽松（先文本再数字，
  见 `assert::loose_eq`），引号对结果毫无影响，强加只是噪声。
  保持 `String` 而不改用 `serde_json::Value`，是因为可视化断言编辑器的输入框产出字符串——
  改用 `Value` 会平添"输入框里的 `200` 是数字还是字符串"这个新歧义，而收益（类型信息）
  在宽松比较下用不上。真要做严格类型断言时再改不迟。

  **key 位置更宽松**（key 恒按字符串取用，无类型歧义）：读得回原值就裸写，画布坐标的 `y: -70`
  正是靠这条——YAML 1.1 把 `y` 当布尔别名，1.2 不会，我们按 1.2。

  判定用**真实解析器**验证而不是手写判定表：「什么算数字」的边界（`1_000` 是字符串、`007` 是字符串、
  `.inf` 是数字）只有解析器自己说了算。故 `yes` / `2026-07-30` / `12:30` 这些本就是字符串的值不带引号。

  **单引号优先**，只在单引号表达不了时（含控制字符）升级双引号——要加引号的值里常含反斜杠
  （断言的 `matches` 正则、Windows 路径），双引号会逼着把 `\d` 写成 `\\d`。

  多行文本走块标量 `|` / `|-`；画布坐标整数值写成整数（不留 `502.0`）。
  有**黄金测试**用仓库里真实的 case 逐字比对输出。
- **变量语法只认 `${{var}}`**（`core/src/vars.rs`）：`{` 是 YAML 的流式映射指示符，
  以 `{{` 开头的值必须整行加引号（`url: '{{baseUrl}}/get'`；`url: {{host}}` 更会被**静默**
  读成嵌套映射、URL 直接没了），而 `$` 不在指示符表里——`url: ${{baseUrl}}/get` 可以裸写。
  GitHub Actions 用 `${{ }}` 多半同理；Ansible 用 `{{ }}`，其官方文档就明确要求加引号。
  **不留无 `$` 的旧写法**：同一件事两种写法、而其中一种会把用户逼回加引号。
- **case schema 版本是 `apicase: v0.1`**（常量 `CASE_VERSION`）：带 `v` 前缀故不是数字形态，
  落盘不必加引号，也不会在 `0.10` 时被读成 `0.1`。
- **解析侧宽进**：schema 说是字符串的字段一律走 `s()`，用户裸写 `value: 2` / `name: 123` /
  `apicase: 0.1` 都读成字符串，而不是被当成"类型不对"悄悄丢掉。**宽进严出**——
  保存时规范化成带引号，把"这是字符串"在文件里写明白。

### HTTP：客户端池是本层最大的性能收益

按「代理 + 证书校验 + CA + 超时」这组配置缓存 `reqwest::Client`：

- 改造前每请求 `Client::builder().build()` 一次 —— TLS 根证书库重建、**连接池随客户端一起丢弃**。
  批量跑 100 个打同一服务的用例，就是 100 次 TCP + 100 次 TLS 握手。
- 现在配置不变就复用同一个客户端，keep-alive 连接因此真正活得下来。**有测试钉住：5 个请求 1 条连接。**
- CA 文件的 **mtime 与长度**参与缓存键：换了证书文件客户端自动重建，不必重启。
- **锁中毒不让池子报废**：别处 panic 毒化了锁后，照直 `unwrap` 会让此后每个请求都以
  「缓存已损坏」告终；池里只是可重建的客户端，直接取回内部数据继续用。
- 响应体**分块累加**并守住 64MB 上限（`text()` 一次性全读会先吃光内存才轮到判断），
  超限**明确报错**而非静默截断。
- `verifySsl == false` → `danger_accept_invalid_certs`；`caCertPath` → 追加到默认信任库
  （PEM bundle 与 DER 都支持，DER 先自行校验 ASN.1 首字节，免得错误延后成一句无指向的「创建客户端失败」）；
  `timeout > 0`（毫秒）→ 覆盖「连接 + 发送 + 读完响应体」全过程。

### Cookie：jar 装进 reqwest，头自己写进报告

`cookie.rs` 的 jar（`cookie_store` 的 store + 落盘节流）同时充当 `reqwest::cookie::CookieStore`，
按「开关 + jar 路径」参与客户端缓存键——provider 是 builder 级设置，不进键就会出现
「关了开关仍在带 cookie」这类跟着缓存走的幽灵行为。

- **收 `Set-Cookie` 交给 reqwest 而不是自己在响应回来后解析**：`POST /login → 302 + Set-Cookie → GET /home`
  中间那一跳的响应我们根本看不到（reqwest 内部就跟完了），而重定向后那一跳又要带上刚拿到的 cookie。
  装 provider 后这两件事都在链路内部完成。
- **发送前仍自己算一次 `Cookie` 头写进请求**（`cookie::attach`，在 `send_with_auth` 里）：
  报告记的是这一份请求，补在这里才看得见本次带了什么会话。reqwest 只在请求没有该头时才由 jar 补，
  两条路径不会打架。**用户手写的 `Cookie` 头优先**，jar 不插手；Digest 重发前刷新（401 常同时下发新会话）。
- **jar 按落盘路径在进程内共享一份**（`HashMap<路径, Arc<CookieJar>>`）：同一路径两份 store
  就是谁后写盘谁把对方的会话抹掉。桌面端与 CLI 用的是同一个文件，会话因此互通。
- **落盘节流 ≥1s + 写临时文件再 rename**：批量跑 200 个用例不该产生 200 次写盘；
  半截文件会让整份会话在下次加载时丢失。`flush_all()` 在批量运行收尾与每次调试发送后强制写一次。
- 读不回来的 jar 文件（损坏 / 权限）**回落空 jar 而不是报错**——最坏结果只是重新登录一次，
  不该让请求发不出去。

#### 落盘格式是 YAML，且是给人和 AI 编辑的（2026-08-05）

`.apicase/cookies.yml`：域名分组 → `name` / `value` / `path` / `secure` / `expires`
（格式见 [3.YAML格式规范](3.YAML格式规范.md#cookiesymlcookie-会话)）。此前存 `cookie_store` 的内部
表示（`raw_cookie` 里塞着整串 `Set-Cookie`），那是库的私有格式——人读着费劲、AI 更不敢动。

- **因此不再有 `apicase cookie` 子命令**：文件本身就是接口，再包一套命令等于给同一份数据开第二条
  路径，两条路径必然漂移。`AGENTS.md` 与 `apicase docs cookies` 负责把 AI 指过去。
- **宽进严出**：读的时候容错（省略字段、值写成数字、字符串布尔、扁平列表），**一条写坏只丢那一条**
  ——否则就是「AI 改错一行，登录态全没了」；写回去一律规范化、默认值不落盘。
- **写入仍走 `cookie_store`**：手写的那些拼成一行 `Set-Cookie` 交给它解析（`insert_into`，
  与管理界面的 `put` 同一条路径），域匹配与合法性判定不另写一套。
- **旧的 `cookies.json` 自动迁移**：yml 不存在时读它，落盘时写成 yml 并把它删掉（不留第二个真相）。
  过期时间的编解码在 `util::iso8601_secs` / `parse_iso8601`（自算历法，core 仍不引时区库）。
- **没有 `httpOnly`（2026-08-07 去掉）**：它约束的是浏览器里 `document.cookie` 的读取，apicase 没有
  那个上下文；`cookie_store` 的匹配也只在非 http(s) 协议下才据它拦截（`Cookie::matches` 里的
  `is_http_scheme`），而我们发的只有 http/https——对收发毫无影响。一个「勾了没反应」的开关摆在真
  起作用的 `Secure` 旁边，比缺个字段更误导。字段、编辑弹窗的复选框、明细表的列一并去掉；
  旧文件里写着它只是被忽略（不整条丢弃），服务端下发的 `HttpOnly` 照收，只是不再记录与展示。

### 执行引擎：三级 + 三条不变量

`run_step` / `run_case` / `run_batch`。**调试运行与回归运行是同一份实现**，只差报文体截断这一个开关。

- **变量隔离**：每个 case 一份独立 `RunContext`（environment + 该 case 的 `vars`），
  **case 之间不共享 outputs**——否则一开并发就是竞态。
- **`failed` ≠ `error`**：前者请求发出去了但断言没过（被测服务的问题），后者请求本身失败
  （网络 / TLS / 超时，常是环境或用例的问题）。两者排查方向完全不同。
- **取消在 case / step 边界生效**，已发出的 HTTP 不中断——半截请求对被测服务是一种伤害。

### 失败传播：上游挂了，下游跳过

case 的模型是 DAG，执行语义就该是 DAG 的：**某个 step 挂了，依赖它的下游标记 `skipped` 而不执行**
（对齐 TestNG `dependsOnMethods`、pytest-dependency、GitHub Actions `needs`、Airflow）。
不这么做会有两种坏结果：下游拿着未解析的 `${{...}}` 字面量发出**真实写请求**（我们发的是 HTTP，
不是幂等计算），以及报告里一串被连累的失败淹没唯一的根因。

| 上游状态 | 是否阻断下游 |
|---|---|
| `error` | **恒阻断**，不可配 —— outputs 必然为空，跑下去 100% 是噪音 |
| `failed` | 阻断；`continueOnAssertionFailure` 打开时不阻断 |
| `skipped` | 阻断（传递性：没跑的节点没有产出） |

- **按依赖闭包传播，不按线性顺序**——独立分支不受另一条分支连累，这正是 DAG 比列表值钱的地方。
- `skipReason` 指向**根因**而非直接上游（隔三层也写「上游 login 失败」），否则一条长链上
  得到的是一串「上游 B 失败」「上游 C 失败」，而要找的始终是最上面那个。
- **skipped 不参与 case 状态汇总**：case 的状态该指向根因那一步，不被后面一串跳过稀释。
- 三个开关正交：**跳过传播**（默认行为，非开关）、**`continueOnAssertionFailure`**（断言失败算不算
  阻断性失败）、**`stopOnFailure`**（整轮立刻停）。后者管"要不要继续跑后面的 case"，前者管"case 内部谁该跑"。

**判定只有一份**：调试运行的循环在前端（每跑完一步要刷新界面），它只回报每步的状态，
"算不算阻断源"与"连累到谁"都由 core 的 `blocked_from_outcomes` 算——同 `topo_order` 的处理。
`run_case` 内部的流式传播与它是同一规则的两份代码，有**交叉验证单测**钉住两者结果一致。

**并发**：`concurrency > 1` 时 case 之间用 `tokio::Semaphore` 限流，case 内部的 step 仍按拓扑序串行。
**默认仍是 1**；串行路径独立成一支（不走 spawn 与信号量），顺序精确、`stopOnFailure` 语义干净。
并发安全的前提是 OAuth 2.0 token 缓存做了 **in-flight 去重**：每个缓存键一把异步锁，
同键并发只有第一个真去换 token——没有它，8 个并发就是 8 次 token 交换。

并发路径下结果按**完成序**追加（跑完一个冒一个），而不是提交序——进度因此真的像实时流。
`join_next()` 里串行 `push` + `emit`，故「一次回调只新增一个 case」这条不变量在并发下仍成立，
桌面端取 `cases[n-1]` 的增量事件不受影响。

值来自 `application.yml` 的 `settings.concurrency`，由 `Workspace::run_opts()` 统一装配，
桌面端 / CLI / MCP 三端同源（`-j` 与 MCP 的 `concurrency` 参数是这一次的临时覆盖）。
取值恒被 clamp 进 `1..=MAX_CONCURRENCY`（64）——**`0` 会让信号量容量为 0，
表现是整轮运行永远拿不到令牌而挂起**，故解析期、装配期、落盘前各兜一道。

### 报告存真实值：脱敏已整体移除

报告里的请求头、响应体、`outputs`、断言的实际值**一律是原文，不掩码**。
早先有一套五规则的脱敏（`redact.rs`，2026-08-03 整体删除），移除的理由是它与报告的用途相冲：
报告是排查材料，而被掩掉的恰恰是排查时要逐处核对的东西——
`Authorization` 到底带没带对、上游提取出的 token 是不是空、断言的 `actual` 究竟取到了什么。
更麻烦的是它会**掩掉与凭据无关的内容**：一个未解析的 `${{steps.login.outputs.token}}`
出现在 `Authorization` 头里时会被掩成 `Bearer ${{s***`，本该一眼看出的变量没替换反而被藏了起来。

**代价要认**：报告含明文凭据。`.apicase/reports/` 已在 `.gitignore` 里，
但**转发报告、把它塞进 CI 制品之前需要自行判断**。

报文体截断保留（`BodyRecord::clip`，与凭据无关）：默认 64KB，`bytes` 记原始大小，
切点落在字符边界。单文件 HTML 会把报文体全内联，几十个大 JSON 就能把报告顶到打不开。
调试运行不截断（`for_debug` 用 `usize::MAX`）——响应区要看的就是完整内容。

### 报告：只有一套渲染实现（硬约束）

`report_shell()`（空壳 = CSS + 渲染 JS）供 apicase 内嵌 iframe，`render_html()`（空壳 + 内联数据）
供落盘与 CLI，**共用同一份资源**（`render/report.css|body.html|js`，`include_str!` 编译进二进制）
→ 应用内 / 历史回看 / 发给同事三处像素级一致。有单测断言「除数据块外逐字相同」。
迁移时与原 TS 实现做过**逐字比对**，历史报告与新报告无任何视觉差异。

- **单文件自包含**：数据内联在 `<script id="apicase-report" type="application/json">`，不另存 `report.json`。
  **不做 ndjson + 轮询**——`file://` 下 fetch 同目录文件会被 CORS 拦掉（Playwright 正是栽在这）。
- 内联 JSON 转义 `</` → `<\/`（响应体里的 `</script>` 会提前闭合标签）与 U+2028/2029。
- `parse_report_html` 是反向读回：找 `<script id="apicase-report">` 里的 JSON、能反序列化成 `RunReport`、且 `schemaVersion` **不高于**当前版本，四关缺一即视为普通 HTML（**只认自己生成的报告**）。往返等价有单测护栏。
  版本判定是 `<=` 而非 `==`：**老报告要一直打得开**（v1 里只是没有 `skipped` 而已），
  而更新的报告可能带本渲染器不认识的状态，宁可降级为纯文本也好过静默渲染错。
  当前 `REPORT_SCHEMA_VERSION = 2`——**这一版是为 `StepStatus::skipped` 涨的**：
  加字段对旧解析器向后兼容，新增枚举值不兼容（旧报告页不知道该给它什么颜色、算不算进统计）。
- **整份报告有三个视图：可视化 / JSON / YAML**（顶部工具条最左），后两者是「把这份结果整个拿走」的出口——
  贴进 issue、存档、喂给别的工具。切到源码视图时筛选与搜索一并隐藏（它们只对列表有意义），
  右侧换成「复制全部」。
  - **只在切过去时才生成文本**：一份几百个用例的报告序列化出来是几 MB，每次进度更新都算一遍会把页面拖死；
    运行中停在源码视图上则随数据更新重出（少见但不能是死的）。
  - 源码块占一屏高、内部滚动。不设上限会让页面变成几千行的长条，「复制全部」滚没了反而更难用。
  - 有个 CSS 坑：`.cases { display: flex }` 的特异性高过 `[hidden]` 自带的 `display: none`，
    只设 `hidden` 属性列表照样显示，得补一条 `.cases[hidden] { display: none }`。
- **单段报文体也可切 JSON / YAML / 原文，并一键复制**（`report.js` 的 `ApicaseFmt`）。
  与上面那层互补：那个是「整份拿走」，这个是「只要这一段响应」。
  报文体是报告里最常被拿去别处用的东西——贴进 issue、喂给下一个请求、和同事对字段。
  - **只有能解析成 JSON 的才给格式切换**，纯文本 / HTML 只留「复制」：点了「YAML」却什么都不变最让人困惑。
  - 原文存在 `<pre data-raw>` 上，每次切换都从原文重算，不受上一次显示的是哪一种影响。
  - **复制的是当前显示的那一份**（切到 YAML 就是为了把 YAML 贴出去）；`file://` 下
    `navigator.clipboard` 常被拒，故留了 `textarea + execCommand` 这条老路。按钮自己变「已复制」，
    不弹 toast——报告可能嵌在 iframe 里，浮层会被裁掉。
  - YAML 只用于**展示与复制**、不参与解析回读，故规则比 core 的 emitter 简单；但该加的引号必须加
    （`'200'`、`'true'`、含 `: ` 的值），否则复制出去粘到别处就变了意思。**键位置更宽松**（键恒按字符串取用，
    无类型歧义），一份响应里键名成百上千，多出来的引号全是噪声。多行文本走块标量 `|` / `|-`。
  - 这段代码抽成 `// #region fmt` 标记的独立 IIFE，前端测试按标记截取求值（`test/reportfmt.test.mjs`，31 项）——
    报告页跑在浏览器里、没有模块系统，不这样就只能靠肉眼看。
  - 顺带修了个既有隐患：筛选段控件原先按 `.seg button` 选，而格式切换也是一组 `.seg` 按钮，
    点一次筛选会把所有格式按钮的选中态清掉。改按 `data-filter` 匹配。
- **普通 HTML 也能可视化预览**（`HtmlPreview.tsx`），但按"只看不跑"处理：`sandbox=""` 不给任何能力，再注入 CSP `default-src 'none'` 挡住无需脚本的外部资源请求。两种模式都**不给 `allow-same-origin`**——给了就等于把 iframe 放进同源，sandbox 形同虚设。用户可显式授权运行脚本。

## 桌面壳：Tauri 命令层

`src-tauri` **不含任何执行语义**，只有桌面应用才需要的能力。`commands/exec.rs` 是纯转发：
把 JSON 变成 core 的类型、把产物变回 JSON、把进度转成事件。

### 执行相关（全部转发 core）

- `analyze_case(text)` / `dump_case(case)`：case 文本 ↔ 模型。
- `parse_app_config(text) -> { environment, settings, active }`：一次读全 `application.yml` 的几块配置
  （分成多个命令等于多次 IPC + 多次 YAML 解析）；`dump_app_config(baseText, environment, settings)` 写回并保留未知顶层键。
- `set_active_env(baseText, name)`：只改顶层 `active`（当前生效的环境）。**单独一个命令**而不并进
  `dump_app_config`：后者走「解析 → 重新 emit」会抹掉注释，而切环境是顶栏一点就写盘的高频动作，
  这条路是文本级替换，注释与排版原样保留。传空名字 = 删掉该键。
- `run_step(step, vars, steps, opts)`：界面上的「发送 / ▶ 运行」。上下文由前端传入——
  它是「当前这个标签页的运行态」，生命周期跟着 UI 走，放后端反而要同步两份状态。
- `topo_order(steps)`：按 `dependsOn` 排序（返回下标）。循环留在前端是为了逐步刷新界面，
  但**排序规则只有 core 一份**（成环兜底等边界不该两处各写一遍）。
- `run_batch(args) -> RunReport`：批量运行，跑完返回最终报告；`report_file` 给了就由后端周期落盘。
- `cancel_run(runId)`：取消（托管状态 `RunState = Mutex<HashMap<runId, Cancel>>`）。
- `report_shell()` / `parse_report(text)`：报告空壳与反向读回。
- `list_cookies(jarPath)` / `save_cookie(jarPath, prev?, cookie)` / `delete_cookie(jarPath, domain, path, name)` /
  `clear_cookies(jarPath, domain?)`：cookie jar 的读 / 增改 / 删 / 清（设置页「Cookies」用）。
  jar 路径由前端给——core 不猜工作空间在哪。`domain + path + name` 是 cookie 的主键，
  只按 name 删会误伤同名不同域的那条；`save_cookie` 的 `prev` 是改动前的主键，
  改了域 / 路径 / 名不删旧的就会留下一条孤儿。

**进度事件 `run://progress/{runId}` 按增量推**：一份跑了 200 个用例的报告可达数 MB，
每完成一个就整份序列化过一次 IPC 会把界面拖卡。三种事件：`start`（报告头，`cases` 为空）
→ `case`（逐个追加）→ `end`（收尾）。
> 序列化上有个坑：`#[serde(rename_all)]` 在 enum 上**只管 variant 名**，字段名要 `rename_all_fields`。
> 少了后者前端读 `durationMs` 就是 `undefined`，表现为「进度条一动不动」且无任何报错。已由测试钉住。

**周期写盘**在后端做（`ReportWriter`）：每 ≥1s 整份覆写一次，持锁写盘天然串行，不会写出半截文件。

### 桌面专属

- **应用设置**（存 `~/.apicase/settings.json`，**三平台同一个位置**，跨 dev / 打包一致）：
  `read_app_settings()` / `write_app_settings(content)` / `app_paths()`。当前存全部应用级偏好：
  最近打开的工作空间、主题、代理、快捷键绑定与总开关、文件树是否显示隐藏项。
- `init_workspace(path)`：目录初始化为工作空间（无 `application.yml` 则写初始模板；幂等）。
- `list_cert_files(root)`：递归列出工作空间内的证书文件（`.pem/.crt/.cer/.der/.ca-bundle`），
  返回**相对工作空间根**且统一用 `/` 分隔的路径（配置要跨平台共享）。
- `system_info()`：「关于」页的 OS / 架构 / 芯片。
- **文件与目录**：`list_dir(path, showHidden?)`（目录在前、组内忽略大小写排序；`.git`/`node_modules`/
  `target`/`dist` **恒不列**——「显示隐藏文件」不等于「显示一切」）、`read_text_file` / `write_text_file` /
  `read_file_smart`（NUL 嗅探 + UTF-8 校验）/ `create_file` / `create_dir` / `rename_path` /
  `copy_path`（拒绝覆盖、拒绝复制进自身子目录）/ `delete_path` / `search_workspace` / `path_exists`。
- **文件系统监听**：`watch_workspace(path)` 递归监听，事件经 **250ms 去抖**、过滤噪声后以
  `workspace:fs-change` 发往前端；再次调用替换旧监听。**噪声只按目录名挡**（`.git` 与
  `node_modules`/`target`/`dist` 这类高频且与用例无关的），**不按"隐藏项"一刀切**——
  文件树的「显示隐藏文件」开着时 `.apicase/`、`.env` 都是可见的，滤掉它们的变更就会让
  用户删掉一份报告后还看着它。前端只刷新**已加载**的目录，没展开过的隐藏目录本就不会空转。
- **伪终端**：`terminal_open/write/resize/close`，输出以 `terminal://data/{id}` 事件（原始字节）流回前端。

## 命令行与 MCP：`apicase-cli`

**与桌面壳平行的第二层外壳**，同样只做三件事：给输入、注入 IO、把产物交给用户。
执行语义一行不写——它和界面跑的是同一个 `apicase-core`，因此不存在
「界面里跑过了、CLI 跑却挂了」（Newman 相对 Postman 正是栽在这，两套实现）。

### 两个二进制，各自独立

| 产物 | 包名 | 目录 | 用途 | 依赖 |
|---|---|---|---|---|
| `apicase` | `apicase-cli` | `cli/` | 命令行与 MCP | `apicase-core` |
| `apicase-desktop` | `apicase-desktop` | `src-tauri/` | 图形界面 | `apicase-core` + Tauri |

**两者互不引用**，唯一的交集是共同依赖 `apicase-core`。各自 `cargo build` 出各自的可执行文件，
可以单独分发、单独安装、单独升级。

为什么不合成一个二进制按 argv 分流：**Linux 上动态链接器在 `main` 之前就会失败**
（`libwebkit2gtk` 不存在），用户看到 `error while loading shared libraries`——
`apicase run` 连一行代码都执行不到，而服务器上跑 CLI 恰恰是最主要的场景。
macOS 上裸二进制跑 Tauri 也行为异常（NSApplication 需要 bundle）。

一致性靠的不是同一个进程，而是**同一个执行内核**加**同一份数据**：
CLI 跑出的报告在界面文件树里点开就能看，CLI 登录留下的会话界面里接着用。

| 配置 | 存哪 | 谁读 |
|---|---|---|
| `verifySsl` / `caCert` / `timeout` / `cookies` / `continueOnAssertionFailure` / `concurrency` | `application.yml` 的 `settings:`（随 git，团队共享） | 两端，走 `Workspace::client_config()` / `run_opts()` |
| **代理** | `settings.json`（应用级，不进版本库） | 两端，走 `paths::load_app_prefs()` |
| cookie 会话 | `.apicase/cookies.yml`（可手工编辑） | 两端，同一个 jar 文件 |
| 报告 | `.apicase/reports/*.html` | 两端，同一个目录 |
| 主题 / 快捷键 / 最近打开 / 文件树显隐 | `settings.json` | 只有界面（纯 UI 偏好） |

**代理曾经是个裂缝**：它影响执行结果，却只有界面读得到（CLI 只认 `APICASE_PROXY` 环境变量），
于是「界面里设了直连、CLI 照样走系统代理」——正好能造出「界面里跑过了、CLI 跑却挂了」。
现在 CLI 两级回落：**环境变量优先**（CI 与容器里没有 `settings.json`，那里需要显式控制），
回落到界面的设置，都没有才跟随系统。

> 应用配置目录的推导只有 core 一份（`paths::app_config_dir()` → `~/.apicase`），
> 桌面端引用它而不走 `PathResolver`。两份推导必然漂移，而漂移的表现是
> **用户的设置凭空丢了**且不报任何错。
>
> **位置三平台同形**（Windows 即 `C:\Users\<用户名>\.apicase`），`APICASE_HOME`（绝对路径）可覆盖。
> 老位置（`PathResolver` 语义：`Library/Application Support` / `%APPDATA%` / XDG，均带 `identifier` 一层）
> 保留为**迁移来源与只读回落**：桌面端启动时搬一次（`migrate_legacy_settings()`，新文件已存在则绝不覆盖），
> CLI 只回落读、不写盘（可能跑在只读环境）。`src-tauri` 里有一条测试比对**老位置**与
> `mock_app()` 的配置根——推导对不上就等于没搬。
>
> **读不到一律回落默认**：只用界面的人从没跑过 CLI，只用 CLI 的人（CI、容器）根本没有
> `settings.json`，甚至可能连主目录都没有——这些都不是错误状态。

**三个包名对齐**（`apicase-core` / `apicase-cli` / `apicase-desktop`），但**两者的构建方式并不对称**：

```bash
cargo build -p apicase-cli --release   # → target/release/apicase，拷走就能用
npm run tauri build                    # → target/release/bundle/{macos,dmg}/…
```

CLI 是纯 Rust，`cargo build` 就是全部。桌面端还要先有前端产物，而**跑 `cargo build` 不会构建前端**——
`beforeBuildCommand`（`npm run build`）是 tauri CLI 的职责，cargo 不认识它。
直接 `cargo build -p apicase-desktop --release` 得到的是「Rust 侧编好了、前端嵌的是 `dist/` 里上次的版本」，
而且**不给任何提示**。它只适合验证 Rust 侧能不能编过，产不出可分发的 `.app` / `.dmg`。

> 包名与产物名不必相同，这里刻意用了两套：`apicase-cli` 是 cargo 的标识（`-p` 用它），
> 产物却叫 `apicase`——用户敲的是 `apicase run`，不该是 `apicase-cli run`。
> 而桌面端**不能**也叫 `apicase`：macOS 与 Windows 的文件系统默认大小写不敏感，
> 与 CLI 同名会在同一个目录里撞成一个文件。
> （`src-tauri` 的包名原是脚手架默认的 `app`，2026-08-04 一并对齐。）

### CLI 随桌面安装包一起分发

桌面安装包内含一份 `apicase`。理由是**版本一致性**——同一个安装包 = 同一次编译 =
同一个 `apicase-core`，「界面里跑过了、CLI 跑却挂了」这个承诺才真正闭合；
6.4 MB 的体积代价可以忽略。

但这是「捆绑**加**独立」而非「捆绑**代替**独立」：CI 与容器里为了一个命令行工具去下
几十 MB 的桌面包是荒唐的，CLI 必须仍能单独构建、单独分发。

```
Apicase.app/                       目录名来自 productName
└── Contents/
    ├── MacOS/apicase-desktop      桌面端，名字来自 [[bin]] name（不是 productName）
    └── Resources/bin/apicase      ★ CLI
```

> 一个曾被搞错的细节：macOS bundle 内的**可执行文件名取自 `[[bin]] name`**，
> `productName` 只决定 `.app` 的目录名。所以这里是 `MacOS/apicase-desktop` 而非 `MacOS/Apicase`。
> 也正因如此，把桌面端从脚手架默认的 `app` 改名为 `apicase-desktop` 那一步，顺带
> 保证了它与 CLI 的 `apicase` 在任何目录下都不会因大小写不敏感而撞成同一个文件。

**用 `bundle.resources` 而不是 `externalBin`**：`externalBin` 是给 sidecar 进程用的——
要求文件名带 target triple 后缀（`apicase-aarch64-apple-darwin`），打包时再削掉，
而且它会把文件放进 `Contents/MacOS/`，与桌面端可执行文件混在一处。
CLI 是「随包分发的一个工具」而不是「应用要拉起的子进程」，放 `Resources/bin/` 语义更准，
也不必伺候那套命名规则。

**中转目录 `src-tauri/bin/`**（不进版本库）：`tauri.conf.json` 里的 resources 路径只写死
一条，而 dev 与打包用的是不同 profile。直接指向 `../target/release/apicase` 的话，
只 build 过 debug 的机器上 `npm run tauri dev` 会因为那个文件不存在而失败。
中转一层，谁填进去由 `scripts/stage-cli.mjs` 决定：

```
beforeDevCommand    npm run cli:stage:debug && npm run dev    # dev 用 debug 版，秒级
beforeBuildCommand  npm run cli:stage && npm run build        # 打包用 release 版
```

备料脚本**自己负责编译**，而不是让调用方记着先编——忘了编的后果是
「打出来的包里装着上一次的旧 CLI」，且没有任何报错。它还显式 `chmod 755`：
打包链路里少一个可执行位的表现是「装好之后 apicase 敲不动」，代价太高，不赌默认行为。

### 操作层 `ops`：CLI 与 MCP 的共同底座

```
apicase-core        执行语义
     ↑
  ops              操作层：run / list / check —— 与呈现无关、与协议无关，**不 print**
     ↑
 ┌───┴───┐
CLI 渲染   MCP 工具
```

CLI 与 MCP 若各写一遍业务必然漂移——那正是执行语义下沉 core 时要消灭的技术债，
不该在上层重新长出来。有了它，每个子命令与每个工具都只是同一个函数的两种外壳，
**参数名与语义一一对应**：AI 读过 `apicase run --help` 就会用 `apicase_run`，反之亦然。

**「不 print」是硬约束**，不只是洁癖：MCP 的 stdio 传输规定 **stdout 只能有协议消息**，
这一层漏一行 `println!` 就会破坏 JSON-RPC 帧，表现为「连上了但什么都不工作」且几乎无从定位。
运行进度走回调（`Event::Start` / `Event::Case`，与桌面端推给前端的三段式同形）。

### 命令与约定

```
run  ls  check  show  env  report  new  init  docs  mcp  completion  self
```

（曾有过 `gui`，2026-08-04 移除；`cookie` 2026-08-05 移除——会话就是一份可编辑的
`.apicase/cookies.yml`，见上面的 Cookie 一节。）

- **工作空间向上查找**（同 git 找 `.git`）：`-w` → `APICASE_WORKSPACE` → 从**目标所在目录**向上找
  `application.yml`。从目标而非当前目录起算，是为了让 `apicase run /别的项目/api/login.yml`
  自动用那个项目的环境与设置。
- **找不到也照样跑**（「未锚定」，`Workspace::is_scratch()`）：以目标所在目录为根，配置全默认。
  `apicase run /tmp/试一下.yml` 本就该直接跑起来——用例是自包含的一份 YAML，
  跑它不需要任何前置仪式。`application.yml` 的价值在于**声明边界**
  （子目录里也能找到根、环境变量放哪、报告与会话落哪），临时跑一个具体文件时这些都不需要。

  未锚定时收窄三件事，都是为了**不在别人的目录里留痕**：不落 HTML 报告
  （显式 `--report` 仍照办）、不建 cookie jar、不碰 `.gitignore`。

  还有一条硬拦截：**未锚定时不许省略目标**。那时的「根」只是当前目录，在 `~` 底下敲一句
  `apicase run` 会递归扫掉整个主目录、把碰巧同名的 `.yml` 全当用例跑一遍——
  我们发的是真实 HTTP 写请求，那是能造成实际伤害的。
- **无参数打印帮助而不是开界面**（git / docker / cargo 的规矩；在终端敲 `apicase` 弹出一个窗口是一种惊吓）。
- **`run` 的目标可以是 `-`**：从 stdin 读一份用例直接跑，不必先落盘（AI 生成一段 YAML 就能验证）。
- **`--step <id>` 自动带上上游依赖**（`runner::with_dependencies` 的依赖闭包）——
  只写要跑的那一个，链由 core 补齐；漏一个上游的后果是「下游拿着未解析的 `${{...}}` 发出真实写请求」。
- **`--var k=v` 是往活动环境里追加**，仍会被 case 级 `vars` 覆盖。语义可解释，且执行内核一行不改。
- **输出格式跟着 TTY 走**：终端 text、管道 json（`apicase run | jq` 直接成立）。
  `NO_COLOR` 与 `--color` 决定着色。text 模式全部走 stdout（它本身就是报告）；
  json 模式下 JSON 走 stdout、进度走 stderr。
- **JSON 就是 `RunReport`**——与报告页内联的那份同一套 schema。**一套数据契约，三处消费**
  （报告页 / CLI / MCP）。默认 `--detail summary`：**schema 与计数都不变**，
  只把通过的 step 的报文与断言明细拿掉、失败的 step 保留现场（报文截 2KB + 失败的断言）。
  一份 500 用例的完整报告有几 MB，给全份无论对 `jq` 还是对 AI 都是错的默认值。

**退出码四档**（`0` 通过 / `1` 断言失败 / `2` 用法错误 / `3` 执行错误）：
`2` 留给用法错误是 GNU 工具的强约定（`grep`：0 匹配 / 1 不匹配 / 2 出错）；
`1` 与 `3` 分开则是 apicase 特有的——**`failed ≠ error` 本就是内核的核心理念**，
退出码不体现它等于在 CI 那一层把最有用的信息丢掉。两者同时出现取 `3`（跑都没跑起来更严重）。
Ctrl-C 置取消位而非直接死（已发出的 HTTP 不打断，部分报告仍落盘），退出 `130`。

**CLI 里没有唤起界面的命令**（曾有过 `apicase gui`，已移除）。
两个二进制职责单一：要用命令行就敲 `apicase`，要用界面就开 `apicase-desktop`。
跨进程唤起要维护「找可执行文件、判断显示服务可用、分类各种失败」这一整套猜测逻辑，
而它换来的只是省掉用户点一下图标——不值。

桌面端自己带 `startup_workspace()`：从 argv 里挑出**存在且是目录**的那个参数
（跳过 macOS 从 Finder 启动塞的 `-psn_0_…` 与各平台桌面项的开关），前端启动时拿到就直接打开。
这条路径独立于 CLI，支撑 `apicase-desktop <工作空间>` 与「把目录拖到应用图标上」。

### 让 AI 用起来：三层，一层比一层低摩擦

```
① AGENTS.md + CLI      零配置，文件在目录里就生效，随 git 走。三十多个 Agent 原生读
② MCP                  要在每个客户端里配一次，适合只放行工具、不给 shell 的环境
③ 什么都不装            AI 只能读写 YAML 文本，跑不了
```

**主路径是 ①**。`AGENTS.md` 是 Linux Foundation 旗下 Agentic AI Foundation 的开放标准，
Codex / Cursor / Copilot / Gemini CLI / Windsurf / Zed / Aider / Devin 等原生支持，
Claude Code 也读。它零配置、随 git 走到每个同事的机器上；MCP 则要每人配一次。

**内容刻意做得短——指路，不复制。** `AGENTS.md` 只告诉 AI 去哪儿查
（`apicase docs` / `check` / `run --json`），不把 YAML 规范抄一份进去。抄一份的后果有二：
每次 AI 打开项目都吃掉几千 token；规范改了这里没改，就有了第二个真相。
这与 MCP 把格式规范做成 `apicase_docs` 工具、而不是塞进 `instructions` 是同一条原则。

**幂等写入靠 `<!-- apicase:begin/end -->` 标记**：已有标记则只替换其间内容、
有文件无标记则追加、无文件则新建。工作空间很可能就是某个大项目的根目录，
那里的 `AGENTS.md` 讲的是整个项目的事，**绝不能覆盖**。标记残缺时当作没有——
在半个标记上做切片会把用户的内容切掉一块。

**兜底路径只写平台约定，不写本机绝对路径**：`AGENTS.md` 随 git 走，
写死 `/Users/某某/…` 到同事那儿就是错的。CLI 已在 PATH 时那段兜底根本不生成。

#### 命令行工具接进 PATH

AI 读了 `AGENTS.md` 会直接敲 `apicase`，敲不到就是硬失败——它不会自己去
`Contents/Resources/bin/` 里翻。所以桌面端与 CLI 各有一个入口，**走同一份实现**
（`core::cli_link`）：

| 入口 | 谁用 |
|---|---|
| 设置页「AI」的安装按钮 | 普通用户 |
| `apicase self install` / `uninstall` / `status` | 命令行用户、脚本化安装 |
| `apicase init` 顺带做掉 | 新建工作空间时 |

**优先 `~/.local/bin` 而不是 `/usr/local/bin`**，理由不是它更好，而是**不需要提权**——
目标是「用户无感」，弹一次系统密码框就不无感了。另一条更硬的理由：`.app` 可以装在
`/Applications` 也可以装在 `~/Applications`，全局软链指向用户级安装时，
另一个用户要么撞不到、要么读的是别人的目录，那人卸载后就变成断链。
业界分野也是这个走向：系统级应用（Docker、VSCode）走全局，
开发者工具链（rustup、uv、pipx）走用户目录。

落点按「已存在 + 在 PATH 里 + 当前用户可写」挑，而不是按目录名硬排；
一个都不满足才回落到 `~/.local/bin` 并提示用户加进 PATH。
**位置被别的 apicase 占着就不动**（可能是 `cargo install` 装的），报出来让用户决定——
覆盖别人的东西才是冒犯。判断「是不是同一份」按 canonicalize 后的真实路径比，
不比字符串：软链与大小写不敏感都会骗人。

**用软链而不是拷贝**，这样应用升级后 PATH 里的自动跟着新。
卸载入口不能省：macOS 把 `.app` 拖进废纸篓不会清理软链，PATH 里会留一个断链，
之后敲 `apicase` 报的是「No such file or directory」，比「命令未找到」更让人困惑。

#### `apicase init` 现在做三件事

```
① application.yml     声明边界（没有它就没有向上查找、没有报告与会话的落点）
② 命令行工具进 PATH    AI 敲得到
③ AGENTS.md           AI 知道这是什么
```

全部幂等，可用 `--no-link` / `--no-agents` 单独关掉。

界面侧对应「设置 → AI」分区（放**项目组**——用户来这儿是为了「让 AI 能操作这个工作空间」，
那是项目视角）。②③ 在界面上合成**一个「初始化」按钮**：用户要的是「能用」，
拆成两行两个按钮只是把内部实现摊给他看；出问题时看下面两行状态即可分辨是哪一件没成。

- **AGENTS.md 是三态**（`agents::state` → `ready` / `stale` / `absent`）：段落在、但内容是旧版本
  时报**「不一致」**。此前只有有 / 无两态，于是升级后界面显示「已配置」而 AI 手上是上个版本的说明。
  判定与生成必须用同一个 `cli_on_path` 前提（它决定正文里有没有那段兜底路径），否则装完 CLI 会凭空
  多出一次「不一致」。
- **打开工作空间即自动初始化，且没有开关**（原 `aiAutoSetup` 那个默认关的复选框已删除，
  连同 `settings.json` 里的字段）：apicase 的用例本就是给 AI 接管着写的，
  一个「要不要让 AI 能用」的选项只会制造「AI 说找不到 apicase 命令」这类求助。
  按钮仍留着——自动那次可能因目录只读而失败，状态也可能被外部改坏，得有个重来的入口。
- **MCP 那块按 Agent 给出两种接入方式**：下拉选 Claude Code / Codex / OpenCode / Trae / Qoder，
  分「命令配置」与「文件配置」，做成**标签页**而不是上下摞两个代码块：它们是二选一，
  摞着读起来像是要依次都做一遍。没有命令行入口的客户端（Trae / Qoder）那个标签禁用并说明原因，
  默认落在文件配置上。两种方式**同一套骨架**：**写到哪儿 → 接入 → 删除**，
  两步对称地各带一个可复制的代码块——装完发现不对却找不到怎么撤，比装不上更让人恼火；
  而「这条命令把配置写到哪」（`~/.claude.json` 的全局 mcpServers / `~/.codex/config.toml` / …，
  含 Windows 写法与生效范围）不说清楚的话，用户既不知道会不会污染仓库，也不知道换台机器还在不在。
  Claude Code 那块**三种作用域一并给出**（默认的 local = 仅当前项目、`-s user` = 所有项目、
  `-s project` = 写进项目根 `.mcp.json` 随仓库共享），每条上方一行注释写清落点——
  「装一次处处能用」与「只给这个项目」是两种真实需求，只给一条总有人要去翻文档。
  删除块与接入块**逐条对称**（有测试钉住条数与注释一一对应）：作用域对不上会删到另一处的同名条目。
  不把 `apicase mcp` 本身摆出来——那是**给客户端去 spawn 的**服务端命令，
  用户自己敲只会得到一个卡住的 stdio 进程。几处要点：
  - **接入命令与配置一律不带 `-w`**：MCP 配置是给客户端长期用的，而客户端明天可能开在别的项目上。
    不带它时 server 就把**调用方的工作目录**当工作空间（有没有 `application.yml` 都能用，
    没有即「未锚定」：照跑，只是不落报告、不建 cookie jar），AI 还能每次调用传 `workspace` 换项目。
    写死还有第二个坏处：目录改名或换机器后 `serve()` 启动即校验，server 连起都起不来。
    界面上不再解释这套定位规则（那是内核的事，摊给用户只是噪音），它写在 MCP 的开场白里给 AI 看。
  - **每家的落点都按「作用范围 → 位置」写全**（Codex 的全局 `~/.codex/config.toml` 与项目级
    `.codex/config.toml`、OpenCode 的项目根 `opencode.json` 与全局 `~/.config/opencode/opencode.json`、
    IDE 型的面板路径），带上 Windows 写法。**写在哪儿取决于格式能不能容注释**：
    命令与 TOML 写成命令上方的 `#` 注释（复制时一并带走，读的人不必在两处对照），
    JSON 片段则只能放在片段上方那行——里面写 `//` 复制过去就是语法错误。
  - **各家的配置形状并不相同**：Claude Code / Trae / Qoder 读 `mcpServers`（JSON），
    Codex 是 `~/.codex/config.toml` 的 `[mcp_servers.apicase]`（**TOML**，照 JSON 那套贴过去会被整份忽略），
    OpenCode 的键是 `mcp` 且 `command` 是数组。IDE 型的两家没有命令行入口，就直说，
    不编一条不存在的命令出来。
  - `claude` / `codex` 的 `--` 分隔不能省，少了它后面的参数会被客户端自己的解析吃掉；
    OpenCode 的 `mcp add` 目前只有交互式向导。这些都有前端测试（`test/ai.test.mjs`）钉住。
  - 一律用命令名 `apicase` 而非自带那份的绝对路径：这些会写进随 dotfiles 走的配置文件。
- 界面不提供「移除」：卸载是一次性的收尾操作，`apicase self uninstall` 已完整覆盖，
  两处各留一份实现迟早会有一处忘了跟。

### MCP：七个工具

`apicase mcp` 走 stdio 传输。工具 `apicase_run` / `check` / `list` / `show` / `env` / `report` / `docs`
（带 `apicase_` 前缀，同 Playwright MCP 的 `browser_*`，避免多 server 并存时通名撞车）。

**除 `docs` 外每个工具都收一个可选的 `workspace`（绝对路径）**，定位优先级是
**调用时显式给的 > 启动时的 `-w` > 目标所在目录 > 调用方的工作目录**。
理由是 AI 手里往往同时开着几个项目：没有这个入口，它只能靠传绝对路径的 target 间接换地方，
而 `apicase_env` / `apicase_report` 这类没有 target 的工具则彻底换不了。
显式给的与 `-w` 都按「就是这个目录」处理（不再向上找），靠目标 / 工作目录推导时才向上找
`application.yml`——**找不到也不算错**，那时就以该目录为根（未锚定：不落报告、不建 jar）。
开场白里因此明说「默认把你当前的工作目录当作工作空间，要换项目就传 workspace」。

- **协议层用官方 SDK（`rmcp`）而不是手写**，这与「YAML 输出器自己写」并不矛盾：
  那个是**产品面**（用户要读、要 diff 的源文件格式），这个是协议帧、产品面为零，
  唯一价值是「能被各家客户端连上」。且协议一年三版
  （`2025-06-18` → `2025-11-25` → `2026-07-28`，最后一版**移除了 initialize 握手**改为无状态），
  现实中的客户端跨越两个时代，那张兼容矩阵是 SDK 的职责。
  风险对冲：MCP 层收敛在 `mcp.rs` 一个文件，只做「参数解包 + 调 ops + 转 `CallToolResult`」，业务零行。
- **`apicase_docs` 是给 AI 的入口条件**：AI 不知道 apicase 的 schema，靠猜必然写错。
  内容 `include_str!` 直接嵌 `docs/0.latest/3.YAML格式规范.md` 并**按标题分节**
  （`case` / `assertions` / `auth` / `body` / `vars` / `settings` / `all`），
  **不另写一份速查**——另写的那一刻就有了两个真相。有测试钉住每个主题都真的摘到内容，
  规范里的标题被改名会立刻红。
- **不提供写文件的工具**：用例是 YAML 文本，AI 自带的文件工具已经够用，
  再包一层只会多一道权限与语义的错位。
- **`instructions`（开场白）写的是最小闭环**：查格式 → 写 YAML → `check` 自检 → `run` 验证 → 读失败现场改，
  并特意说明 `failed` / `error` / `skipped` 的区别——那是 apicase 结果里最容易被误读的一处。
- **与 CLI 刻意不同的默认值**：`apicase_run` **默认不落盘 HTML 报告**（CLI 默认落）。
  AI 调 run 多半是「验证我刚写的这个用例对不对」，每次甩一份几 MB 的 HTML 进工作空间是污染。
- 每次工具调用**重新打开工作空间**：会话期间 AI 会改 `application.yml` 与用例，
  缓存住只会让工具用着过时的配置（开销是读一个几 KB 的文件）。
- 相对路径按**工作空间根**解析，不按进程 cwd——MCP 客户端的 cwd 是编辑器的启动目录，
  而 AI 手里的路径来自 `apicase_list` 的输出（那是相对工作空间根的）。

配置示例：

```json
{ "mcpServers": { "apicase": { "command": "apicase", "args": ["mcp", "-w", "/path/to/workspace"] } } }
```

## 前端：交互

**前端只做配置与展示。** 请求表单 → `run.ts` 的 `runStep(step, ctx, opts)` → 执行内核完成
「变量透传 → 组装 → 认证 → 发送 → 提取 → 断言」 → 前端把 `StepResult` 折成响应区要的形状渲染。
客户端配置 `ClientConfig` = 代理（应用级偏好）+ 请求设置（工作空间 `application.yml`）+ cookie jar，
CA 与 jar 的相对路径在此还原为绝对路径。
UI 对标 Postman：方法下拉（彩色）与 URL **连体** + Send；Headers（自动增行）/ Body 配置 Tabs；响应区状态徽章 + 耗时 + 大小，Body(Pretty/Raw) / Headers Tabs。

**三栏布局（仿 VSCode）**：顶栏**最右**三个切换按钮（VSCode 风格图标：外框方块 + 对应边填充）显隐三块面板——**左**文件树 / **底**终端 / **右** AI 对话。布局包裹为 `.body-layout`（横向：`.sidebar` + `.center-col` + `.ai-panel`），`.center-col` 内纵向排 `.workspace` 与 `.bottom-panel`。显隐状态 `LayoutFlags{left,bottom,right}` 存 **`sessionStorage`**（`apicase.layout.v1`）——刻意做成**会话级**：关闭应用即清空，下次启动回到默认（左开、底/右关），不像主题那样是跨启动的长期偏好；底部栏可拖高、右侧栏可拖宽（复用既有 resizer 模式，`body.resizing-row`/`resizing-col`）。底部终端与右侧 AI **首次打开后常驻**（`display:none` 隐藏而非卸载），保留 shell 会话/滚动与对话历史。快捷键（`shortcuts.ts` 「视图」组）：`Mod+B` 左栏 / `Mod+J` 终端 / `Mod+Alt+B` 右栏。
- **终端**（`TerminalPane.tsx`）：`xterm.js` + `FitAddon`；挂载即 `terminal_open`（cwd=工作空间），监听 `terminal://data/{id}` → `term.write(Uint8Array)`（原始字节交 xterm 缓冲，天然处理跨包 UTF-8）；`onData` → `terminal_write`；`ResizeObserver` → fit + `terminal_resize`；切回可见时 refit + focus；`cwd` 变化（切工作空间）重建会话。
- **AI 对话**（`AiChat.tsx`，本期 UI 外壳）：消息气泡列表（自动滚底）+ 多行输入（Enter 发送 / Shift+Enter 换行）+ 清空；发送后追加用户消息与占位助手回复，后续接真实模型仅替换回复来源。

**工作空间 / 文件树**：左上角自定义下拉 → `plugin-dialog` 选目录 → `invoke("init_workspace")` → `invoke("list_dir")` 渲染左侧文件树（懒加载、可展开折叠）；左侧栏可拖动调宽（默认 260px，范围 160~480；260 是为了让「05-延迟与重定向」这类目录名不一上来就被截断）、可整体显隐。子级容器画**缩进参考线**（`.tree-children::before`，位置 = `calc(6px + var(--tree-depth) * 14px + 8px)`，即父行折叠箭头的中线；`--tree-depth` 由 TreeNode 内联传入，`z-index: 1` 使其压过行的 hover/选中底色，线不被割断）；展开后为空的目录显示「空文件夹」占位，文字与同级文件名左对齐。打开工作空间即 `invoke("watch_workspace")` 启动监听，订阅 `workspace:fs-change` 事件做**自愈刷新**（仅刷新已加载目录，保持懒加载一致）。

**文件树的行菜单与剪贴板**：每行（含**工作空间根那一行**，其交互与 `.tree-row` 一致：26px 行高、6px 圆角、`cursor: pointer`、hover 底色、点击选中 + 同款选中橙条）**悬浮 / 选中 / 该行菜单打开时**在最右显形一个「⋯」按钮，点击弹出的菜单与右键完全同源（`ctxItems`）——根：新建用例 / 新建文件夹 / 粘贴 / 显示文件所在位置；目录：再加 克隆 / 复制 / 重命名 / 删除；文件：克隆 / 复制 / 重命名 / 显示文件所在位置 / 删除。工具栏「+」走另一份 `newItems`（仅新建用例 / 新建文件夹），由 `ctxMenu.newOnly` 区分。「粘贴」在目录与根上**常驻**，剪贴板为空时 `disabled` 灰显。树选中态 `treeSel{path,isDir}` 与「当前打开文件」分离——**目录也要能被选中**（粘贴要落到它里面），点目录即展开且选中，切标签时选中项跟随当前文件，点根行「⋯」则清空选中让粘贴落到根。剪贴板是应用内状态 `clip{path,isDir}`（不走系统剪贴板），**只有复制、无移动语义**，故粘贴后保留、可连续粘贴。粘贴目标 = 选中目录本身 / 选中文件的父目录 / 无选中则工作空间根；重名经 `uniqueName` 自动排号（`用例.yml` → `用例 副本.yml` → `用例 副本 2.yml`），**不覆盖**。两条拦截：目录粘进自身或子目录、源已被外部删除。重命名后由 `retargetPaths(from,to)` 统一迁移标签、当前文件、选中项、展开态与子项缓存——目录改名时其下已打开文件的标签路径也跟着走。

**多选**（2026-08-07）：Shift 连选 + Cmd/Ctrl 点选。**`sel: Sel[]` 是唯一真相，`treeSel` 是它的末项**
（最近点击的那一行，粘贴目标 / 根行高亮等既有单选逻辑照旧用它）——两者分开存必漏同步，
故只留 `selectOne` / `clearSel` 两个入口，别处不直接 `setSel`。算法全在 `treesel.ts`（纯函数、有单测）：

- **Shift 区间按「可见顺序」算**，不是按目录结构：`flattenVisible` 把 childrenMap + expanded 拉平成
  一份与渲染顺序一致的数组，展开的子项算在内、折叠的不算。锚点 = 最后一次**非 Shift** 点击的行
  （`anchorRef`），Shift 恒**基于它重算**而非累加——累加的实现表现为「Shift 点回去反而选得更多」。
  锚点已不可见时退化成只选目标行。
- **带修饰键点击不打开文件、不展开目录**：挑三个用例的过程中每点一下就开一个标签，选完满屏狼藉。
  Cmd 分支用**函数式 `setSel`**：两次点击若落进 React 同一批处理，闭包里的 `sel` 还是上一帧的。
- **右键落点**（同 Finder / VSCode）：点在已选中的行上，菜单作用于整个选区；点在选区外的行上，
  先把选区收回到这一行。少了后半条，用户会在毫无察觉的情况下对一批东西执行操作。
- **祖先吸收**（`pruneDescendants`）：选区里同时有 `订单/` 和 `订单/下单.yml` 时只处理最上层的。
  删除、移动、复制、克隆都要过这一道——否则删除会「删完父再删子」报错，移动会拿着已不存在的子路径去 rename。
- 多选菜单只留说得通的项（生成测试报告 / 克隆 / 复制 / 删除）：重命名是另一个功能，
  「显示文件所在位置」只能作用于一个，粘贴的落点在多选下也不明确。
- **选中态只靠行高亮，不加提示条**：曾试过一条「已选 N 项 + 取消选择」的细栏，
  但它常驻占一行、把树整体下推，而选了什么行高亮本就看得见——为一个次要信息
  牺牲侧栏的简洁不划算。工作空间根不参与多选。
- **取消选择两条路**：`Esc`（侧栏有焦点时；焦点在搜索框里则放行给输入框）、
  点侧栏空白处（判「点到的不是任何可交互元素」，而不是给 `.tree` 撑满高度——
  后者要改侧栏的布局与滚动，代价大得多）。「随便点一行」不算取消：
  那会打开文件 / 展开目录，而且仍剩一项选中。
- **批量落地的名字要在批次内累积**（`planCopy` / `planClone`）：一次粘两个同名文件，
  第二个必须看得见第一个刚落地的名字，否则两个都算出同一个「x 副本」，后一次拷贝盖掉前一次。

**拖拽移动**（2026-08-06；2026-08-07 支持多选）：树里的行可直接拖到另一处，落点是「拖到的那一行**所属的目录**」——
拖到文件夹上即它自己，拖到文件上即该文件所在目录（同 VSCode，不必精确瞄准文件夹标题），
拖到工作空间根那一行即根。判定在 `pathutil` 的 `dropTargetDir` / `checkMove`（纯函数，有单测）：
拖回原处或放到自己身上**静默无操作**（用户什么也没要求，弹错误纯属打扰），目录放进自己的子目录则拒绝。
**同名时拒绝而不排号**——这一点与粘贴刻意不同：粘贴排号是因为那本就是"再来一份"，
而移动时悄悄改名会让人在新位置找不到刚拖过去的东西。多选拖拽是**全或无**（`planMove`）：
判定（含同名）全部做完才动手，移了一半再报错，用户得自己逐个核对哪些已经过去了——
而这正是他一次拖过来想省掉的事。同名有两种，文案与单选时同源：目标目录已有（`X 下已有 a.yml`，
多个补「等 N 项」）、批次内两项互撞（`选中项里有两个 a.yml，不能一起移动到 X`）。
`dragover` 阶段只判结构性问题（`canDropInto`）不查同名——那要读盘，而它每移动几像素就触发一次。
落地后走的还是 `rename_path`
（`std::fs::rename`，后端另有「拒绝覆盖同名」的测试）＋ `retargetPaths` ＋ `noteSelfWrite`（免得 fs 监听把自己的动作报成外部改动）。
视觉上拖动源半透明、落点行虚线框 + `--accent-tint` 底（与实底的「选中」区分得开）。

> 这里有个 Tauri 层的前提：窗口配置必须 **`"dragDropEnabled": false`**。
> 它默认为 `true`，此时 OS 的原生拖放会**吃掉 webview 内的 HTML5 拖放事件**，
> 表现是拖起来但永远收不到 `drop`——而这是配置问题，代码里怎么查都查不出来。
> 关掉它的代价是窗口不再接收系统拖入的文件，apicase 目前没有这个入口（打开工作空间走的是目录选择框）。`Ctrl/⌘+C`、`Ctrl/⌘+V` **只在左侧栏有焦点时**生效（`.sidebar` 挂 `tabIndex={-1}` + `onKeyDown`，事件源是 input/textarea/contentEditable 时放行），不进全局快捷键表——那是 document 级分发，会劫持编辑区/终端里的正常复制粘贴。「显示文件所在位置」走 `@tauri-apps/plugin-opener` 的 `revealItemInDir`（`opener:default` 已含）。

**case 读写**（`case.ts`）：点击 `.yml`（非 `application.yml`）→ `read_text_file` → `await analyzeCase(text)` → 渲染。编辑标记 dirty → `Cmd/Ctrl+S` 或保存按钮 → `await dumpCase(c)` → `write_text_file`。**解析与序列化都在 Rust**，`case.ts` 只剩 TS 类型与 IPC 封装——这些调用全在用户操作边界（打开 / 切视图 / 保存），一次 IPC 往返不到 1ms。序列化裁剪默认值（`enabled:true`、空 body 等不落盘）。

> **唯一留在前端的执行相关同步逻辑**是 `splitQueryFromUrl` / `mergeQueryIntoUrl`：它们在 URL 输入框的**打字热路径**上（每敲一个字符都调），走 IPC 会让输入变黏手。Rust 侧有等价实现（`core/src/request.rs`）服务于发送，两边各有单测钉住。

**三视图与 flow 编辑**（`App.tsx` + `FlowCanvas.tsx` + `RequestEditor.tsx` + `draft.ts`）：case 内部统一为 step 列表模型（单节点 = 1 个 step；YAML 写 `steps:` 列表，每步含 `protocol:` 与 `request:`）。顶栏三视图切换——**文本**（原始 YAML，互斥）/ **流程**（DAG 画布）/ **请求**（复用请求编辑器），按**意图式**切换（关掉唯一在显栏落文本、从文本点某栏则确保显示该栏）。内容驱动默认视图（`analyzeCase` 判 valid/单/多）；切结构视图前 `commitText` 重解析 rawText，切文本前从结构态 `dumpCase` 刷新（结构是切换时的真相源）。画布 `dependsOn` 自动分层布局 + SVG 贝塞尔连线。**画布交互**（`FlowCanvas.tsx`）：平移（拖背景 / 滚轮）+ 缩放（Ctrl/⌘ 滚轮锚定光标，工具栏放大/缩小/缩放%复位）+ 适应视图 + 规整（清手动坐标恢复自动布局）；**拖拽节点**持久化坐标到该 step 的 `ui: { x, y }`；从 **out 端口拖到目标节点建立依赖**（防自连/重复/成环）；边悬停显示删除按钮解除依赖；双击空白快速加节点；**拖拽对齐吸附**（与其它节点列/行对齐时贴齐并显示参考线）；右下角 **小地图/概览**（节点缩略 + 视口框，点击/拖拽导航）。坐标是视图态、拓扑（`dependsOn`）是真相。

**多标签页**（`TabBar` + `tabOrder` + `tabCacheRef`）：活动标签用 live state，非活动标签用 `TabSnapshot` 快照保存完整编辑态；`openTab` 快照当前 + 恢复目标（新标签走 `openCase` 加载），`closeTab`/`closeOtherTabs`/`closeAllTabs`（dirty 关闭前确认）；重命名/删除文件同步标签。

**flow 执行**（`run.ts` + 执行内核）：`发送` / `▶ 运行`——每步的「变量透传（`${{vars}}` / `${{steps.x.outputs.y}}`）→ 组装 → 认证 → 发送 → 按 `res.*` 路径提取 `outputs` → 评估断言」**全在 Rust**。「运行全部」的顺序由 `topoOrder` 命令排出，循环留在前端是为了每跑完一步就刷新界面；outputs 用本地上下文在 `await` 间同步透传。断言结果逐条 ✓/✗，失败标红节点。请求编辑器在参数/请求头/认证/请求体之外，追加 输出 / 断言 / 文档 / 请求 ID 等 Tab（输出/请求 ID 仅多请求场景，请求 ID 置于末尾；「文档」标签支持 markdown 编辑与预览，内容存 step 的 `docs:`）。

**断言目标与补全**（`core/src/assert.rs` + `src/assertPath.ts`）：目标统一挂在 `res` 命名空间下
（`res.status` / `res.headers.<名>` / `res.body<路径>`），认不出的目标显式取不到值（`∅`），
不做前缀猜测——`res.bodyfoo` 宁可判无效，也不能被当成"取整个响应体"而静默通过。
目标格的补全由 `assertPath.ts` 按**最近一次响应**逐层给候选，每条带该路径的当前值摘要；
期望值格同样按目标的当前值给一条建议（`suggestValue`），但只建议不自动填，且在
`matches` / 容器值 / 超长文本这些场合闭嘴——一键把返回值固化成期望值正是脆弱断言的来路。
这是全前端唯一一处与内核重复实现的求值逻辑：内核在跑完之后求值，补全要在输入时就给出候选，
两边跑同一套规则（两侧各有单测钉住），所以点着选出来的路径运行时一定取得到。

**批量运行与报告**（`run.ts` + 执行内核）：文件树右键「生成测试报告」→ 配置对话框（用例预览 / 递归 / 环境）→ 运行报告标签页 + 落盘 `<workspace>/.apicase/reports/<时间戳>-<目标名>.html`。**多选可一起跑**（2026-08-07）：目录与用例混选，`discoverAll` 合并后**去重**（两个选中目录互为父子时会扫出重复项，跑两遍既费时、报告里也会出现两条同名结果）再合成**一次**运行、**一份**报告；报告名走 `reportFileNameMulti`（`<时间戳>-<首个目标>等N项.html`，与 CLI 的 `report_file_name_multi` 逐字一致），报告头 `options.targets` 记下**全部**目标——只记第一个的话，半年后回看会以为那次就只跑了它。后端本就收 `targets: Vec<BatchTarget>`，这里没有新增命令。

- **执行、报告渲染、周期写盘全在 Rust**；前端只负责开标签、订阅 `run://progress/{runId}` 事件、把 case 逐个追加进本地报告对象。事件按**增量**推（`start` 报告头 → `case` 逐条 → `end` 收尾），而不是每次整份重发。
- **报告头里的运行参数从 `opts` 派生**，不并列写第二遍——半年后回看一份失败报告，「当时用的哪套环境、截断阈值多少」直接决定结论能不能信。
- **报告只有一套渲染实现**（硬约束）：iframe 里跑的空壳与落盘 `report.html` 出自同一份资源。空壳经 `report_shell()` 取一次并进程内缓存（它与运行数据无关；`srcDoc` 一变就会重新加载整个文档，握手状态会作废）。
  - **分层**：iframe 内 = 报告内容；iframe 外 = 运行控制（进度条 / 取消 / 在浏览器打开）——分发出去的 HTML 里本就不该有「取消」。
  - **postMessage 协议**：宿主 → 报告 `host`（握手；收不到即为浏览器独立打开，IDE 专属动作不渲染）/ `theme` / `report`；报告 → 宿主 `ready` / `open-case`。`sandbox="allow-scripts"` 且**不给 `allow-same-origin`**；`srcdoc` 的 origin 是 `null` 故只能 `postMessage(*)`，宿主侧按 type 白名单处理，`file` 经 **`resolveInWorkspace`** 解析——报告会被转发，它给的路径是不可信输入：含 `..` 段的、本身是绝对路径的、落在当前工作空间之外的一律拒绝，**且拒绝要出声**（静默不动的表现就是「点了没反应」，没人分得清是坏了还是被拦了）。
  - 这条判断收进具名函数而不是散在调用处：`isUnder(parent, p)` 两个参数同型、写反了照样编译，而写反的后果是恒 `false`——「在 apicase 中打开」曾因此长期失效且不报错。
  - **「在浏览器中打开」走 `openPath` 而非 `openUrl("file://…")`**：opener 插件的默认权限集只放行 `http(s)`/`mailto`/`tel`，`file://` 会被 ACL 拒掉。故 capabilities 里另配 `opener:allow-open-path` **并带路径 scope**——该权限本身"不预置任何 scope"，光声明仍会被拒。
  - scope 写作 `**/.apicase/reports/*.html`：`.apicase` 必须是**字面量**。opener 的路径 scope 走 `tauri::fs::Scope`，Unix 上 `require_literal_leading_dot` 默认 `true`，于是 `*`/`**` 一律匹配不到点开头的路径段——连 `**` 这种全通配都匹配不上 `.apicase/…`（实测确认）。
  - **live 增量推数据**而非重塞 `srcdoc`（整页重画会丢展开态与滚动位置），报告页按 case `file` 作 key diff DOM；失败 / 错误默认展开。
  - 增量是**两段都增量**：Rust → 前端逐个 `case` 事件（`RunEvent::Case`），前端 → iframe 也只 postMessage 新增的那条（`run.ts` 的 `reportPush`）。后者曾是每次重发整份——结构化克隆按报告大小走，跑 N 个用例就是 O(N²) 的复制量，一份 500 用例的报告可达几十 MB。换报告 / 首次 / case 变少 / 运行收尾这四种情况仍退回整份，有单测钉住。
  - **落盘间隔随报告增大而拉长**（`ReportWriter::interval`）：每次落盘都要渲染整份 HTML，固定 1 秒一次会让后半程一直在重复渲染已完成的数据；应用内进度靠事件实时推送，落盘只是归档与崩溃兜底。
- **伪路径标签**：`tabOrder` 存路径字符串，运行标签用 `apicase://run/<id>` 前缀分流——不走 `openCase`、不进 `tabCacheRef`（不是编辑态），`isDirtyPath` 恒 `false`，关闭时一并 `cancel_run` 并释放会话。会话状态独立存 `runSessions`。
- **报告目录 `.apicase/` 与 fs 监听**：监听刻意跳过 `.` 开头路径（否则周期覆写会把文件树刷爆），故运行结束后**精准刷新**一次已加载的报告目录。首次运行时把 `.apicase/` 写进工作空间 `.gitignore`。

**认证**（`core/src/auth.rs` + `core/src/request.rs`；前端 `auth.ts` 只剩显示元信息）：六种方式——`No Auth / Basic Auth / Bearer Token / API Key / Digest Auth / OAuth 2.0`（命名对齐 Postman/Insomnia/Bruno）。静态头（Basic/Bearer/API Key）由 `request::build` 直接组装；需要额外交互的两种收敛进 **`send_with_auth`**：**Digest** 首发不带凭据，吃到 401 后解析 `WWW-Authenticate` challenge 算摘要（`qop=auth` 五段式 / 无 qop 两段式，支持 `MD5-sess`，不支持 `auth-int`）**重发一次**；**OAuth 2.0**（客户端凭据）发送前 POST `tokenUrl` 换 `access_token`（凭据走 Basic 头或表单体）。以 RFC 2617 官方向量验证摘要计算。

- **token 缓存键含 `tokenUrl|clientId|clientSecret|scope|clientAuth`**：改任何一项即自动换一把新 token，前端因此不必再手动清缓存。缓存提前 30s 过期。
- **in-flight 去重**：每个缓存键一把异步锁，同键并发只有第一个真去换 token，其余在锁上等、醒来直接读缓存。这是 case 之间敢开并发的前提。
- **`send_with_auth` 返回实际发出的那一份请求**：OAuth 2.0 换来的 `Authorization`、Digest 重发时算出的摘要头只在那一份里。报告要如实记录发了什么——认证恰恰是最常出问题的一环。

**Cookies 管理**（设置页「Cookies」分区，属**项目组**——jar 跟着工作空间走；顶栏有饼干图标**直达该分区**，
清一次登录态是调试里的高频动作，埋在配置 → 左导航第三项之后太深）。版式对齐 Bruno
（读的是 `bruno-app/src/components/Cookies/index.js`）：顶部工具条（搜索 + 添加 + 清空全部）→
**按域折叠**的分组（域名 + 条数 + 该域的 ＋ / 清空）→ 展开后是**明细表**
（名称 / 值 / 路径 / 过期 / Secure / 子域 / 操作）。
- **域可折叠，默认只展开第一组**：一个站点动辄七八条 cookie，全摊开就得一直滚；
  而打开这个页面通常是为了看「刚跑的那个域」。
- **操作一律图标按钮**（`.icon-btn`，常态低调、hover 才浮出底色）：这种密集列表里每行挂两三个文字按钮，
  既把行撑宽一截也更吵。行内与域头的操作都平时透明、hover 才显形（同环境列表）。
- **明细用表格而不是「name = value + 一串标签」**：列对齐之后，「哪几条只发 https」「谁快过期了」
  一眼扫得出来；标签堆在行尾则要逐行读。列宽上，能算出宽度的列（路径 / 时间 / 两个勾选 / 操作）给固定 px，
  名称与值吃剩余空间——用百分比会在窄容器下把时间挤成「2026-09-0…」。
- **已过期不挂标签**：整行淡化 + 过期时间转告警色就够了，多一个标签只会把最不重要的那列撑宽。
- **两种空态分开写**：一条都没有（饼干图标 + 「添加 Cookie」）与搜不到（放大镜 + 「清空搜索」），
  该给的下一步动作不同。
- **编辑弹窗 600px**（比 `.modal-wide` 的 440 再宽一档）：值那行放的是 token / JWT，440 下连一半都显示不出来。
  版式是**三行两列**——域 | 路径、名称 | 值、过期时间 | 属性，左右等高、没有半行空白。
  过期时间用自写的 `DateTimePicker`（`datetime.ts` + `DateTimePicker.tsx`）而不是
  `<input type="datetime-local">`：后者外观各平台各不相同（WebKit 下是一串分段数字，与全站控件不搭），
  且放不下「清除 / 今天」这两个最常用的动作——而它们正是这里的高频操作
  （「这条不要过期时间了」「给我一个从现在起的时间」）。**未设置即会话 Cookie**（不写 `Expires`）。
  面板是**日历 + 右侧时/分两列滚动**：比 `<input type="time">` 少一次「点进去再敲数字」，
  打开时自动把当前时分滚到列中间（60 个分钟项，不定位就得从 00 找起），列上下加渐隐遮罩
  （滚动列表的首尾项恒被切一半，硬边看着像渲染坏了）。
  日历排布（周一为首、固定 42 格、跨月补位）抽在 `datetime.ts` 里单测钉住——排错一天，
  用户点「1 号」拿到的是上个月最后一天，这种错屏幕上很难看出来。
  > 样式上有个坑：`.modal-cookie` 写在 `.modal` 之前，同特异性下会被后者的 `width: 320px` 盖掉，
  > 故用双类选择器 `.modal.modal-cookie` 提一档特异性。
- **搜索同时匹配域 / 名 / 值**：「哪个 cookie 里存着这个 token」与「这个站有哪些 cookie」同样常见。
- **增改走同一个入口**（`CookieJar::put`）：拼一行 `Set-Cookie` 交给解析器，而不是自己拼装属性对象——
  这样手工加的与服务端下发的走同一套合法性判定，不会分裂成两套语义。`Expires=` 需要 HTTP 日期，
  故 `util` 补了 `http_date`（自算历法，同 `iso8601` 不引时区库；星期几算错的话解析器会把过期时间丢掉）。
- **校验只在 Rust**，前端把错误原样显示在对话框里、不关窗——前端复刻一份判定必然与内核漂移。
- **`hostOnly` 要单独暴露**：store 里 host-only 与带 `Domain` 属性的域名字符串**长得一样**
  （`Suffix` 存的也是去点后的域名），不标出来，编辑一次就把「子域一并生效」悄悄丢了。
  编辑框里用 `.example.com` 的写法表达它。
- **值不掩码**（同报告的既有决策：被掩掉的恰恰是排查时要核对的），只做单行截断 + `title` 给全文。
  已过期的仍列出并标注——否则用户看到「没有 cookie」却又删不掉它。
  进分区即重读一次（cookie 随请求不断变化，缓存住只会显示过期状态）。
调试发送前若 cookie 开着会先确保 `.apicase/` 已进 `.gitignore`（每个工作空间一次）：jar 含明文会话，
而此前只有批量运行才写那一行，只做调试的人会漏掉。
**设置页的当前分区由 `App` 持有**（`settingsSection`）而非 SettingsPage 内部 state：顶栏图标要能指名跳进
「Cookies」，而内部 state 随标签切走即卸载丢失。顺带得到「切走再回来仍在原分区」。
进可视模式那一步走 `wantConfigVisualRef` 标志而非直接调用——标签是异步激活的（新开要读盘、
旧标签要从快照恢复），且**标志只消费一次**：否则用户跳过来后自己切回「文本」会被立刻拽回可视，退都退不出去。

**environment（多套环境）**：打开工作空间读根 `application.yml`（`parseAppConfig` 一次取回 environment 与 settings），topbar 右侧下拉切换；运行时 `ctx.vars = { ...活动环境, ...case级vars }`（case 覆盖环境）。任意 `.yml`（含 `application.yml`）可在编辑器**以文本打开**——非 case 落文本视图；保存 `application.yml` 后即时重载环境。**文本视图忠实**：有效 case 无结构化改动时保留原文件文本（含注释），仅有编辑时才 `dumpCase` 重生成。

**文件树工具栏**：顶部搜索框（输入即 `search_workspace` 递归搜索，结果切换为扁平列表、点击打开）+ `+` 按钮（弹「新建 case / 新建 folder」菜单）。**可视化新建 case**：对话框填 名称 + method + URL → 生成 case 文件并自动打开；右键菜单的「新建 case」走同一对话框。

**全局快捷键**（`shortcuts.ts` + `App.tsx`）：app 级快捷键，单一 `document` keydown 分发（`ref` 取最新绑定 / 动作闭包，复用 `saveRef` 模式）。核心动作：新建用例 / 打开工作空间 / 保存 / 关闭标签 / 搜索 / 打开配置页 / 发送请求。修饰键统一抽象 `Mod`（macOS=⌘、其它=Ctrl），跨平台一套配置；纯键在输入框内不拦截（避免干扰打字），带 Mod 的组合处处生效。配置页「快捷键」分区支持查看、录制重绑、冲突检测、禁用、恢复默认；override 与总开关持久化到 `settings.json`（app 级偏好，区别于 workspace 级 `application.yml`）。

**自定义标题栏**（`tauri.conf.json` 窗口配置，macOS）：
- `titleBarStyle: "Overlay"` + `hiddenTitle: true`：内容延伸进标题栏、隐藏标题文字。
- `trafficLightPosition { x, y }`：把红绿灯下移与顶栏内容垂直居中对齐（近似 `红绿灯中心 ≈ y + 7`；当前 `x:16, y:16`，顶栏高 38px）。**改此项须重启 `tauri dev`**。
- 全屏自适应：靠窗口尺寸**变化方向**判断（缩小=退出全屏，立即恢复留白，早于红绿灯出现），避免退出全屏时红绿灯覆盖下拉。

## 运行 / 构建 / 测试

两个产物各有各的开发循环。

**图形界面**（`apicase-desktop`）：

```bash
cd app
npm install                       # 首次
npm run tauri dev                 # vite + 窗口一起起，热重载；改 core/ 触发 Rust 重编译
npm run tauri build               # 打包安装包（.dmg / .app / .deb / .msi）
```

**命令行**（`apicase`）：**不需要**对应的 `dev` 模式——它只编 `cli` 与 `core`、不碰 Tauri，
改一行 core 的增量编译在 **2 秒**，直接重跑比守一个 watch 进程更快也更清楚。

```bash
cargo cli run -e dev              # == cargo run -q -p apicase-cli -- run -e dev
cargo cli check                   # 任意子命令都这么接
cargo cli-check                   # 只做类型检查，不产二进制

cargo build -p apicase-cli --release   # 出正式二进制（target/release/apicase）
```

`cli` / `cli-check` 是 `app/.cargo/config.toml` 里的 alias。**`-q` 不能省**：
cargo 自己的 `Compiling` / `Finished` 两行会混进 CLI 的输出，
`cargo cli run --json | jq` 就直接崩了（构建**错误**仍照常走 stderr，不会被吞）。

**测试**：

```bash
npm run build                     # 前端类型检查 + 打包
npm test                          # 前端单测 + IPC 接线核对
cargo test --workspace            # 执行内核 + 命令层 + CLI（默认全部离线，联网用例标了 #[ignore]）

cargo test -p apicase-cli --test exit_codes           # 只跑退出码的端到端
cargo test -p apicase-cli 名字 -- --nocapture         # 单个测试，放行 println
```

**调 MCP 服务器**要换个手法：stdio 传输下 **stdout 被协议占着**，
往那儿写一个字节就会破坏 JSON-RPC 帧。因此日志一律 `eprintln!`，跑的时候把两条流分开：

```bash
# 手工喂一轮：日志分流到文件，stdout 只剩协议消息
{ printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"debug","version":"1"}}}' \
                '{"jsonrpc":"2.0","method":"notifications/initialized"}' \
                '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'; sleep 1; } \
  | cargo cli mcp -w <工作空间> 2>/tmp/mcp.log

# 或用官方调试器（可视化点工具、看请求响应）
npx @modelcontextprotocol/inspector cargo run -q -p apicase-cli -- mcp -w <工作空间>
```

「stdout 只有 JSON」有测试钉住，但开发期真正会踩的是**在 ops 层临时加了一行 `println!` 忘了删**——
表现是 MCP 客户端「连上了但什么都不工作」，且不报任何错。

**测试分层**：

| 层 | 覆盖 |
|---|---|
| `apicase-core`（233） | YAML（含仓库真实 case 的黄金往返）、emitter 引号规则、变量、JSONPath、断言、请求组装、Digest（RFC 2617 官方向量）、客户端池、Cookie（收发 / 持久化 / 开关 / 增删改 / HTTP 日期）、执行引擎（并发 / 取消 / OAuth2 去重 / 连接复用 / 依赖闭包）、工作空间定位与用例发现（含**并行度从配置装进 `RunOpts`**）、报告命名与写盘节流、应用配置目录与代理偏好的容错 |
| 命令层（18） | 命令转发、**事件序列化形状**、文件命令、启动参数挑工作空间、**配置目录与 Tauri 的一致性** |
| CLI 单测（36） | 校验规则、报告裁剪、`--var` 切分、着色与东亚字符宽度、MCP 工具清单与开场白、格式规范分节、`-j` 省略即跟随配置 |
| CLI 集成（9） | **真跑二进制**看退出码（0/1/2/3 各一条）、`--json` 的 stdout 是否干净、报告落点与 `.gitignore` |
| 前端（15 组） | URL↔query 同步、编辑态互转、markdown、路径工具、应用设置、断言补全、HTML 预览、报告增量推送、运行参数组装（并行度归一）、Cookie 分组 / 搜索、日历排布、报文体 JSON↔YAML |
| `scripts/check-ipc.py` | 42 个命令的**命令名与参数名**逐一核对 |

- **退出码单独做端到端**：它是 CLI 与 CI 之间**唯一的契约**，而单测只能覆盖「算出来的码对不对」，
  覆盖不了「这个码有没有真的被返回」（中间隔着 `ExitCode::from`、`?` 的早退、panic）。
  那层测试自带一个 30 行的极简 HTTP 服务，因此不依赖网络。

- **执行引擎的测试起真实的本地 HTTP 服务**（`core/src/testutil.rs`，手写 HTTP/1.1 最小子集）——
  用假的 send 回调去测等于把被测对象换掉了。该 mock 支持 keep-alive，因此还能验证连接复用确实发生。
- **IPC 接线核对**补的是类型检查覆盖不到的一环：参数名对不上既没有编译错误、也没有类型错误，
  只有点下去才发现。已接入 `npm test`。
- **测试之间不共享进程级缓存**：客户端池做成可实例化的 `ClientPool`（测试用独立实例）；
  token 缓存靠 mock server 端口天然唯一来隔离，**不调 `clear_token_cache()`**——那会清掉
  并行跑的别的测试正在用的条目。

## 当前实现边界

- **执行语义全部在 Rust**（`apicase-core`）：YAML 解析与序列化、变量透传、请求组装、认证
  （含 Digest 摘要与 OAuth 2.0 换 token）、JSONPath 提取、断言、报告渲染。前端只做配置与展示。
  桌面壳（`src-tauri`）只剩命令转发与桌面专属能力（文件树 / fs 监听 / 伪终端 / 应用配置目录）。
- **CLI 与 MCP 已可用**（`apicase-cli`，二进制名 `apicase`）：13 个子命令 + 7 个 MCP 工具，
  与桌面端共用内核、配置、cookie jar 与报告目录。**尚未做的是分发**——
  `externalBin` 打包、桌面端的「安装命令行工具」按钮、Linux 的 deb/AppImage 落点与软链；
  当前用 `cargo build -p apicase-cli` 产出的二进制本身就是完整可用的。

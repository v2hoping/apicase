# 技术架构

> 描述 apicase 的实现架构现状（v0.1）。

## 技术栈

- **桌面框架**：Tauri 2.x（Rust + 系统 WebView）。
- **执行内核**：`apicase-core`（独立 crate，**零 Tauri / 零 GUI 依赖**）；`reqwest`（rustls TLS，避免本地 OpenSSL）；`tokio`（异步与并发调度）；`serde` / `serde_json`（`preserve_order`）/ `serde_yaml`；`base64`；`md5`；`regex`。
- **桌面壳**：`tauri-plugin-dialog`（目录选择）；`notify`（fs 监听）；`portable-pty`（伪终端）。
- **前端**：React 19 + TypeScript + Vite 7；`@tauri-apps/plugin-dialog`；`@xterm/xterm` + `@xterm/addon-fit`（底部终端）。**不再有 YAML / HTTP / 执行相关依赖**。
- **前后端通信**：Tauri command + `invoke`；批量运行的进度走 Tauri event。
- **权限**（`capabilities/default.json`）：`core:default`、`opener:default`、`dialog:default`、`core:window:allow-start-dragging`（自定义标题栏拖动窗口需显式授权）。

## 目录结构（`app/`）

## 执行内核 `apicase-core`

**一句话职责：从 case 文件到运行报告的全部语义都在这里。** 桌面壳与将来的 `apicase run` CLI
只做三件事——给输入、注入 IO、把产物交给用户。二者不共享任何执行语义，因此不会出现
「界面里跑过了、CLI 跑却挂了」这类两套实现必然产生的漂移。

```
case.yml → yaml → vars → request → auth → http → jsonpath → assert → redact → RunReport → report.html
```

**边界是硬的**：`core/Cargo.toml` 里没有 `tauri`。这条线一旦破掉（比如为了发个进度事件
而 `use tauri::Emitter`），CLI 就得把整个 GUI 框架拖进来编译。故进度上报走**回调注入**
（`ProgressFn`），桌面壳在回调里转成 Tauri 事件，CLI 在回调里打印一行。

### YAML：解析容错、输出规范

- **解析一律容错**：除「YAML 本身语法错」外，认不出的 `op` 回落 `eq`、认不出的 `auth.type` 回落 `none`、
  `settings` 解析失败回落全默认。配置文件是手写的，一处写错不该让整个功能瘫掉。
- **序列化自己写**（`yaml/emit.rs`），不用通用库。落盘的 case 是用户要读、要 diff、要 review 的源文件，
  格式不是实现细节。

  **引号按字段的语义类型加**，一条规则：值位置的字符串，裸写后若不被读成字符串就加引号。

  | 字段 | 写法 | 例 |
  |---|---|---|
  | 会发到网络上的字符串（`query`/`headers`/表单的 `value`、`url`、`id`…） | 数字 / 布尔形态**加引号** | `value: '2'`、`name: '1'` |
  | 数字 / 布尔（`timeoutMs` / `x` / `y` / `enabled`） | 裸写 | `timeoutMs: 500000`、`x: 502` |
  | 断言的期望值（`assertions[].value`） | **裸写** | `value: 200`、`value: ok` |
  | 自由类型（`vars` / `body.json`） | 引号在这里**有语义** | `retries: 3` vs `label: '3'` |

  HTTP 报文里没有数字类型——query / header 的值语义上恒是字符串，`value: 2` 裸写虽也读得回 `"2"`，
  但读的人无从判断类型（Postman 的 JSON collection 里同样是 `"2"`）。而 `timeoutMs` 在模型里
  真的是 `u64`，写成 `'500000'` 反而误导。

  **`assertions[].value` 走宽松规则**（`LOOSE_SUBTREE_KEYS`）：它是期望值、不进报文，
  类型跟着 `target` 走；且它在模型里恒是 `String`、比较本就宽松（先文本再数字，
  见 `assert::loose_eq`），引号对结果毫无影响，强加只是噪声。
  保持 `String` 而不改用 `serde_json::Value`，是因为可视化断言编辑器的输入框产出字符串——
  改用 `Value` 会平添"输入框里的 `200` 是数字还是字符串"这个新歧义，而收益（类型信息）
  在宽松比较下用不上。真要做严格类型断言时再改不迟。

  **key 位置更宽松**（key 恒按字符串取用，无类型歧义）：读得回原值就裸写，画布坐标的 `y: -70`
  正是靠这条——YAML 1.1 把 `y` 当布尔别名，1.2 不会，我们按 1.2。

  判定用**真实解析器**验证而不是手写判定表：「什么算数字」的边界（`1_000` 是字符串、`007` 是字符串、
  `.inf` 是数字）只有解析器自己说了算。故 `yes` / `2026-07-30` / `12:30` 这些本就是字符串的值不带引号。

  **单引号优先**，只在单引号表达不了时（含控制字符）升级双引号——要加引号的值里常含反斜杠
  （断言的 `matches` 正则、Windows 路径），双引号会逼着把 `\d` 写成 `\\d`。

  多行文本走块标量 `|` / `|-`；画布坐标整数值写成整数（不留 `502.0`）。
  有**黄金测试**用仓库里真实的 case 逐字比对输出。
- **变量语法只认 `${{var}}`**（`core/src/vars.rs`）：`{` 是 YAML 的流式映射指示符，
  以 `{{` 开头的值必须整行加引号（`url: '{{baseUrl}}/get'`；`url: {{host}}` 更会被**静默**
  读成嵌套映射、URL 直接没了），而 `$` 不在指示符表里——`url: ${{baseUrl}}/get` 可以裸写。
  GitHub Actions 用 `${{ }}` 多半同理；Ansible 用 `{{ }}`，其官方文档就明确要求加引号。
  **不留无 `$` 的旧写法**：同一件事两种写法、而其中一种会把用户逼回加引号。
- **case schema 版本是 `apicase: v0.1`**（常量 `CASE_VERSION`）：带 `v` 前缀故不是数字形态，
  落盘不必加引号，也不会在 `0.10` 时被读成 `0.1`。
- **解析侧宽进**：schema 说是字符串的字段一律走 `s()`，用户裸写 `value: 2` / `name: 123` /
  `apicase: 0.1` 都读成字符串，而不是被当成"类型不对"悄悄丢掉。**宽进严出**——
  保存时规范化成带引号，把"这是字符串"在文件里写明白。

### HTTP：客户端池是本层最大的性能收益

按「代理 + 证书校验 + CA + 超时」这组配置缓存 `reqwest::Client`：

- 改造前每请求 `Client::builder().build()` 一次 —— TLS 根证书库重建、**连接池随客户端一起丢弃**。
  批量跑 100 个打同一服务的用例，就是 100 次 TCP + 100 次 TLS 握手。
- 现在配置不变就复用同一个客户端，keep-alive 连接因此真正活得下来。**有测试钉住：5 个请求 1 条连接。**
- CA 文件的 **mtime 与长度**参与缓存键：换了证书文件客户端自动重建，不必重启。
- **锁中毒不让池子报废**：别处 panic 毒化了锁后，照直 `unwrap` 会让此后每个请求都以
  「缓存已损坏」告终；池里只是可重建的客户端，直接取回内部数据继续用。
- 响应体**分块累加**并守住 64MB 上限（`text()` 一次性全读会先吃光内存才轮到判断），
  超限**明确报错**而非静默截断。
- `verifySsl == false` → `danger_accept_invalid_certs`；`caCertPath` → 追加到默认信任库
  （PEM bundle 与 DER 都支持，DER 先自行校验 ASN.1 首字节，免得错误延后成一句无指向的「创建客户端失败」）；
  `timeoutMs > 0` → 覆盖「连接 + 发送 + 读完响应体」全过程。

### 执行引擎：三级 + 三条不变量

`run_step` / `run_case` / `run_batch`。**调试运行与回归运行是同一份实现**，只差脱敏与截断两个开关。

- **变量隔离**：每个 case 一份独立 `RunContext`（environment + 该 case 的 `vars`），
  **case 之间不共享 outputs**——否则一开并发就是竞态。
- **`failed` ≠ `error`**：前者请求发出去了但断言没过（被测服务的问题），后者请求本身失败
  （网络 / TLS / 超时，常是环境或用例的问题）。两者排查方向完全不同。
- **取消在 case / step 边界生效**，已发出的 HTTP 不中断——半截请求对被测服务是一种伤害。

**并发**：`concurrency > 1` 时 case 之间用 `tokio::Semaphore` 限流，case 内部的 step 仍按拓扑序串行。
**默认仍是 1**；串行路径独立成一支（不走 spawn 与信号量），顺序精确、`stopOnFailure` 语义干净。
并发安全的前提是 OAuth 2.0 token 缓存做了 **in-flight 去重**：每个缓存键一把异步锁，
同键并发只有第一个真去换 token——没有它，8 个并发就是 8 次 token 交换。

### 脱敏：五条互补规则

报告会被转发、进 CI 制品、甚至提交进仓库，故**默认开启**。

1. 请求头按名字掩码（`Authorization` 这类值本身即凭据）；
2. **已知凭据值的字面替换**（凭据会被回显到响应体 / URL 任何位置；来源含 environment、case `vars`、上游 outputs）；
3. **JSON 响应体按 key 掩码**（登录接口新返回的 token 事先不知其值，只能靠字段名认）；
4. `outputs` 在报告里掩码，但**透传给下游 step 的是原值**；
5. **断言的 `actual` / `expected`**——`res.body.data.token exists` 的 `actual` 就是 token 原文，前四条一条都拦不住它。
   目标路径像凭据就按名字掩码，占位符 `∅`（路径不存在）与 `—`（无期望值）放过。

掩码保留 scheme 与前 4 位（完全抹掉会让「是不是根本没带认证」无从排查）。
**先脱敏再截断**，否则横跨截断边界的凭据会留下前半截。报文体默认截断 64KB（`bytes` 记原始大小，切点落在字符边界）。

### 报告：只有一套渲染实现（硬约束）

`report_shell()`（空壳 = CSS + 渲染 JS）供 apicase 内嵌 iframe，`render_html()`（空壳 + 内联数据）
供落盘与 CLI，**共用同一份资源**（`render/report.css|body.html|js`，`include_str!` 编译进二进制）
→ 应用内 / 历史回看 / 发给同事三处像素级一致。有单测断言「除数据块外逐字相同」。
迁移时与原 TS 实现做过**逐字比对**，历史报告与新报告无任何视觉差异。

- **单文件自包含**：数据内联在 `<script id="apicase-report" type="application/json">`，不另存 `report.json`。
  **不做 ndjson + 轮询**——`file://` 下 fetch 同目录文件会被 CORS 拦掉（Playwright 正是栽在这）。
- 内联 JSON 转义 `</` → `<\/`（响应体里的 `</script>` 会提前闭合标签）与 U+2028/2029。
- `parse_report_html` 是反向读回，提取失败即视为普通 HTML（**只认自己生成的报告**）。往返等价有单测护栏。

## 桌面壳：Tauri 命令层

`src-tauri` **不含任何执行语义**，只有桌面应用才需要的能力。`commands/exec.rs` 是纯转发：
把 JSON 变成 core 的类型、把产物变回 JSON、把进度转成事件。

### 执行相关（全部转发 core）

- `analyze_case(text)` / `dump_case(case)`：case 文本 ↔ 模型。
- `parse_app_config(text) -> { environment, settings }`：一次读全 `application.yml` 的两块配置
  （分成两个命令等于两次 IPC + 两次 YAML 解析）；`dump_app_config(baseText, environment, settings)` 写回并保留未知顶层键。
- `run_step(step, vars, steps, opts)`：界面上的「发送 / ▶ 运行」。上下文由前端传入——
  它是「当前这个标签页的运行态」，生命周期跟着 UI 走，放后端反而要同步两份状态。
- `topo_order(steps)`：按 `dependsOn` 排序（返回下标）。循环留在前端是为了逐步刷新界面，
  但**排序规则只有 core 一份**（成环兜底等边界不该两处各写一遍）。
- `run_batch(args) -> RunReport`：批量运行，跑完返回最终报告；`report_file` 给了就由后端周期落盘。
- `cancel_run(runId)`：取消（托管状态 `RunState = Mutex<HashMap<runId, Cancel>>`）。
- `report_shell()` / `parse_report(text)`：报告空壳与反向读回。

**进度事件 `run://progress/{runId}` 按增量推**：一份跑了 200 个用例的报告可达数 MB，
每完成一个就整份序列化过一次 IPC 会把界面拖卡。三种事件：`start`（报告头，`cases` 为空）
→ `case`（逐个追加）→ `end`（收尾）。
> 序列化上有个坑：`#[serde(rename_all)]` 在 enum 上**只管 variant 名**，字段名要 `rename_all_fields`。
> 少了后者前端读 `durationMs` 就是 `undefined`，表现为「进度条一动不动」且无任何报错。已由测试钉住。

**周期写盘**在后端做（`ReportWriter`）：每 ≥1s 整份覆写一次，持锁写盘天然串行，不会写出半截文件。

### 桌面专属

- **应用设置**（存**应用配置目录** `settings.json`，仅按 `identifier` 定位，跨 dev / 打包一致）：
  `read_app_settings()` / `write_app_settings(content)` / `app_paths()`。当前存全部应用级偏好：
  最近打开的工作空间、主题、代理、快捷键绑定与总开关、文件树是否显示隐藏项。
- `init_workspace(path)`：目录初始化为工作空间（无 `application.yml` 则写初始模板；幂等）。
- `list_cert_files(root)`：递归列出工作空间内的证书文件（`.pem/.crt/.cer/.der/.ca-bundle`），
  返回**相对工作空间根**且统一用 `/` 分隔的路径（配置要跨平台共享）。
- `system_info()`：「关于」页的 OS / 架构 / 芯片。
- **文件与目录**：`list_dir(path, showHidden?)`（目录在前、组内忽略大小写排序；`.git`/`node_modules`/
  `target`/`dist` **恒不列**——「显示隐藏文件」不等于「显示一切」）、`read_text_file` / `write_text_file` /
  `read_file_smart`（NUL 嗅探 + UTF-8 校验）/ `create_file` / `create_dir` / `rename_path` /
  `copy_path`（拒绝覆盖、拒绝复制进自身子目录）/ `delete_path` / `search_workspace` / `path_exists`。
- **文件系统监听**：`watch_workspace(path)` 递归监听，事件经 **250ms 去抖**、过滤噪声后以
  `workspace:fs-change` 发往前端；再次调用替换旧监听。**噪声只按目录名挡**（`.git` 与
  `node_modules`/`target`/`dist` 这类高频且与用例无关的），**不按"隐藏项"一刀切**——
  文件树的「显示隐藏文件」开着时 `.apicase/`、`.env` 都是可见的，滤掉它们的变更就会让
  用户删掉一份报告后还看着它。前端只刷新**已加载**的目录，没展开过的隐藏目录本就不会空转。
- **伪终端**：`terminal_open/write/resize/close`，输出以 `terminal://data/{id}` 事件（原始字节）流回前端。

## 前端：交互

**前端只做配置与展示。** 请求表单 → `run.ts` 的 `runStep(step, ctx, opts)` → 执行内核完成
「变量透传 → 组装 → 认证 → 发送 → 提取 → 断言」 → 前端把 `StepResult` 折成响应区要的形状渲染。
客户端配置 `ClientConfig` = 代理（应用级偏好）+ 请求设置（工作空间 `application.yml`），
CA 的相对路径在此还原为绝对路径。
UI 对标 Postman：方法下拉（彩色）与 URL **连体** + Send；Headers（自动增行）/ Body 配置 Tabs；响应区状态徽章 + 耗时 + 大小，Body(Pretty/Raw) / Headers Tabs。

**三栏布局（仿 VSCode）**：顶栏**最右**三个切换按钮（VSCode 风格图标：外框方块 + 对应边填充）显隐三块面板——**左**文件树 / **底**终端 / **右** AI 对话。布局包裹为 `.body-layout`（横向：`.sidebar` + `.center-col` + `.ai-panel`），`.center-col` 内纵向排 `.workspace` 与 `.bottom-panel`。显隐状态 `LayoutFlags{left,bottom,right}` 存 **`sessionStorage`**（`apicase.layout.v1`）——刻意做成**会话级**：关闭应用即清空，下次启动回到默认（左开、底/右关），不像主题那样是跨启动的长期偏好；底部栏可拖高、右侧栏可拖宽（复用既有 resizer 模式，`body.resizing-row`/`resizing-col`）。底部终端与右侧 AI **首次打开后常驻**（`display:none` 隐藏而非卸载），保留 shell 会话/滚动与对话历史。快捷键（`shortcuts.ts` 「视图」组）：`Mod+B` 左栏 / `Mod+J` 终端 / `Mod+Alt+B` 右栏。
- **终端**（`TerminalPane.tsx`）：`xterm.js` + `FitAddon`；挂载即 `terminal_open`（cwd=工作空间），监听 `terminal://data/{id}` → `term.write(Uint8Array)`（原始字节交 xterm 缓冲，天然处理跨包 UTF-8）；`onData` → `terminal_write`；`ResizeObserver` → fit + `terminal_resize`；切回可见时 refit + focus；`cwd` 变化（切工作空间）重建会话。
- **AI 对话**（`AiChat.tsx`，本期 UI 外壳）：消息气泡列表（自动滚底）+ 多行输入（Enter 发送 / Shift+Enter 换行）+ 清空；发送后追加用户消息与占位助手回复，后续接真实模型仅替换回复来源。

**工作空间 / 文件树**：左上角自定义下拉 → `plugin-dialog` 选目录 → `invoke("init_workspace")` → `invoke("list_dir")` 渲染左侧文件树（懒加载、可展开折叠）；左侧栏可拖动调宽（默认 260px，范围 160~480；260 是为了让「05-延迟与重定向」这类目录名不一上来就被截断）、可整体显隐。子级容器画**缩进参考线**（`.tree-children::before`，位置 = `calc(6px + var(--tree-depth) * 14px + 8px)`，即父行折叠箭头的中线；`--tree-depth` 由 TreeNode 内联传入，`z-index: 1` 使其压过行的 hover/选中底色，线不被割断）；展开后为空的目录显示「空文件夹」占位，文字与同级文件名左对齐。打开工作空间即 `invoke("watch_workspace")` 启动监听，订阅 `workspace:fs-change` 事件做**自愈刷新**（仅刷新已加载目录，保持懒加载一致）。

**文件树的行菜单与剪贴板**：每行（含**工作空间根那一行**，其交互与 `.tree-row` 一致：26px 行高、6px 圆角、`cursor: pointer`、hover 底色、点击选中 + 同款选中橙条）**悬浮 / 选中 / 该行菜单打开时**在最右显形一个「⋯」按钮，点击弹出的菜单与右键完全同源（`ctxItems`）——根：新建用例 / 新建文件夹 / 粘贴 / 显示文件所在位置；目录：再加 克隆 / 复制 / 重命名 / 删除；文件：克隆 / 复制 / 重命名 / 显示文件所在位置 / 删除。工具栏「+」走另一份 `newItems`（仅新建用例 / 新建文件夹），由 `ctxMenu.newOnly` 区分。「粘贴」在目录与根上**常驻**，剪贴板为空时 `disabled` 灰显。树选中态 `treeSel{path,isDir}` 与「当前打开文件」分离——**目录也要能被选中**（粘贴要落到它里面），点目录即展开且选中，切标签时选中项跟随当前文件，点根行「⋯」则清空选中让粘贴落到根。剪贴板是应用内状态 `clip{path,isDir}`（不走系统剪贴板），**只有复制、无移动语义**，故粘贴后保留、可连续粘贴。粘贴目标 = 选中目录本身 / 选中文件的父目录 / 无选中则工作空间根；重名经 `uniqueName` 自动排号（`用例.yml` → `用例 副本.yml` → `用例 副本 2.yml`），**不覆盖**。两条拦截：目录粘进自身或子目录、源已被外部删除。重命名后由 `retargetPaths(from,to)` 统一迁移标签、当前文件、选中项、展开态与子项缓存——目录改名时其下已打开文件的标签路径也跟着走。`Ctrl/⌘+C`、`Ctrl/⌘+V` **只在左侧栏有焦点时**生效（`.sidebar` 挂 `tabIndex={-1}` + `onKeyDown`，事件源是 input/textarea/contentEditable 时放行），不进全局快捷键表——那是 document 级分发，会劫持编辑区/终端里的正常复制粘贴。「显示文件所在位置」走 `@tauri-apps/plugin-opener` 的 `revealItemInDir`（`opener:default` 已含）。

**case 读写**（`case.ts`）：点击 `.yml`（非 `application.yml`）→ `read_text_file` → `await analyzeCase(text)` → 渲染。编辑标记 dirty → `Cmd/Ctrl+S` 或保存按钮 → `await dumpCase(c)` → `write_text_file`。**解析与序列化都在 Rust**，`case.ts` 只剩 TS 类型与 IPC 封装——这些调用全在用户操作边界（打开 / 切视图 / 保存），一次 IPC 往返不到 1ms。序列化裁剪默认值（`enabled:true`、空 body 等不落盘）。

> **唯一留在前端的执行相关同步逻辑**是 `splitQueryFromUrl` / `mergeQueryIntoUrl`：它们在 URL 输入框的**打字热路径**上（每敲一个字符都调），走 IPC 会让输入变黏手。Rust 侧有等价实现（`core/src/request.rs`）服务于发送，两边各有单测钉住。

**三视图与 flow 编辑**（`App.tsx` + `FlowCanvas.tsx` + `RequestEditor.tsx` + `draft.ts`）：case 内部统一为 step 列表模型（单节点 = 1 个 step；YAML 写 `steps:` 列表，每步含 `protocol:` 与 `request:`）。顶栏三视图切换——**文本**（原始 YAML，互斥）/ **流程**（DAG 画布）/ **请求**（复用请求编辑器），按**意图式**切换（关掉唯一在显栏落文本、从文本点某栏则确保显示该栏）。内容驱动默认视图（`analyzeCase` 判 valid/单/多）；切结构视图前 `commitText` 重解析 rawText，切文本前从结构态 `dumpCase` 刷新（结构是切换时的真相源）。画布 `dependsOn` 自动分层布局 + SVG 贝塞尔连线。**画布交互**（`FlowCanvas.tsx`）：平移（拖背景 / 滚轮）+ 缩放（Ctrl/⌘ 滚轮锚定光标，工具栏放大/缩小/缩放%复位）+ 适应视图 + 规整（清手动坐标恢复自动布局）；**拖拽节点**持久化坐标到该 step 的 `ui: { x, y }`；从 **out 端口拖到目标节点建立依赖**（防自连/重复/成环）；边悬停显示删除按钮解除依赖；双击空白快速加节点；**拖拽对齐吸附**（与其它节点列/行对齐时贴齐并显示参考线）；右下角 **小地图/概览**（节点缩略 + 视口框，点击/拖拽导航）。坐标是视图态、拓扑（`dependsOn`）是真相。

**多标签页**（`TabBar` + `tabOrder` + `tabCacheRef`）：活动标签用 live state，非活动标签用 `TabSnapshot` 快照保存完整编辑态；`openTab` 快照当前 + 恢复目标（新标签走 `openCase` 加载），`closeTab`/`closeOtherTabs`/`closeAllTabs`（dirty 关闭前确认）；重命名/删除文件同步标签。

**flow 执行**（`run.ts` + 执行内核）：`发送` / `▶ 运行`——每步的「变量透传（`${{vars}}` / `${{steps.x.outputs.y}}`）→ 组装 → 认证 → 发送 → JSONPath 提取 `outputs` → 评估断言」**全在 Rust**。「运行全部」的顺序由 `topoOrder` 命令排出，循环留在前端是为了每跑完一步就刷新界面；outputs 用本地上下文在 `await` 间同步透传。断言结果逐条 ✓/✗，失败标红节点。请求编辑器在参数/请求头/认证/请求体之外，追加 输出 / 断言 / 文档 / 请求 ID 等 Tab（输出/请求 ID 仅多请求场景，请求 ID 置于末尾；「文档」标签支持 markdown 编辑与预览，内容存 step 的 `docs:`）。

**断言目标与补全**（`core/src/assert.rs` + `src/assertPath.ts`）：目标统一挂在 `res` 命名空间下
（`res.status` / `res.headers.<名>` / `res.body<路径>`），认不出的目标显式取不到值（`∅`），
不做前缀猜测——`res.bodyfoo` 宁可判无效，也不能被当成"取整个响应体"而静默通过。
目标格的补全由 `assertPath.ts` 按**最近一次响应**逐层给候选，每条带该路径的当前值摘要；
期望值格同样按目标的当前值给一条建议（`suggestValue`），但只建议不自动填，且在
`matches` / 容器值 / 超长文本这些场合闭嘴——一键把返回值固化成期望值正是脆弱断言的来路。
这是全前端唯一一处与内核重复实现的求值逻辑：内核在跑完之后求值，补全要在输入时就给出候选，
两边跑同一套规则（两侧各有单测钉住），所以点着选出来的路径运行时一定取得到。

**批量运行与报告**（`run.ts` + 执行内核）：文件树右键「运行并生成报告…」→ 配置对话框（用例预览 / 递归 / 环境）→ 运行报告标签页 + 落盘 `<workspace>/.apicase/reports/<时间戳>-<目标名>.html`。

- **执行、报告渲染、周期写盘全在 Rust**；前端只负责开标签、订阅 `run://progress/{runId}` 事件、把 case 逐个追加进本地报告对象。事件按**增量**推（`start` 报告头 → `case` 逐条 → `end` 收尾），而不是每次整份重发。
- **报告头里的运行参数从 `opts` 派生**，不并列写第二遍——半年后回看一份失败报告，「当时脱没脱敏、截断阈值多少」直接决定结论能不能信。
- **报告只有一套渲染实现**（硬约束）：iframe 里跑的空壳与落盘 `report.html` 出自同一份资源。空壳经 `report_shell()` 取一次并进程内缓存（它与运行数据无关；`srcDoc` 一变就会重新加载整个文档，握手状态会作废）。
  - **分层**：iframe 内 = 报告内容；iframe 外 = 运行控制（进度条 / 取消 / 在浏览器打开）——分发出去的 HTML 里本就不该有「取消」。
  - **postMessage 协议**：宿主 → 报告 `host`（握手；收不到即为浏览器独立打开，IDE 专属动作不渲染）/ `theme` / `report`；报告 → 宿主 `ready` / `open-case`。`sandbox="allow-scripts"` 且**不给 `allow-same-origin`**；`srcdoc` 的 origin 是 `null` 故只能 `postMessage(*)`，宿主侧按 type 白名单处理并校验 `file` 在工作空间内（`isUnder`）。
  - **live 增量推数据**而非重塞 `srcdoc`（整页重画会丢展开态与滚动位置），报告页按 case `file` 作 key diff DOM；失败 / 错误默认展开。
- **伪路径标签**：`tabOrder` 存路径字符串，运行标签用 `apicase://run/<id>` 前缀分流——不走 `openCase`、不进 `tabCacheRef`（不是编辑态），`isDirtyPath` 恒 `false`，关闭时一并 `cancel_run` 并释放会话。会话状态独立存 `runSessions`。
- **报告目录 `.apicase/` 与 fs 监听**：监听刻意跳过 `.` 开头路径（否则周期覆写会把文件树刷爆），故运行结束后**精准刷新**一次已加载的报告目录。首次运行时把 `.apicase/` 写进工作空间 `.gitignore`。

**认证**（`core/src/auth.rs` + `core/src/request.rs`；前端 `auth.ts` 只剩显示元信息）：六种方式——`No Auth / Basic Auth / Bearer Token / API Key / Digest Auth / OAuth 2.0`（命名对齐 Postman/Insomnia/Bruno）。静态头（Basic/Bearer/API Key）由 `request::build` 直接组装；需要额外交互的两种收敛进 **`send_with_auth`**：**Digest** 首发不带凭据，吃到 401 后解析 `WWW-Authenticate` challenge 算摘要（`qop=auth` 五段式 / 无 qop 两段式，支持 `MD5-sess`，不支持 `auth-int`）**重发一次**；**OAuth 2.0**（客户端凭据）发送前 POST `tokenUrl` 换 `access_token`（凭据走 Basic 头或表单体）。以 RFC 2617 官方向量验证摘要计算。

- **token 缓存键含 `tokenUrl|clientId|clientSecret|scope|clientAuth`**：改任何一项即自动换一把新 token，前端因此不必再手动清缓存。缓存提前 30s 过期。
- **in-flight 去重**：每个缓存键一把异步锁，同键并发只有第一个真去换 token，其余在锁上等、醒来直接读缓存。这是 case 之间敢开并发的前提。
- **`send_with_auth` 返回实际发出的那一份请求**：OAuth 2.0 换来的 `Authorization`、Digest 重发时算出的摘要头只在那一份里。报告要如实记录发了什么——认证恰恰是最常出问题的一环。

**environment（多套环境）**：打开工作空间读根 `application.yml`（`parseAppConfig` 一次取回 environment 与 settings），topbar 右侧下拉切换；运行时 `ctx.vars = { ...活动环境, ...case级vars }`（case 覆盖环境）。任意 `.yml`（含 `application.yml`）可在编辑器**以文本打开**——非 case 落文本视图；保存 `application.yml` 后即时重载环境。**文本视图忠实**：有效 case 无结构化改动时保留原文件文本（含注释），仅有编辑时才 `dumpCase` 重生成。

**文件树工具栏**：顶部搜索框（输入即 `search_workspace` 递归搜索，结果切换为扁平列表、点击打开）+ `+` 按钮（弹「新建 case / 新建 folder」菜单）。**可视化新建 case**：对话框填 名称 + method + URL → 生成 case 文件并自动打开；右键菜单的「新建 case」走同一对话框。

**全局快捷键**（`shortcuts.ts` + `App.tsx`）：app 级快捷键，单一 `document` keydown 分发（`ref` 取最新绑定 / 动作闭包，复用 `saveRef` 模式）。核心动作：新建用例 / 打开工作空间 / 保存 / 关闭标签 / 搜索 / 打开配置页 / 发送请求。修饰键统一抽象 `Mod`（macOS=⌘、其它=Ctrl），跨平台一套配置；纯键在输入框内不拦截（避免干扰打字），带 Mod 的组合处处生效。配置页「快捷键」分区支持查看、录制重绑、冲突检测、禁用、恢复默认；override 与总开关持久化到 `settings.json`（app 级偏好，区别于 workspace 级 `application.yml`）。

**自定义标题栏**（`tauri.conf.json` 窗口配置，macOS）：
- `titleBarStyle: "Overlay"` + `hiddenTitle: true`：内容延伸进标题栏、隐藏标题文字。
- `trafficLightPosition { x, y }`：把红绿灯下移与顶栏内容垂直居中对齐（近似 `红绿灯中心 ≈ y + 7`；当前 `x:16, y:16`，顶栏高 38px）。**改此项须重启 `tauri dev`**。
- 全屏自适应：靠窗口尺寸**变化方向**判断（缩小=退出全屏，立即恢复留白，早于红绿灯出现），避免退出全屏时红绿灯覆盖下拉。

## 当前实现边界

- **执行语义全部在 Rust**（`apicase-core`）：YAML 解析与序列化、变量透传、请求组装、认证
  （含 Digest 摘要与 OAuth 2.0 换 token）、JSONPath 提取、断言、脱敏、报告渲染。前端只做配置与展示。
  桌面壳（`src-tauri`）只剩命令转发与桌面专属能力（文件树 / fs 监听 / 伪终端 / 应用配置目录）。
